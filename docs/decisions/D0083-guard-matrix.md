# D0083 守りの差をテストで固定し、フックの入力の読みを固くする（#132）

## 目的

守りの入口が4つあり（SDK の道・会話の道・プラグインの作る役と審査役・pipe-in 自身の開発用）、同じ道具の呼び出しでも、許すか止めるかが違う。違いは、コードを読まないと分からなかった。

守りを変える前に、いまの結果を1つの表としてテストで固定する（A）。変えたときに、差が「許す → 止める」として見える。あわせて、プラグインのフックの入力が読めないときに、止めない側に倒れうる所を塞ぐ（B）。

A と B は別のコミットにした（A はテストと文書だけで、動きを変えない。B は動きが変わる）。

## 機能要件と受け入れ基準

### A いまの結果を表で固定する（`tests/guard_matrix.py`・`tests/test_guard_matrix.py`）

- FR-01 「道具 × 場所 × 段の種類 × 守り」の表を1つ作り、いまの結果（許す／止める／判断しない）をテストで固定する。守りの列は9つ：SDK の道（守る場所を書かない・書いた）、会話の道、プラグインの作る役・審査役、開発用の4つの役（`pipe-in-analyst`・`tester`・`coder`・`verifier`）。
  - D0083-AC-01：表の全行で、結果が表のとおり（`test_d0083_ac01_matrix_row_matches_each_guard`・`test_d0083_matrix_shape`）。
  - D0083-AC-02：止める行は、すり抜けの道でも止まる（絶対パス・相対パス・`..`・MultiEdit・NotebookEdit・Bash の `>`・`tee`・`cp`・`sed -i`・`python -c`・`bash -c`・`$(…)`・サブエージェントの中から・PowerShell・MCP）。リンクを経た道は、守りごとの実際の結果を固定する（`test_d0083_ac02_bypass_rows_are_denied`・`test_d0083_ac02_symlink_row_records_actual_result`）。
  - D0083-AC-03：許す行（ふつうのコード・テスト・成果物）は通る（`test_d0083_ac03_allowed_rows_pass_where_allowed`）。
  - D0083-AC-06：作る役が書ける `pipes/pipe-in-<名前>/prompts/a.md`、審査役の Read、`pipe-in-gen list` は通る（`test_d0083_ac06_*`）。
  - D0083-AC-07：前の版の形（前の名前のフォルダと環境変数）でも、同じ結果（`test_d0083_ac07_old_form_gives_same_result_as_new`）。
- FR-02 開発用のフック（`.claude/hooks/pipe_in_guard.py`）は、表に列を足すだけで、直さない。
- FR-03 Skill と Agent の差の理由を、表のコメントと `docs/guide/safety.md` の「4つの守りの比較」に書く。

### B フックの入力の読みを固くする（`generator/guard_hook.py`。テストは `tests/test_guard_hook_input.py`）

- FR-04 入力を読むときのどんな例外でも、止める。
  - D0083-AC-04：壊れた JSON・UTF-8 でない入力・深い入れ子・空の入力・大きすぎる入力・読み取りの失敗で、フックは止める返事を出し、例外で落ちない。理由の文に入力の文字は入らない（`test_d0083_ac04_*`）。
- FR-05 止める返事を書き出せないときは、標準エラーに理由を書いて、終了コード 2 で終わる。
  - D0083-AC-05：標準出力に書けないとき、終了コードは 2。標準エラーにも書けなくても 2。本物のプロセスでも 2 で、120 にならない（`test_d0083_ac05_*`）。
- FR-06 標準入力の大きさに上限（16 MiB）を置き、超えたら止める。
  - D0083-AC-08：上限ちょうどは読め、1 バイト超えると止まる。読むのは上限＋1 まで（`test_d0083_ac08_*`）。
- FR-07 `agent_type` が文字列でも null でもない入力は、読む道具（Read・Glob・Grep）以外を止める（開発用のフックと同じ決まり。D0032）。
  - D0083-AC-09：文字列でない `agent_type` は、読む道具だけ通り、ほかは止まる。理由の文に入るのは型の名前だけ。ほかの `agent_type` と、`agent_type` の無い呼び出しは、今までどおり（`test_d0083_ac09_*`）。
  - D0083-AC-10：会話の道の入口（`chat_hook`）と `pipe-in-gen guard-hook` の入口でも、同じ（`test_d0083_ac10_*`）。
  - D0083-AC-11：A の表は、B のあとも書き換えなしで同じ結果（`tests/test_guard_matrix.py` をそのまま流す）。

## 決めたことと理由

- 表は `tests/` の中の Python のデータにした（JSON にしない）。行ごとに理由のコメントが要り、拡張とは共有しないため。期待の値は、読みからの予想でなく、テスト先行の段が9つの列に実際に流した結果を入れた。
- SDK の道の列を2つに分けた（守る場所 `protected_paths` を書かない・4か所を書いた）。既定が空であることが、差の中心のため。
- 実測で分かったこと（メモの表は読みからの整理だった）：
  - `git add`・`git commit` は、SDK の道と会話の道で通り、プラグインと開発用で止まる。`git push` は全部で止まる。
  - `$(…)` は、守る場所を書かない SDK の道でも止まる。
  - 開発用の `pipe-in-coder` は、`.pipe-in/` と `pipeline.toml` に書ける。
  - agents のある段は、会話の道では始める前に断るので、その段の列は「判断しない」にした。
  - **リンクを経た道で、書き込みが通る組が2つある**：プラグインの作る役（パイプの `prompts/` の中のリンクが `.claude/settings.json` を指すとき）と、開発用の `pipe-in-coder`（`src/` の中のリンクが同じ所を指すとき）。どちらもパスを文字として整えるだけで、リンクの先をたどらない。SDK の道（守る場所を書いたとき）と会話の道は、先をたどって止める。issue の決まりどおり、実際の結果を表に固定し、直すのは別の issue にする。
- B は、止める側に倒すだけで、止める範囲を狭めない。直す前に止まっていた入力で、直したあとに通るものは無い（A の表と既存の守りのテストが、書き換えなしで通る）。
  - 例外を受ける範囲は `Exception` の下まで（開発用のフックと同じ）。`KeyboardInterrupt`・`SystemExit` は受けない。
  - 止める返事を書けないときの形は、開発用のフックに合わせた（標準エラーと終了コード 2）。書けなかったバイトが残ると、終了の処理でまた失敗して終了コードが 120 に変わるので、本物の起動のときだけ、出力先を捨て先へ付け替える（`quiet_exit_streams`）。
  - 上限は 16 MiB（根拠のある数字ではない）。超えると、メインの会話の道具の呼び出しも止まる。
  - 文字列でない `agent_type` で通すのは、Read・Glob・Grep だけ。
  - 会話の道の入口（`chat_hook.py`）は、`guard_hook.main` と `decide` を通るので、コードを変えずに同じ直しが効く。
- 無人の実行（夜のまとめ実行）で進めた。次の点は推しの案で決めた（人の確認は朝）：上限の値／FR-07 を入れる／リンクを経た道は実際の結果を固定する／表の形と列の分け方／会話の道の入口も含める／例外を受ける範囲／通す道具は3つ。
- 受け入れたリスク：リンクを経た道の2つの組は、今は通るまま。フックそのものが起動できないとき（Python が無いなど）の動きは、この件では変えていない。

## 対象外・残った課題

- 開発用のフックを直すこと、守る範囲を変えること（#134 で行う）、Skill を SDK の道で止めることは、対象外。
- リンクを経た道の2つの組を止めることは、別の issue にする（`gh issue create` は人が決める。材料は上の「実測で分かったこと」）。
- FR-07 の「開発用のフックと同じ決まり」は、文字列でない `agent_type` を止めることが同じ、という意味。細部は2つのフックで違う（監査 A-04）：開発用は `SubagentHandback` も通し、判断の途中の例外では絞らない相手と読む道具を通す。プラグインは、通すのが Read・Glob・Grep だけで、判断の途中の例外ではどの呼び出しも止める。標準入力の上限は、プラグインにだけある。
- 監査の報告（5件。直していない。人の確認は朝）：
  - A-01 `docs/guide/safety.md` の「会話の道・プラグイン・開発用は、書かなくても止めます」は、開発用の `pipe-in-coder` が `.pipe-in/`・`pipeline.toml` に書けることと合わない（同じ節の表は正しい）。
  - A-02 同じ文書の「ほかの名前の文字列には何もしません」は、会話の中で段が開いているあいだ（`pipe-stage`・`pipe-probe` 以外をどれも止める）には当たらない。注記が要る。
  - A-03 `generator/guard_hook.py` の頭の説明・`decide` の説明・`plugin/hooks/hooks.json` の説明・`pipe-in-gen` の help・`docs/guide/plugin.md` の「それ以外には何もしない」が、文字列でない `agent_type` を止めるようになったことを書いていない。
  - A-04 上の項目のとおり。
  - A-05 `safety.md` の「Bash の `$(…)` は、どの守りでも道具ごと止めます」は、道具ごとでなく、そのコマンドを止める。
- 助言の報告（公式の文書 hooks のリファレンスと照らした。7件。直していない）：変えた5点（止める返事の形・書けないときの終了コード 2・上限・`agent_type`・例外）は、どれも文書の決まりに合う。文書に足すとよい点が3つ：`agent_type` が無いのは `--agent` を付けないメインの会話だけ（V-02）／0 と 2 以外の終了コードと、`pipe-in-gen` を起こせないときは「止めない失敗」で、プラグインの側の文書に明記が無い（V-03）／16 MiB は公式の上限でなく、このフックの自前の上限（V-05）。
- 審査の採点：overall 0.9、verdict は pass（しきい値 0.7）。審査役の指摘：助言 V-03 は、フックの失敗を止める側にできる仕組み（`onFailure: "block"`）に触れていない。プラグインのフックにこれを付けるかは、別に決める。公式の文書の後ろの3分の1は、助言役も審査役も読んでいない（入力の大きさの上限の記述があるかは未確認）。

## 確かめたこと

- 本体 `python -m pytest -q`：全部通った。拡張は触っていない。
- A の表（82 件）は、製品コードを変える前の作りで緑で、B のあとも書き換えなしで緑。
- B の赤の確かめ：足したテストのうち 102 件は、直す前に「深い入れ子で `RecursionError` が外へ出る」「標準出力に書けないと例外が外へ出て、本物のプロセスの終了コードが 1」「上限が無い」「文字列でない `agent_type` が通る」で落ちた。
- 途中で分かった環境の罠：開発用の入れ込み（`pip install -e`）が主の checkout を指していると、worktree のテストが、直す前の `generator/` を読む（`pipe_in/` は worktree のものを読む）。入れ込みを worktree に向け直して確かめた。
- Claude Code の実機で、フックが終了コード 2 を返したときに道具の呼び出しが止まることは、公式の文書によること（この実行では流していない。まだ）。
