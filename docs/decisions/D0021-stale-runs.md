# D0021 止まっているかもしれない実行の印（段のログが更新されない実行に「⚠ 更新なし」を出す）

## 目的

パイプを並列で流す人が、端末を閉じた・処理が落ちたなどで途中で止まった実行に気づけるように、「動いている」のまま段のログが決まった時間（既定 10 分）動かない実行に、実行パネルの図の節・一覧の行・詳細のバッジと知らせ・時系列の帯で「⚠ 更新なし」の印と言葉を出す。判定は段のログのファイルの更新時刻と今の時刻だけで行い、プロセスは調べない。イシュー #43。`docs/roadmap.md` 段階1「見る」。D0017・D0019 の「対象外」にあった「#43 で扱う」は、この記録が扱った。

#### 最後の更新の時刻（基盤）
- FR-01 段のログを読むとき、各ログのファイルの更新時刻（UTC のミリ秒）を記録の写しに付ける。読むのはいまの work_dir と別の worktree の work_dir のどちらも、同じ読み方
  - D0021-AC-01 段のログ（`logs/NN_<段>.jsonl`）を読むと、各ログに更新時刻が付く（いまの work_dir・別の worktree の両方）。（テスト：FS）
  - D0021-AC-02 更新時刻が読めない（`stat` が失敗する・途中で消えた）、または有限でない・0 以下の値のログは、時刻なしで写しに入る。読み取り全体は失敗しない。（テスト：FS・Q・PV）
  - D0021-AC-03 読み取りに足すのは `stat` だけ。書き込みの関数も子プロセスも使わない（読み取りの口の型は変わらない）。`utimes` など書き込みの関数は、確認用ページの作りとテストの中だけで使い、`src/` の製品のコードには入れない。（テスト：FS・AX）

#### 最後の更新からの秒
- FR-02 動いている段の節と、動いている run の行に、最後の更新からの秒（`quietSec`）を持たせる
  - D0021-AC-04 印の対象の run（FR-14）で、動いている段（今の判定と同じ：`Prompt` があり結果の行が無く、`state.json` に載った最大の通し番号より後ろの段のログ。判定の作りは変えない）があり、そのログの更新時刻が読めるとき、`quietSec` ＝ 今 − 基準の時刻（秒、切り捨て）が、図の動いている段の節と、一覧の行の両方に入る。基準の時刻は、その run の全ログのうち、更新時刻が読めるものの最新（FR-13）。同じ写しから純粋な関数が作った節と行は同じ値になる（本番の読み取りは図と行で別に 2 回読むので、境目では一瞬ずれうる。決めたことの「受け入れたリスク」）。（テスト：PV・RL・Q）
  - D0021-AC-05 更新時刻が今より先（時計のずれ）でも、`quietSec` は負にならず 0 になる。（テスト：PV・RL・Q）
  - D0021-AC-06 選ばれた動いている段のログに更新時刻が無いときは `quietSec` が null。ほかのログの時刻や、段の始まりの時刻（`Prompt` の `at`）・`updated_at` で代わりにしない（D0017 と同じ。当てにならない近似はしない）。（テスト：PV・RL・Q）
  - D0021-AC-07 動いている以外では `quietSec` は null：確認待ち・待ち（段の合間）・終わった・前の実行（`archive/`）の行、動いている段以外の節、記録なし。（テスト：PV・RL）
  - D0021-AC-08 `quietSec` は「今」を引数（`ViewClock`）で受ける純粋な関数で決まる。同じ入力なら同じ結果で、時計を読まない。（テスト：PV・RL・Q）
  - D0021-AC-48 `quietSec` は 7 日（604800 秒）を上限にする（D0019 の時系列の長さの上限と同じ）。古いファイルの時刻（1980 年など）でも、表示が桁あふれしない。（テスト：Q・PV・RL・PH）

#### 目安の時間と設定
- FR-03 「止まっているかも」と見なす目安の時間は、既定を 10 分にし、設定で変えられる。0 は印を出さない
  - D0021-AC-09 `vscode/package.json` に設定 `pipe-in.staleAfterMinutes`（整数・既定 10・最小 0）があり、説明に「0 で印を出さない」と書いてある。（テスト：MF）
  - D0021-AC-10 設定の値を目安の秒にする関数（`app/` に置く。置き場所は設計で決め、`design.md` の表を直す）：10 → 600、1 → 60、0 → 印なし（null）。設定が無い・整数でない（小数・文字・真偽）・負・無限大のときは既定の 600。（テスト：ST）
  - D0021-AC-51 設定の名前を `app/names.ts` に定数として持ち、その名前が `package.json` の設定のキーと一致する（`manifest.test.ts` の設定の一覧の期待にも足す）。（テスト：NM・MF・EX）

#### パネルのスクリプトの判定
- FR-05 パネルのスクリプトが、D0017 の数え上げと同じ仕組みで、基準＋描き直しを受けてからの時間が目安に届いた要素に `is-stale` を付ける
  - D0021-AC-13 描き直しを受けた直後、`data-quiet` を持つ要素は、基準 ≥ 目安なら `is-stale` が付き、基準 < 目安なら付かない（目安の 1 秒前・ちょうど・1 秒後を確かめる）。（テスト：PS）
  - D0021-AC-14 目安に届いていない要素は、パネルの時計で測った経過を基準に足した値が目安に届いたとき、1 秒ごとの数え上げの中で `is-stale` が付く。記録の時刻もファイルも読まない。（テスト：PS）
  - D0021-AC-15 印の中の時間（`data-elapsed` に基準の秒を入れる）は、`is-stale` の付く前も後も同じ数え上げに乗って 1 秒ごとに増える。（テスト：PS）
  - D0021-AC-16 新しい描き直しで基準が目安より小さくなる（記録が更新された）と、`is-stale` が外れる。基準が目安以上のままなら付いたまま。（テスト：PS）
  - D0021-AC-17 数え上げる要素（`data-elapsed` か `data-quiet`）が無ければタイマーを回さない。`data-quiet` だけの描き直しでも回る。タイマーは 1 つのまま。（テスト：PS）
  - D0021-AC-18 隠れるとタイマーが止まり、戻ると隠れていた時間を足して付け直す。隠れているあいだに目安を越えていれば、戻った時点で付く。（テスト：PS）
  - D0021-AC-19 パネルの時計が戻っても、数え上げは基準より小さくならず、付いた `is-stale` は次の描き直しまで外れない。（テスト：PS）
  - D0021-AC-20 `data-stale-after` が 1 以上の整数の文字（数字だけ）でないとき、`data-quiet` が 0 以上の整数の文字（数字だけ）でないときは、`is-stale` を付けない。確かめる値：空・空白・`0`・`-5`・`abc`・`NaN`・`Infinity`・`1e3`・`+5`・`1.5`・属性が無い。`0` を目安にしても、すべての要素が最初から印にならない。（テスト：PS）
  - D0021-AC-21 動きを減らす設定でも判定は続き、`is-stale` は付く。（テスト：PS）
  - D0021-AC-22 拡張へ送るメッセージの種類は増えない（`ready`・`openArtifact`・`selectRun`）。CSP は今のままで、`style=`・`on…=`・外部の読み込みを足さない。（テスト：PS）
  - D0021-AC-23 D0016・D0017・D0019 でパネルの中に持つもの（理由の欄の選び・絞り込みとタブ・スクロール位置・焦点・戻る矢印の光り）が、`is-stale` の付け外しのあとも残る。（テスト：PS）

#### 時系列の帯
- FR-09 動いている帯に印を添える

#### 古い記録・読めない値
- FR-10 古い記録・壊れた記録でも、例外を出さず、読めないものには印を出さない
  - D0021-AC-35 `Prompt` に `at` が無い・`started_at` が無い・`stages` が無い古い形の記録でも、`state.json` が読めてログの更新時刻が読めれば、節・行・バッジ・知らせに印が出る。矢印は元から流れない（AC-54）。時系列は動いている帯が無い（「時刻の記録なし」・「時刻の記録がありません」のまま）ので出ない。印の時間は D0017 の経過の要素とは別なので、経過が出ない記録でも印は出る。読めなければ何も出ない。D0017-AC-31・D0019-AC-30 の古い形のテストは今のまま通る。（テスト：EC・FL）
  - D0021-AC-36 壊れたログ・形の違う値（`mtime` が文字など）でも、例外を投げず、印は出ない。（壊れた `state.json` は AC-49）（テスト：EC・Q）

#### 最後の更新の取り方
- FR-13 「最後の更新」の基準は、その run の全ログのうち最新の更新時刻にする（動いている段として選ばれたログだけでは決めない）
  - D0021-AC-44 中断した古い途中のログ（通し番号が大きい・`Prompt` だけ・更新が 3 日前）と、再開後の新しいログ（更新が 5 秒前）が並ぶ写しでは、動いている段の判定は今のまま（古い方の段）だが、`quietSec` は 5 になり、印は付かない。（テスト：Q・PV・RL・PH）
  - D0021-AC-45 全ログの更新時刻が目安より古い（放置された実行の）写しでは、最新の更新時刻から決まる `quietSec` が目安以上になり、印が出る。1 つでも目安より新しいログがあれば出ない。（テスト：PV・RL・PH）

#### 印の対象
- FR-14 印は、`state.json` が読めて形が合い、`final` が無く、前の実行（`archive/`）でない run の、動いている段にだけ出す（節・矢印・行・バッジ・知らせ・帯のどれも、同じ根拠で決める）
  - D0021-AC-46 `final` がある run（`PASSED`・`STAGE_ERROR`・`STOPPED_BY_HUMAN` など）に、結果の行が無い途中のログが残る写し（`runList.test.ts` の「final があり、動いているログもある」と同じ形に更新時刻を付けたもの）で、節・矢印・行・バッジ・知らせ・帯のどれにも `quietSec` が付かず、`data-quiet` が出ない。（テスト：PV・RL・PH）
  - D0021-AC-47 前の実行（`archive/<日時>`）を選んだ図・詳細・時系列にも、同じ形の写しで印が出ない（行は元から「終わった」）。（テスト：PV・RL・PH・AR・FS）
  - D0021-AC-49 `state.json` が無い・JSON として読めない・オブジェクトでない run（ログだけが残る）は、動いているログがあっても `quietSec` が null で、どの面にも印が出ない。最初の段のあいだ（`state.json` がまだ無い）と、壊れた `state.json`（通し番号の基準が 0 になり、古いログを拾うため）がこれにあたる。（テスト：PV・RL・PH）

#### 画面・手で・実機

## 決めたことと理由

### 人が決めたこと（要件定義で聞いた 5 点）

- **「最後の更新」の元は段のログのファイルの更新時刻（mtime）。** 本体を読むと、動いている段のあいだに進みうるのは段のログの mtime だけだった（`state.json` の `updated_at` は段が終わるまで動かず、ログの行に時刻は無い。SDK の段のログもバッファが溢れるまで進まない）。本体に行ごとの時刻や `flush` を足す案（本体と記録の形を変え、古い記録に効かない）と、成果物の更新時刻も入れる案（動いているあいだの信号として弱く、読み取りが増える）は採らなかった。
- **基準はその run の全ログのうち最新の更新時刻**（動いている段のログ 1 つではない）。`--from` で再開したとき、中断した古い途中のログが「動いている段」として選ばれ続ける今の作りでも、元気な実行に誤報を出さないため。動いている段の判定そのものは変えない。
- **設定 `pipe-in.staleAfterMinutes`（整数。既定 10。0 で印なし。上限 10080 分＝7 日）を足す。** 段によって「静かな時間」の普通の長さが大きく違うので、固定の値では誤報か見逃しになる。10 分は要件メモの例の値で、測っていない。
- **静かな長い段（SDK の長いコマンド・長い考え中、`record` 経由の段）は動いていても印が出ることを受け入れる。** 印は「かも」の知らせで、知らせの文に「プロセスは調べていません。長い段では、動いていてもログが更新されないことがあります」と書き、ガイドと設定で補う。
- **印は要件メモの「節と行」から、詳細のバッジ・知らせと時系列の帯まで広げる。** D0019 の 3 つの領域のどこを見ても分かるように。
- **判定の穴（最初の段のあいだ `state.json` が無い・再実行で前の記録が残る・並列で先に終わった段・再開で古いログが選ばれる）は別の issue。** この機能は判定の作りに触れず、印の誤報が出ない側に倒した。

### 聞かずに決めたこと

- 状態の言葉「動いている」は替えず、印を**添える**（時系列の帯も「● 動いている」を残して「⚠ 更新なし」を添える）。行の状態・見出し・タブの件数は図とステータスバーと同じ判定（D0019）で、時刻で変えると食い違うため。
- 言葉は「⚠ 更新なし 10:12」（時間は D0017 と同じ `m:ss`・`h:mm:ss`）。詳細のバッジは「⚠ 止まっているかも」。
- 印の対象は、`state.json` がオブジェクトとして読め、`final` が無く、前の実行（`archive/`）でない run の動いている段だけ。確認待ち・待ち（`idle`）・終わった・前の実行には出さない。「待ちのまま長く動かない」印は別の issue。
- 名前は `quietSec`（最後の更新からの秒）・`data-quiet`・`data-stale-after`・`is-stale`。状態の `idle`（待ち）と紛れないように `idle` を避けた。
- 拡張は描き直しのたびに、基準の秒と目安の秒を HTML の属性で渡し、パネルのスクリプトが D0017 の数え上げと同じ 1 つのタイマーで比べて `is-stale` を付ける。付けるだけで外さず、外れるのは記録が更新されて描き直されたとき（DOM ごと入れ替わる）。時計が戻っても経過は負にならない。
- `quietSec` は `PipelineView.quietSec` の 1 か所で作り、節・帯・行はそこから取る（節が作られない段名でも行と帯がずれない）。目安はドメインに入れず、画面の部品の引数で渡す（`quietSec` は目安に依らない事実。設定が変わっても読み直しは要らず描き直しだけで足りる）。
- 読み取りは、ログの中身を読んだあとに `stat` する（読んだあとに追記されると時刻は新しく出るので、誤報の側に倒れない）。読み取りの口（`ReadOnlyFs`）は 6 つのまま。`final` のある run・`archive/` の run は今までどおり `logs/` を開かない。
- 7 日の上限（時系列の長さ・`quietSec`・設定）は `domain/timestamp.ts` の `MAX_SPAN_SEC` 1 つから作る。
- 節に印が出たら 2 行目の「経過」を隠して印に入れ替える（節の幅 176px に 2 つ並ばない。経過は行・詳細・時系列に残る）。時系列の帯は普段の文字と印つきの文字を両方持ち CSS で入れ替える（目安の手前の見え方を変えないため）。一覧の行は、印が出る行だけ 3 行目（セッション ID の行）を包み、印は右に置く。印の無い行の HTML は 1 文字も変わらない。
- 色は橙（`--vscode-charts-orange`）の枠と点線だけで、文字は前景色（橙の文字は明るいテーマで読みにくい）。確認待ちの黄の実線とは、点線・「⚠」・言葉で見分ける。動きの CSS は `prefers-reduced-motion: no-preference` の中だけで、印そのものは動きを減らす設定でも出る。
- 印の要素の中身は固定の言葉と数字だけ。拡張へ送るメッセージの種類（`ready`・`openArtifact`・`selectRun`）・CSP は変えない。
- 確認用ページは、動いている見本をすべて一時フォルダに写し、ログの更新時刻を見本の「今」からの相対にそろえる（`utimes` は `scripts/` とテストの中だけ。`tests/fixtures/` は読むだけ）。更新なしの見本 `run-panel-stale-light/dark`（目安を 12 秒過ぎた）と `run-panel-stale-soon-dark`（5 秒手前。`window.__previewNext()` で更新後の本体を送れる）を足した。
- 要件定義の AC-35 の読み方：矢印と時系列に印が出ないのは `Prompt` に `at` が無い記録だけ。`started_at`・`stages` が無い記録は、実物の作りどおり矢印も帯も出る。
- 文書の検査は前例どおり `tests/test_guide.py` に置く。`extension.ts` の配線（設定を読む・目安を渡す・`previous` を渡す・設定が変わったら描き直す）は、ソースを文字で読む検査で守る。
