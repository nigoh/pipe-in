# D0064 確認待ちから、確かめる文書を開き、答え方を案内する

## 目的

D0046（確認待ちの知らせ）では、知らせのボタンが「実行を見る」だけで、確かめる文書を直接開けず、答え方も案内していなかった。GitHub の issue #98（#14 の残り）を扱う。

## 機能要件と受け入れ基準

- FR-01 開いたパネルの確認待ちの知らせ（黄の枠。`view/shellHtml.ts` の `renderNotice`）に、「確かめる文書を開く」ボタンを足す。
  - D0064-AC-01 ボタンは既存の `openArtifact`（`data-artifact`）で、新しいメッセージの種類は足さない。
  - D0064-AC-03 成果物の一覧にあって読める文書のときだけ出す。出せないときも答え方は出す。
- FR-02 同じ枠に答え方を出す。
  - D0064-AC-02 `python -m pipe_in record review <段> approved`・`revise --feedback`・`quit` と、`/pipe-in --artifact` のときのアーティファクトのボタン（D0044）。
- FR-03 既存の決まりを変えない。
  - D0064-AC-04 外から来た文字は `escapeHtml` を通す。
  - D0064-AC-05 動いている段があるとき・終わったあとは出さない。
  - D0064-AC-06 知らせ（`showInformationMessage`）のボタンは「実行を見る」だけ。D0046 の「同じ待ちで1回だけ・`pipe-in.notifyWhenWaiting` で切れる・パネルで見ている実行は外す」は変えない。

## 決めたことと理由

- 知らせのボタンは増やさず、開いたパネルの側で案内する（人と決めた。知らせのボタンが増えすぎないように）。
- 開くボタンは成果物のタブと同じ仕組みを使い、拡張が書く場所も、依存も増やさない。

## 対象外・残った課題

- 知らせの文は変えない。`/pipe-in --artifact` を使っているかどうかは拡張からは分からないので、答え方は両方を並べる。
