# D0017 実行の図で、動いている様子と各段の時間をリアルタイムで見られるようにする

## 目的

実行パネルの図を見る開発者が、いまどの段が動いている・確認を待っているか、それぞれにどれだけ時間がかかっているかを、図の動きと1秒ごとの数え上げで一目で分かるようにする。見ていて飽きない画面にする。イシュー #41。`docs/roadmap.md` 段階1「見る」。

## 決めたことと理由

人が決めた 4 点（要件定義）。

- やり直した段の回ごとの時間は、右の欄の「時間」の節に出し、図の節には合計だけを出す。節のツールチップはキーボードや狭い画面で読めず、節を高くすると図の位置が全部ずれる。D0016 の理由の欄と同じ並びになる。
- 確認待ちの時間は段の合計に入れず、確認の節に待ち時間として出す。人が文書を読んでいる時間で、段の実行時間とは別のため。
- 一度だけ光らせるのは、検証の不合格の戻る矢印と、確認の修正の矢印の両方（どちらも「戻る矢印」）。
- 新しく書く時刻は UTC からのずれつきにする。拡張とパイプの実行で時刻帯が違っても合う。

人が決めた 2 点（設計とテスト先行のあと）。

- 差し戻しの光りは、光り始めの時刻を覚えて、1.4 秒のあいだは `render` をまたいで付け直し、続きから動かす（Web Animations の `currentTime`）。実行中は記録の更新で `render` がよく来るので、「次の `render` で消える」では光りが途中で切れる。
- 始まりの時刻が無い記録では、バナーの全体の経過も数え上げない（`started_at` はずれなしの古い書き方なので、時刻帯が違うと合わない）。

聞かずに決めたこと。

- 時計のずれは、パネルが記録の時刻と自分の時計を比べないことで避ける。拡張が `render` のたびに「その時点の経過秒」を HTML に入れ、パネルは受けた時刻からの差だけを足す。拡張ホストの側で時計を読むのは `extension.ts` だけで、domain は「今」を引数（`ViewClock`）で受ける。
- 隠れたパネルは `visibilitychange` で止めて戻す。数え上げのために `retainContextWhenHidden` は使わない（メモリを使い、`render` が溜まる）。
- 時刻の無い進行中の記録を `updated_at` で近似することはしない（不正確なため）。
- 時刻の書き方は本体の `pipe_in/engine/clock.py` の1か所にする。

形の互換：`state.json` の `pending_review.since` と、段のログの `Prompt` 行の `at` を足すだけ（開発フローの `at` はずれつきに替わる）。`started_at`・`updated_at`・`began_at` は今のまま。古い記録は、時刻が無ければ今までどおり終わった時間だけを出す。拡張のメッセージの種類と `render` の形は変えない。依存は足していない。

画面用の見本は、完了の `tests/fixtures/showcase/` に加えて、途中で止めた3つ（`showcase_running`：実装の2回目が動いている、`showcase_running_next`：検証の2回目が動いている、`showcase_waiting`：要件定義の確認待ち）を `tests/showcase.py` で作る。確認用ページ `run-panel-running-*`・`run-panel-waiting-*` は、始まりから 83 秒・待ち始めから 40 秒の時点を「今」にして組み立てる。完了の見本は `Prompt` 行に `at` が足されただけで、`99_summary.md` は作り直さない（利用枠の戻る時刻が手元の時刻帯で変わるだけのため）。

### D0010・D0016 からの変更

[D0010](D0010-ui-records.md)・[D0016](D0016-sendback-reasons.md) は書き換えない。次が変わる。

- 終わった段の時間の書き方が `12s` から `0:12` になった。
- 図の節に、経過・待ち時間の文字と動き（脈打ち・流れる点・点滅・一度だけの光り）が付いた。戻る矢印の `<g>` は回数を `data-count` に持つ。
- 右の欄の並びに「時間」の節が入った（注意 → 理由 → 時間 → 出力 → 成果物 → 使用量）。
- パネルのスクリプトが、タイマー1つと、光りの覚え（`flashMemo`）を持つようになった。拡張へ送るメッセージの種類は変わらない。

## 対象外・残った課題

- 止まっているかもしれない実行の印（本体が落ちて「動いている」のまま残ると、数え上げは増え続ける）。#43 で扱う。
- 費用やトークンの動き、残り時間の見積もり、確認待ちの時間を履歴に残すこと。
- パイプの差し戻しの矢印（#12）、作業台の動き。
- 光っている途中は、線が太くなるのに合わせて矢印の先の三角も大きくなる（`marker` が線の太さで大きさを変えるため）。目立つが少し大きい。気になれば別に直す。
- 開発フローの古い `at`（ずれなし）と `started_at` は手元の時刻として読むので、時刻帯の違うリモートでは全体の経過がずれることがある（受け入れたリスク）。
