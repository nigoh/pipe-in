# D0030 ブランドを「プラグ」に決め、画面のデザインの土台を docs/design/ に残す

## 目的

計画ボード・実行パネル・進み具合のページ・パイプ作業台の見た目がばらばらだった。ブランドの色とスタイルを1つに決め、部品と画面の見本をそろえて、これから画面を直すときの土台にする。

## 決めたことと理由

- **5案（プラグ・配管図・信号・藍染・端子台）から「プラグ」を選んだ。** 今のロゴのコーラルとティールをそのまま使え、ロゴを作り直さずに済む。形も色数も少なく、いちばん簡素。
- **コーラル＝人が手を出す、ティール＝流れている・選んでいる、と役で分けた。** ボードでも作業台でも「どこで人の手が要るか」が同じ色で分かる。
- **状態は色だけでなく印と言葉でも伝える。** 色の見分けがつきにくい人や、明暗の画面の違いで読み違えないため。
- **明るい画面と暗い画面の色を対で決めた。** VSCode も claude.ai も暗い画面で使う人が多い。どの板も明暗を左右に並べて確かめた。
- **作業台のケーブルの色を変える。** 今の「次の段は青・分岐は茶・差し戻しは赤の破線・並列の枠は緑」から、プラグの色に寄せ、線の形でも見分けられるようにする（コードに入れるのはこれから）。
- **アイコンは Lucide（ISC）を使い、自作しない。** 線の太さ 2px・角の丸い線画で、プラグの見た目に合い、商用でも使える。npm の依存には足さず、使うアイコンの SVG だけを写し、ライセンスの全文を `docs/design/LICENSE-lucide.txt` に置く（拡張は外から読み込まないため）。コンセントとプラグ、フロー図の形のブロックの外形は pipe-in だけの形なので自作。
- **キャンバスの写しをリポジトリに置き、URL は置かない。** キャンバスは持ち主だけが開ける手元のもので、URL は手元の事情にあたる。写しがあれば、別の会話でもキャンバスを作り直せる。
- **画面の中の見本の名前は、手元のセッションの名前を使わない。** 公開するため、見本の題（「CSV 出力を足す」など）に置き換えた。

## 対象外・残った課題

- 画面のコードへの反映（進み具合のページ `live_page.py`、実行パネルと作業台 `vscode/`）。画面ごとに `/pipe-in` で進める。計画ボード `board.html` は、プラグの色・Lucide のアイコン・状態の札・模様のある進み具合の棒・棒の本数で示す優先に合わせた（左の帯の色はやめ、枠と下地で示す）。
- 色の決まりを1か所（CSS の変数やトークンのファイル）にまとめること。拡張に入れるときに決める。
- README のロゴ・画像の撮り直し。

## 確かめたこと

- 足したテスト 6 件のうち、README と記録が無いことで 3 件が期待した理由で落ちることを確かめてから書いた（残り 3 件はキャンバスの写しを見張るもので、写したあとなので通る）。書いたあと、`pytest -q` が通る。
- 明暗の色の組み合わせは、キャンバスの板の上で目で確かめた。コントラストの比を道具で測ることは、まだ。
