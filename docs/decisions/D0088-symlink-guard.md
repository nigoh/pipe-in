# D0088 リンクを経た道の書き込みを止める（プラグインの作る役・開発用のフック。#137）

## 目的

D0083 の実測で、リンクを経た道の書き込みが通る組が2つ見つかっていた。

- プラグインの作る役（`pipe-builder`）：パイプの `prompts/link.md` が `.claude/settings.json` を指すリンクのとき、書けた。
- 開発用のフックの `pipe-in-coder`：`src/link.json` が `.claude/settings.json` を指すリンクのとき、書けた。

どちらのフックも、パスを文字として整えるだけで、リンクの先をたどっていなかった。SDK の道と会話の道は、先をたどって止める。2つのフックも、リンクの先を見て判断するようにする。D0083 の「受け入れたリスク」（この2つの組は通るまま）を、この記録が置き換える。

### 要求と前提

- UR-01 利用者として、書ける場所の中のリンクを経て、守る場所（`.claude/` など）に書き込まれたくない。
- 前提：フックが判断した時点と、道具が書く時点のあいだに、リンクは差し替えられない（差し替えの競り合いは対象外）。
- 状態を持ち、操作や出来事で移り変わるか
  - 答え：いいえ
  - 理由：1回の書き込みごとの判断で、状態を持たない。

## 決めたことと理由

- 判断の形は、「文字の上の判断（今のまま）と、リンクをたどった判断の、両方が通るときだけ通す」。今の条件に「かつ」を足すだけなので、今まで止まっていた呼び出しが通ることは無い（止める範囲を狭めない）。たどった判断だけにすると、守る場所の中のリンクが書ける場所を指すとき（`.claude/x` → `src/app.py`）に通ってしまうので、選ばなかった。
- 基準の側（パイプの置き場所・環境変数の置き場所・プロジェクト）も、同じようにたどってから比べる。置き場所そのものがリンクの対象や、`/tmp` がリンクの OS で、今まで通っていた書き込みを止めないため。
- 壊れたリンクと輪は、先がどこでも一律に止める（先の有無で分けるより単純で、安全側）。`os.path.realpath` は、輪でも例外を出さずに途中の形を返すので、返ったパスにリンクが残っていれば、決められないものとして止める。
- リンクをたどる補助（`_trace` など）は、2つのフックに同じ形で写した。どちらも1つのファイルで動く作りで、標準ライブラリだけにするため。
- 開発用のフック（`.claude/hooks/`）は、段のサブエージェントが書けない。人の承認を得て、メインが直した。`project_path`（文字の上の判断）は1行も変えず、たどった判断の関数 `project_real_path` を足して、書き込みの判断の条件に加えた。
- 守りを変える変更なので、理由を書く：止める側への変更で、止める範囲を狭める所は無い。すり抜けの道（Bash・PowerShell・MCP・サブエージェント）の結果は、比較の表が書き換えなしで見張っている。
- **今まで通っていて、止まるようになる場面**：書ける場所の中のリンクで、先が書ける場所の外（`.claude/`・`.git/`・ほかの段の記録・パイプの外・プロジェクトの外）を指すもの／壊れたリンク・輪になったリンク。
- 既存のテストの直し：比較の表の2行の期待（`DDDDDDDAD`・`DDDADDDAD` → `DDDDDDDDD`）と、その行を見るテストの説明。名前は、D0083 の記録が引いているので変えていない。
- 無人の実行で進めた。次の点は推しの案で決めた（人の確認は朝）：両方が通るときだけ通す形／壊れたリンクは一律に止める／置き場所のリンクは、基準もたどって通す／補助は2つのフックに写す。

## 対象外・残った課題

- Bash の中のリンク（Bash の書き込みの検査は別の部品）、書いたあとにリンクへ差し替える競合、守る範囲を変えることは、対象外。
- 開発用のフックでは、作業フォルダと書き込み先の、片方だけがリンクを経た形（基準と先で形が食い違う）は、文字の上の判断で今までどおり止まる（通るようにはしていない）。プラグインのフックは、絶対パスなら作業フォルダを基準に使わないので、今までどおり通る（D0088-AC-04）。
- 開発用のフックの `pipe-in-coder` が `.pipe-in/`・`pipeline.toml`・`.mcp.json` に書けること（D0083・D0087 の実測）は、この件では変えていない。
- 2つのフックを別のコミットにする案は採らなかった。比較の表のリンクの2行は、両方の直しがそろって初めて全部「止める」になるため、1つのコミットにした。
