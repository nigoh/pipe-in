# D0032 サブエージェント用のフックが落ちても、通す側でなく止める側に倒す

## 目的

/pipe-in の段を受け持つサブエージェントを絞るフック（`.claude/hooks/pipe_in_guard.py`）が、内部の失敗や想定外の入力で落ちても、書き込み・Bash・Web の絞りが外れて道具の呼び出しが通ることがないようにする。止める表と許す表（何を許し、何を止めるかの一覧）は変えず、「壊れたときに通す」穴を塞ぐ（例外のときと、型のおかしい `agent_type` では、止める側に広げる）。イシュー #52（親イシュー #3。`docs/roadmap.md` の段階0「足場」）。

公式の文書（https://code.claude.com/docs/en/hooks）によると、PreToolUse の command フックが起動できない・終了コードが 0 と 2 以外・時間切れのとき、道具の呼び出しは止まらずに通る（例外は 2 つ。`"onFailure": "block"`（v2.1.295 以降）を付けたときは止まる。Git Bash の無い Windows で、シェルを通す形のフックが失敗したときは、止まることがある）。今までのフックは、入力が読めないときだけは止めたが、判断の途中で例外が出ると Traceback で終わり（終了コード 1）、絞りが外れて通っていた。

## 決めたことと理由

### 人が決めたこと（要件定義で聞いた 7 点。どれも推しの案）

- **例外のとき、メインなど pipe-in- で始まらない呼び出しは止めない。** 止めると、フックが壊れたときに、メインがそれを直す Edit まで止まって、直せなくなる。入力が読めないときだけは、だれの呼び出しか分からないので、今までどおり全部止める。
- **`.claude/settings.json` に `"onFailure": "block"` は付けない。** 付けると、python が無い・起動できない環境で、メインを含むすべての道具の呼び出しが止まり、フックを直すこともできなくなる。このキーには v2.1.295 以降の Claude Code が要る（公式の文書）。それより前の版の動きは文書に無い。代わりに、Python の外の失敗（python が無い・時間切れ・構文エラー）では素通りになることを、受け入れたリスクとしてガイドと原則とこの記録に書いた。
- **止め方は、まず deny の JSON。それも書けないときだけ、終了コード 2 と標準エラー。** deny の JSON の理由がサブエージェントに届くことは D0004 で見ている。公式の文書では、終了コード 2 のときは標準エラーの文が、止めた理由として Claude（サブエージェント）に届く。人にどう見えるかと、実機での動きは確かめていない（AC-32）。
- **`generator/guard_hook.py`（利用者のプロジェクトのガード）は範囲に入れず、別のイシューにする。** 入力を読むところに同じ種類の穴があるはずだが、守る相手と呼ばれ方が違う。
- **Stop のフック（`docs_reminder.py`）は範囲に入れない。** 知らせのためのもので、守る仕組みではない。
- **`agent_type` が文字列でも null・無しでもないとき（リスト・数値など）は止める。** 型が変わったときに絞りが黙って外れるより、目に見えて止まるほうがよい。公式の文書は `agent_type` を文字列の名前（サブエージェントの中か、`--agent` で始めた会話のとき）と書くので、文字列でないときに止めるのは念のため。文書から分かること：`claude --agent pipe-in-…` で始めたメインの会話にも `agent_type` が付くので、絞られる。プラグインのサブエージェントは `pipe-in:pipe-builder` の形で `pipe-in-` で始まらず、このフックは今までどおり絞らない。
- **例外のとき、読むだけの道具と報告（Read・Glob・Grep・SubagentHandback）は通す。** 書かない道具なので、通してもすり抜けの道は開かない。止めると、auto モードでは、どこにも書けない係（監査など）が、親へ報告を返す道が無くなる（D0004。公式の文書では、`SubagentHandback` が渡されるのは auto モードのときだけで、そうでないときは最後の返答の文が報告になる）。

### 設計とテスト先行で人が決めたこと

- AC-28 の表の位置は番号の順（前の番号は決め打ちしない）。作業のあいだに main に D0027〜D0031 が入ったため、この記録の番号は D0027 → D0028 → D0030 → D0031 → D0032 と振り直した。テスト先行の段で承認されたテストは「D0027 の行の次」を見ていたが、振り直しに合わせてメインがこの形に変えた（このとき足したテストで、既存のテストではない）。
- 例外で止めた理由の文の確かめ（AC-16）は、表にある 8 つの係に限る。表に無い `pipe-in-unknown` は、例外を出さずに、いつもの理由で止まる。止まることは 9 つとも確かめる。
- 変えたファイルの確かめ（AC-24）は、`git status --short` と、実装の前のコミットからの `git diff` で見る（コミットは言われるまでしないため）。
- テスト先行のあとに、テストが見ていた 2 つの動き（理由の長さの上限・文字列でない `agent_type` の理由）を、AC-33・AC-34 として足した。

### 止める範囲を広げる側の変更と、その理由

止める範囲を狭める変更は無い。次の 3 つは、止める側に広げる変更（CLAUDE.md の決まりで、理由をここに残す）。

- pipe-in-* の呼び出しで、判断の途中に例外が出たら止める（今までは通っていた）。理由：守る仕組みが壊れたときに通るのは、守る仕組みが無いのと同じ。
- `agent_type` が文字列でも null でもない呼び出しを、分からない相手として止める（今までは、リスト・辞書は例外で通り、数値・真偽は何もせず通っていた）。理由：上の人が決めたこと。
- 止める理由の文の長さを `REASON_LIMIT` で切る。止める判断は変わらない（切るのは判断のあと）。理由：公式の文書では、フックの出力（標準出力の文など）は 10,000 文字までで、超えるとファイルに保存され、先頭 2,000 文字の抜粋だけになる。止める理由（`permissionDecisionReason`）が超えたときの扱いは文書に無く、読まれなければ deny が無かったことになるため、十分下の長さで切る。

すり抜けの道（PowerShell・MCP・Agent・Web・ノートブック）が開かないことは、AC-19 で `main()` 経由で確かめた。囲みは「通す」側に倒れる道を作らない（例外で通るのは、読むだけの道具と報告だけ）。

### 聞かずに決めたこと

- フックの入口を `_run()`（今の中身）と最後の砦 `_last_resort()` に分け、`main()` は `except Exception` で受ける。判定は `is_pipe_in_agent`・`is_guarded_caller`・`is_read_only_tool` の 3 つの関数にまとめ、`decide` は 3 か所だけ変えた。`project_root`・`check_*` は 1 文字も変えていない。
- UTF-8 にできない文字は、書き出しの 1 か所（`encode` の `errors="replace"`）で `?` にする。項目ごとの掃除にしないので、理由に入る項目が増えても同じ所で直る。`surrogatepass` は UTF-8 として読めず、`ensure_ascii=True` は単独のサロゲートを先へ渡すので選ばなかった。
- 書けなかったバイトが残ると、Python の終了処理の flush がまた失敗して、終了コードが 120 に変わる（0・2 以外なので Claude Code は通す）。`__main__` で、戻り値が 0 でないときだけ、標準出力と標準エラーを `os.devnull` へ `dup2` で付け替え、できなければ `sys` から外してから終わる（`_quiet_exit_streams`）。`main()` の中では付け替えない（テストで `main()` を呼んだとき、pytest の出力の取り込み先を壊さないため）。
- `official_doc_url` は `urlsplit` の `ValueError` だけを受ける（1 つの型）。ほかの例外は入口の囲みが受ける。
- `REASON_LIMIT` は 1000 文字（目安。公式の文書の上限ではない）。切る前の本文がこの長さまでで、切ったときは印（15 文字）の分だけ長くなる。止める理由の固定の文は長くても 200 文字ほどで、テストが探す語句は切る前の部分に残る。
- 実装はメインが書いた（`pipe-in-coder` は `.claude/` を書けないため。D0008 の前例）。テストは `pipe-in-tester`、文書の下書きは `pipe-in-coder`。

### 既存のテストを変えた理由

既存のテストは書き換えていない（足しただけ）。検証のあとの監査を受けて、足したテストの説明文とコメントだけを直した（テスト先行の段の言い方「今は TypeError で通る」などを「実装の前は…」に、公開されない設計の節を指していた所を、この記録の項目を指すように。テストの中身と名前は変えていない）。

### 受け入れたリスク

- **Python の外の失敗は素通りになる。** python が見つからない（macOS や Linux で `python3` だけの環境を含む。フックの `command` は `python` で呼ぶ）・起動できない・構文エラー・時間切れ（30 秒）のとき、フックはこのファイルの中では止められず、道具の呼び出しは通る。`onFailure` を付けない代わりに、ガイド（`develop.md`）と原則（`principles.md`）に書き、/pipe-in を始める前に `python --version` で確かめるよう案内した。フックが失敗すると会話に `hook error` の知らせが出る（公式の文書）ので、/pipe-in の最初の道具の呼び出しのあとに、この知らせが出ていないかでも気づける。逆に、Git Bash の無い Windows では、フックの失敗で道具の呼び出しが止まることがある（公式の文書。メインも止まる）。
- 直したフックは、main に入るまで、ほかの会話には効かない（動くフックは会話を始めた場所の写し。D0004・D0008 と同じ）。
- 例外で止めたときの理由には、例外の種類の名前だけを入れ、メッセージは入れない。原因を探すには、フックを手で流す必要がある。
- UTF-8 にできない文字は、理由の中で `?` に見える（止める判断は変わらない）。
- Python 3.11.4 より前では、`https://[docs.claude.com]/` のような角かっこのホストを `urlsplit` が受け付けるので、AC-07 のその 1 件は今のフックでも通る（どちらの版でも止まる）。

### D0008 と前のフックからの変更
