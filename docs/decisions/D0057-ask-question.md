# D0057 人に確認・質問・承認を求めるときは、質問欄（AskUserQuestion）で聞く

## 目的

人に確認や質問をするときの聞き方を、CLAUDE.md の「必ず守ること」の決まりにする。会話の文だけで聞くと、人は見落とす。選ぶ形のほうが答えやすい。人は「質問欄を作らなかったときは答えない」ことを、今後の決まりにすると決めた。開発用のスキル（`.claude/skills/`）の人に聞く所からも、この決まりを指す。

## 機能要件と受け入れ基準

### 機能要件

- FR-01：CLAUDE.md の「必ず守ること」に1項目を足す。人に確認・質問・承認を求めるときは、質問欄（AskUserQuestion）で聞く。会話の文だけで聞かない。
- FR-02：その項目に、理由を1文で添える（会話の文だけの質問は見落とされる。選ぶ形のほうが答えやすい）。
- FR-03：質問欄が使えない会話では、会話の文で、番号つきの選択肢と推しを添えて聞く。
- FR-04：質問欄の使い方の目安を添える（1回に1〜4問、1問に2〜4択。自由に書く答えは「その他」で受ける）。`--auto` でも、止まって聞く所は同じ。
- FR-05：対象の範囲を書く。`pipe_in/` 本体の段の確認（端末の入力）と、人に質問できない段のサブエージェントは対象外。
- FR-06：7つの開発用のスキル（pipe-in・pipe-talk・pipe-plan・pipe-docs・pipe-audit・pipe-advise・pipe-judge）の人に聞く所に、CLAUDE.md の決まりを指す1行を足す。決まりの本文は写さない。

### 受け入れ基準

- D0057-AC-01 CLAUDE.md の「必ず守ること」に、`AskUserQuestion` と「質問欄」を含む項目が1つある（`tests/test_ask_question.py`）
- D0057-AC-02 その項目に「会話の文だけ」がある（同）
- D0057-AC-03 その項目に、質問欄が使えない会話での扱いがある（同）
- D0057-AC-04 その項目に、`pipe_in/` 本体の段の確認（端末）が対象外とある（同）
- D0057-AC-05 「必ず守ること」の既存の9項目が消えていない（同）
- D0057-AC-06 CLAUDE.md を見る既存のテストが通ったまま（`python -m pytest -q`）
- D0057-AC-07 7つの SKILL.md に、「質問欄」と「CLAUDE.md」を含む行がある（`tests/test_ask_question.py`。スキルごとの `parametrize`）
- D0057-AC-08 その行は100字以下の1行で、決まりの本文（1〜4・2〜4・その他・番号つき）を写していない（同。判定の関数 `ask_line_problems` を見本でも確かめる）
- D0057-AC-09 `pipe_in/`・`plugin/` に差分が出ていない（検証の段で `git diff --stat` を見る）
- D0057-AC-10（手で）新しい会話で `/pipe-in` の段の確認まで進め、確認が質問欄で出る。質問欄が使えない会話では、会話の文で番号つきの選択肢と推しが出る

## 決めたことと理由

### 人が決めたこと（要件定義・設計・テスト先行で聞いた点）

- **置き場所は CLAUDE.md の「必ず守ること」の1項目。** 公開する決まりにする（手元だけの `CLAUDE.local.md` にはしない）。
- **7つのスキルにも、指す1行を足す。** 本文は CLAUDE.md の1か所だけに置き、スキルからは指すだけにする。写すと、直すときに食い違うため。
- **質問欄が使えない会話では、会話の文で聞いてよい。** 番号つきの選択肢と推しを添える。聞かずに止めると、ツールが無い会話で何も進まないため。
- **`--auto` でも、止まって聞く所は質問欄で聞く。** 例外を作らない。
- **pipe-in の SKILL.md は、新しい1行を足す。** 設計では「段の進め方」の1行目（183字）の文末を直す形だったが、テスト先行で、AC-08 の100字の上限と食い違うことが分かった。ほかの6つと同じ短い1行を、その行のすぐ下に足す形に直した。

### 聞かずに決めたこと

- **pipe-in の SKILL.md の「必ず守ること」の節には足さない。** この節には本文800字・先頭から節の終わりまで1,600字の上限がある（D0039-AC-03）。節の外の「段の進め方」に足した。SKILL.md と補助ファイルの合計（上限18,300字。D0051）にも収まる。
- **`plugin/skills/` には足さない。** 利用者のプロジェクトで動くプラグインで、この開発の決まりではないため。
- **実装の段はメインが書いた。** 変えるのは CLAUDE.md と `.claude/skills/` だけで、どちらも `pipe-in-coder` には書けない場所のため。

### 受け入れたリスク

- 決まりは文で書いただけで、守られているかは Claude の振る舞いに任せる。フックで止める仕組みは作っていない。質問欄を使わずに聞いたかを、機械で見分けられないため。

## 対象外・残った課題

- `pipe_in/` 本体の段の確認（端末の入力・`--pause`/`--review`）。
- `plugin/skills/` のスキル（利用者のプロジェクト用）。
- 段のサブエージェント（人に質問できない。決めきれない点は成果物に書いて返す。今までどおり）。
- 助言 V-02（サブエージェントが対象外な理由を「AskUserQuestion がサブエージェントから外される道具だから」と書く）は直さなかった。審査で、バックグラウンドのサブエージェントについての裏付けが一部弱いとされたため。
- 助言 V-04（`context: fork` のスキルは CLAUDE.md を読まないので、指す1行だけでは決まりが届かない）は直さなかった。今の7つのスキルはどれもフォークしないため。フォークするスキルを作るときは、本文に要点を1文で書く。

## 監査と助言

- 監査：1件。A-01（`.claude/skills/pipe-in/artifact.md` の「ほかは会話で聞く」が決まりと食い違う）を、人の承認で「ほかは質問欄で聞く」に直した。
- 助言：4件（どれも低）。V-01・V-03（「使えない会話」が対話の Claude Code の外で起こることを示す）を、人の承認で CLAUDE.md に「（`claude -p`・SDK など）」と足して直した。V-02・V-04 は上の「対象外・残った課題」。
- 審査（助言の報告の採点）：overall 0.75（threshold 0.7）、verdict pass。事実の正確さが 0.5 と低め（件数の書き違い、バックグラウンドのサブエージェントの裏付け不足）。
