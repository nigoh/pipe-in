# D0088 プラグインのフックが動かないときは、今は止めない（onFailure を付けない。#138）

## 目的

プラグインの守りは、PreToolUse のフックが `pipe-in-gen guard-hook` を起こして成り立つ。`pipe-in-gen` が PATH に無い・起動できない・0 と 2 以外の終了コードで終わる・時間切れになると、Claude Code の決まりでは「止めない失敗」になり、道具の呼び出しは通る。D0083 でフックの中の失敗は止める側に倒したが、フックそのものが動かないときは、まだ通る。

公式の文書には、フックの失敗を止める側にする設定（`onFailure: "block"`）がある。これをプラグインのフックに付けるかを、調べて決める。D0022 が「ここでは入れない」とし、D0077 と D0083 が「別に決める」としていた点を、この記録で決める。

## 決めたことと理由

### 公式の文書で確かめたこと

出典は https://code.claude.com/docs/en/hooks （「Block the action when a hook fails」の節と項目の表）と、https://code.claude.com/docs/en/plugins/components （「Hooks」「Agents」の節）。引用は、取り込みのときに要約を通っているので、原文そのままとは限らない。

- 設定の名前は `onFailure`。command フックと http フックの1件ごとに書く。値は `"continue"` か `"block"`。Claude Code v2.1.295 以降が要る（"Whether the action that triggered the hook goes ahead when the hook fails: `"continue"` or `"block"`. … Requires Claude Code v2.1.295 or later"）。
- 付けなければ、失敗しても道具の呼び出しは通る（"On most events, when a hook fails or times out, Claude Code still carries out the action."）。
- 失敗に数えるのは、起動できない・0 と 2 以外の終了コード・時間切れ・読めない出力。`"block"` を付けると、PreToolUse ではどれも道具の呼び出しが止まる（"With `"block"` set, a failure does what exit code 2 does on that event … a `PreToolUse` failure blocks the tool call"）。
- プラグインの `hooks/hooks.json` は、設定のファイルの `hooks` と同じ形（"in the same shape as the `hooks` object in `settings.json`"）。だから、プラグインのフックにも書ける。
- プラグインのフックは、プラグインを有効にした会話で、ずっと働く。絞れるのは `matcher`（道具の名前）と `if`（道具の名前と引数の型）で、エージェントの種類では絞れない。プラグインのエージェントの前置きに書いたフックは、無視される。

### 選んだ形

**今は、`plugin/hooks/hooks.json` に `onFailure` を付けない。** 形は今のままにして、テストで固定する。付けるように変えるときは、このテストとこの記録を一緒に直す。

理由：

1. 失敗のときの動きは、「全部止める」（付ける）か「全部通す」（付けない）の二択。このフックは、絞る相手（`pipe-builder`・`pipe-judge`・会話の中の段）を、入力の `agent_type` で見分けるので、`matcher` は `"*"` でないと役に立たない。付けると、`pipe-in-gen` を入れていない人・PATH が通っていない人は、プラグインを有効にしただけで、メインの会話の Read や Bash まで、全部の道具が止まる。
2. v2.1.295 より前の版が、知らない項目 `onFailure` をどう扱うかが、公式の文書に無い。
3. 守りがいちばん要る場面（会話の中でパイプを流す `/pipe-in:pipe-run`）は、流す前に `pipe-probe` で守りが効いているかを確かめ、通らなければ流さない（D0077）。

### 選ばなかった形

- **そのまま付ける**：上の1のとおり。プラグインを入れた人の会話を、守りと関係の無い所まで止めてしまう。
- **`matcher` を絞って付ける**（Write・Edit・Bash だけ、など）：メインの会話の同じ道具も止まるので、二択の問題は残る。絞った分、絞る相手のほかの道具（MCP・Skill など）は、フックが動かないときに通る。
- **起動用のスクリプトを同梱して付ける**（`${CLAUDE_PLUGIN_ROOT}` の下の薄いスクリプトが、`pipe-in-gen` が無ければ「メインは通し、絞る相手だけ止める」と答える）：二択を越えられる見込みがある。ただし、スクリプトを動かす実行役（Python か Node）が要り、起動のしかたが OS で違い、フックの速さ（#27）にも響く。この件の大きさを越えるので、別の issue にする。

### 付けられる条件

次のどれかが満たされたら、付けることを考え直す。

- フックを、エージェントの種類で絞れる仕組みができる（プラグインのエージェントごとのフックが使えるようになる、など）。
- `pipe-in-gen` が無くても答えを返せる、起動用のスクリプトをプラグインに同梱できる（上の3つ目の形）。
- 守りの実行役そのものを、プラグインに同梱できる（「Python を手で入れずに動かす形」＝#24 が決まる）。

### 開発用のフック

pipe-in 自身の開発用のフック（`.claude/settings.json`）にも、`onFailure` は付けていない（D0032。`python` が無い環境で、メインを含む全部の道具が止まり、フックを直すこともできなくなるため）。この件では変えていない。

無人の実行で進めた。付けない、という結論は推しの案で決めた（人の確認は朝）。
