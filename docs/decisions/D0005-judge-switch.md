# D0005 作業台の判定をスイッチで入り切りし、自分をやり直す判定はケーブルを描かずに札で示す

## 目的

パイプ作業台で段を組む人が、段の「判定」を右のパネルのスイッチ1つでオン・オフでき、オンのときだけ判定のしかたと不合格のときの行き先を選べるようにする。これまで段の下に出ていた、意味のわからない差し口（自分へ戻すケーブルのコンセントとプラグ）をなくす。

## 機能要件と受け入れ基準

- FR-01 自分をやり直す判定は、図に差し戻しのケーブル・コンセント・プラグを描かない
  - D0005-AC-01 判定オンで onFail が無い段は、差し戻しのケーブルが返らない（`vscode/src/domain/pipeWires.test.ts`）
  - D0005-AC-02 onFail が自分の段も返らない（同）
  - D0005-AC-05 前の版の `pipe.toml`（判定オン・`on_fail` なし）を読んでも返らない（同）
- FR-02 前の段へ戻す判定は、今と同じく赤い点線のケーブルを描く
  - D0005-AC-03 B から A への差し戻しが1本返る（同）
  - D0005-AC-06（画面）自分をやり直す段の下に差し口・点線が出ず、前の段へ戻す段には点線が出る
- FR-03 カードの札で不合格の行き先を示す（自分は「判定 ↻」、前の段は「判定 ↩」、説明に行き先と上限の回数）
  - D0005-AC-07・D0005-AC-08・D0005-AC-09（`vscode/src/view/checkHtml.test.ts`）
- FR-04〜FR-07 右のパネルに「判定」の箱を置き、いちばん上のスイッチで入り切りする。オンのときだけ判定のしかた・確認用のコマンド・不合格のとき・戻す上限を出す。オンにすると Claude が判定する・この段をやり直すで始める
  - D0005-AC-10・D0005-AC-11・D0005-AC-12（`checkHtml.test.ts`）、D0005-AC-13（`pipeCheck.test.ts`・`checkHtml.test.ts`）、D0005-AC-14・D0005-AC-15（`vscode/src/domain/pipeCheck.test.ts`）
  - D0005-AC-16（画面）スイッチで欄と札が出たり消えたりする。明るい・暗い、幅 800px
- FR-08 前の段へ戻すケーブルを抜いても判定は残し、この段をやり直すにする（判定を切るのはスイッチだけ）
  - D0005-AC-04（`vscode/src/domain/pipeLinks.test.ts`・`vscode/src/domain/pipeEdit.test.ts`）
- FR-09 保存の形と本体は変えない
  - D0005-AC-17 `[stages.check]` の書き出しが前の版と同じ（`vscode/src/domain/pipeModel.test.ts`）
  - D0005-AC-18 作業台のテストが通る（変えたテストは下に挙げる）

## 決めたことと理由

- **自分をやり直す判定はケーブルにせず、カードの札で示す。** 自分へ戻すケーブルは差し替える先が無く、抜き差しする意味が無い。描かなければ「差し口が2つ」が根から消える。U 字を残して名前を付ける形・今の描き方に名前だけ足す形は、段ごとに飾りが増えるので選ばなかった（人の答え Q1）。
- **スイッチの下に、判定のしかたと不合格の行き先と上限をまとめる。** 今ある設定の並べ替えで済み、保存の形も本体も変えずに済む。合格の行き先も選べるようにする形は、本体の判定の動きを変えるので選ばなかった（Q2）。
- **ケーブルを抜いても判定は残す。** 判定を切るのをスイッチだけにすると、ケーブルを抜いただけでコマンドなどの判定の設定が消える驚きが無くなる（Q3）。
- **判断は純粋な関数に出した。** 判定のスイッチと不合格の行き先は `vscode/src/domain/pipeCheck.ts`、札と判定の箱の HTML は `vscode/src/view/checkHtml.ts`。画面のスクリプトは呼ぶだけにして、テストで確かめられるようにした。
- **`pipeWires.ts` の変更は差し戻しの辺を作る1行だけにした。** 別のブランチ（`feat/cable-physics`、ケーブルの線の形）が同じファイルの描画まわりを変えているため。使われなくなった `Wire.self` と `routeReturn` の自分へ戻す枝は残してある。あとから main に入るほうが rebase で片づける。
- **「不合格のとき」の選択肢に、並列の枠の中の前の段も入れた。** 画面の確認で、枠の中の段へ戻す段（見本の「突き合わせ → フロー図」）の欄が「この段をやり直す」と出ることが見つかった（前の作りから同じ）。そのまま触って保存すると戻す先が消える。ケーブルの差し直しでは枠の中の段へ戻せるので、選択肢もそれに合わせた。
- 変えた既存のテスト：`pipeLinks.test.ts` の AC-55（差し戻しを抜くと判定も切れる → 判定は残る）。`pipeEdit.test.ts` には、つなぎをすべて外しても判定が残ることを2件足した。

## 対象外・残った課題

- 合格のときの行き先を選ぶこと。実行を見る画面の判定の描き方。
- `Wire.self` と `routeReturn` の自分へ戻す枝の片づけ（`feat/cable-physics` が入ったあと）。
- 札の記号（↻・↩）が読みにくいという声があれば、文字に替える。
- 前からある `vscode/src/infra/fsVersions.test.ts` の AC-70 の失敗（版の一覧の並び）と型の誤り。この機能では触っていない。
- この機能を作っていたときは、`/pipe-in` の段のサブエージェントが worktree の中に書けなかった（`.claude/hooks/pipe_in_guard.py` が、書ける場所を元のフォルダから見て決めていたため）。そのため、人の承認を得て、テスト先行から検証までをメインエージェントが進めた。フックは D0004 で直った。

## 確かめたこと

- テスト先行で、足したテストが期待した理由（差し戻しが返る・判定が切れる・中身の無い関数）で落ちることを、失敗の文まで読んで確かめた。画面の確認で見つけた選択肢の不具合も、先にテストで落ちることを確かめてから直した。
- `npm test`：293 件中 292 件が通る（落ちるのは前からある AC-70 だけ）。`npm run build` は通る。`npm run typecheck` は、前からある `fsVersions.test.ts` の1件だけ。
- 画面（Playwright。暗い・明るい・幅 800px）：自分をやり直す段の下に差し口と点線が出ず、札が「判定 ↻」になる。スイッチのオフで欄と札が消え、オンで戻る。不合格のときを前の段にすると「判定 ↩」と点線が出る。そのケーブルを抜くと、判定はオンのまま札が ↻ に戻る。欄ははみ出さず、コンソールのエラーは0件。
- 実機の VSCode では、まだ確かめていない。
