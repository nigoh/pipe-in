# D0059 進み具合のページの上に、更新の時刻・確認待ちの札・合計・進みの帯を出し、語・回数・確認待ちの色を設計の板（S3）に合わせる

## 目的

`/pipe-in --artifact` と `/pipe-in:pipe-live` で見る進み具合のページ（`pipe_in/engine/live_page.py`）の上のほうで、いつの写しか・全体でどれだけ使ったか・どこまで進んだか・何を待っているかが一目で分かるようにする。設計の板 S3（`docs/design/canvas/LiveProgress.dc.html`）と、デザインの決まり「待ちは人の判断だけ」（`docs/design/README.md`）に、語と回数の出し方と確認待ちの色をそろえる。写しの形（`pipe_in/engine/live.py`）は変えない。

## 機能要件と受け入れ基準

### 機能要件

- FR-01 写しの `generated_at` を読み、ページの上に「HH:MM 更新」を出す（見ている人のブラウザの時刻帯・24時間・2桁）。
- FR-02 段の費用・ターン・時間の合計を「合計 <費用> ・ <ターン> ・ <時間>」で出す。書き方は段の行と同じ。時間は写しの段の `duration_sec` の和だけ。
- FR-03 段の数を分母に、完了と確認待ちの割合を高さ 8px の帯で出す（間に 2px のすき間）。動いている段は帯に入れない。
- FR-04 最後の結果が無く確認待ちの段があるとき、「確認待ち：<段の表示名>」の札を出す。無いときは札を出さない。
- FR-05 まだ始まっていない段（`waiting`）の語を「待ち」から「まだ」にする。
- FR-06 段の回数は 2 以上のときだけ「N回目」を出す。
- FR-07 これまでの守り（外から読み込まない・写しの文字は `textContent` だけ・`build_page()` は引数なしで同じ HTML・写しの形を変えない・D0044 の答えのボタン）を保つ。
- FR-08 確認待ちの色のトークン `--review` の値を、明るい画面 `#c2471f`・暗い画面 `#ff8a65`（コーラル）に替える。名前は変えず、新しいトークンを足さない。

## 決めたことと理由

- 新しい部品は `_BODY` に置かず、JS が初めて描くときに id なしで1回だけ作る。D0044-AC-43 の「`_BODY` の id がちょうど4つ」「色のトークンは既存のものだけ」の2つのテストを直さずに済み、守りの検査を弱めないため。
- 帯の幅だけは CSSOM の `style.width` で入れる。写しの文字ではなく段の数から計算した割合なので、「値は `textContent` だけで出す」の決まりの例外にした（`live_page.py` の冒頭の説明に書いた）。
- 合計の時間は写しの段の `duration_sec` の和だけにした。写しに実行の開始時刻が無く、いま数えている経過を足すと行の数字の和と合わなくなるため（人の答え）。`/pipe-in` の記録では費用とターンが 0 なので、合計はふつう時間だけになる。
- 札は写しの `review` ではなく段の `status` で決める。`review` の無い古い記録や `pipe-in live watch` の写しでも出るようにするため。確認待ちが無いときは、実行中・結果の札も作らない（人の答え）。
- 確認待ちの色は、新しいトークン（`--coral`）を足さず `--review` の値をコーラルに替えた（人の答え）。ページの中で確認待ちの色が1つにそろう。受け入れたリスク：失敗の赤（`--ng`）と色味が近くなる。見分けは行の言葉（「確認待ち」「失敗」）に任せる。
- 帯はデザインの決まり（`docs/design/README.md`：模様でも分け、下に名前と数を出す）から外し、色だけで塗って `aria-hidden` にした。同じことは段の行の言葉と札で伝わり、色だけに頼らない決まりはそこで守るため（監査 A-01）。
- 「1回目」はページの側で出さないことにした。写しの `attempt` が 1 なのは、スキルが実装と検証を `--attempt 1` から始めるためで、写しの約束（1〜999）どおりなので、写しは変えない。
- D0027-AC-86 で「待ち」としていた、まだ始まっていない段の語を「まだ」に替えた（D0027 の記録は書き換えない。監査 A-03）。あわせて、承認済みのテストのうち、次の4つを仕様の変更に合わせて直した。`CSS_DRAWN` の語、D0027-AC-59 の語の一覧、見本の数の式（`+ 4` → `+ 6`。見本 `answer-progress-*` を足したため）、説明文の「待ち」（監査 A-04 で残りの説明文もそろえた）。
- 札の角の丸みは、デザインの決まり（札 6）に合わせて 6px にした（監査 A-02）。
- 札の手のアイコンは付けない。SVG を作ると名前空間の URL の文字が入り、URL の文字を置かない決まり（D0027-AC-47）に触れるため。
- AC-33 の「完了と確認待ちを塗り分けた帯」と AC-42 の差し戻しの色は、今の見本（要件定義が確認待ちで完了の段が無い）ではなく、新しい見本 `answer-progress-*` で確かめる。AC の文は変えずに、この読み方にした。
- 番号：作業のあいだに main へ D0056（/pipe-talk）・D0057・D0058（PR と issue のテンプレート）が入ったので、この記録とテストの AC の ID を D0056 から D0059 に付け替えた。
- 監査と助言：監査の9件のうち、このブランチに関わる8件を直した・書いた（A-01〜07・A-09）。A-05（`screen-check.md` に進み具合のページの見本の手順が無い）は、`docs/assets/README.md` に見本 `answer-*`・`answer-progress-*` の作り方と見るものを書き、`screen-check.md` はもとからその一覧を指しているので、`screen-check.md` 自体は変えなかった（文書係の案は手順を1項目足す形だったが、スキルの字数の上限 D0039-AC-11 がちょうど使い切られていて入らない）。A-06 は `tests/live_page_preview.py` のコメントが追跡しない作業の記録を指していたのを、この記録と D0044 に向けた。A-07 は上の `style.width` の説明。助言と審査は、変えたファイルに `.claude/` の定義・`plugin/`・`runner.py`・`guard.py` が無かったので流さなかった。

## 対象外・残った課題

- 写しの形を変えること。要件定義・設計の差し戻しの回数（板の「要件定義 2回目」）、差し戻しの理由、成果物のパスの案内は、写しに無い・入れない決まり（`docs/guide/records.md`）なので出さない。合計の時間を「開始からの経過」にすることもしない。
- 段の行の見た目（カードの枠・Lucide のアイコン・区切りの点）、見出しの文字、更新が止まっているときの知らせは、板に合わせていない。
- 土台の色の表（`docs/design/README.md`）に合わせたのは `--review` だけで、地・完了などほかのトークンは前の値（GitHub 風の色）のまま。あとで合わせる（監査 A-09）。
- 記号の検査 `test_d0027_ac55_status_symbols_are_in_the_script`・`…_distinct_per_status` に、前から AC-55（ページの大きさの AC）の番号が付いている。このブランチの変更と関係が無いので直していない（監査 A-08）。
- VSCode の拡張・プラグイン・スキルは変えていない。すでに公開した進み具合のページは、公開し直すまで前の見た目のまま。
- `python -m pipe_in skill worktree sync` が、Windows の端末の文字コード（cp932）で git の出力を読めずに落ちる。この機能では git で直接載せ直した。別の `fix/` で直す。
