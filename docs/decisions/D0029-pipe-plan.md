## 決めたことと理由

- **項目はアーティファクトのデータに置き、ページには書かない。** ボードの上で状態やメモを変えられ、Claude も `sync` で読み書きできる。ページを公開し直しても項目は残る。
- **ボードの URL はリポジトリに書かず、題で探す。** URL は持ち主ごとの手元の事情で、公開するリポジトリには載せない。見つからなければひな形から作り直せる。
- **GitHub のイシューを正としない。手での確認の「まだ」も並べる。** 閉じたイシューでも、決定の記録の「確かめたこと」に「まだ」が残るものは「手で確かめる」に置く。作ったが確かめていないものが見えるようにするため。
- **`sync` は案を見せてから書く。** 人がボードで変えた優先・メモを黙って書き換えない。
- **セッションは、見る人のコネクタで、読むだけにする。** ページが宣言する道具は `list_sessions` 1つだけ。ページから作業を始めたり止めたりはしない（間違って押したときの害が大きく、会話で頼めば足りる）。許しは押したときに初めて聞き、ページを開いただけでは聞かない。
- **セッションと項目のつながりは、項目の `session` に ID を持つだけ。** 状態は持たず、開くたびにセッションの一覧から引く（古い状態が残らない）。
- **リポジトリの側のファイル（`docs/roadmap.md`・イシュー）を書き換えない。** ボードは見える化の道具で、決めごとの置き場所は今のまま。
- 開発の段（`/pipe-in` の5段）は通さず、テストを先に書いてから作った。Python・拡張のコードは変えていない。

## 対象外・残った課題

- GitHub との自動の同期（イシューが変わったらボードが変わる）。今は `/pipe-plan sync` を呼んだときだけ合わせる。
- ボードからイシューを作る・閉じること。
- Artifact と ArtifactData のツールが無い会話（手元の CLI など）では使えない。
