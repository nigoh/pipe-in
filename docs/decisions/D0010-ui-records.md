# D0010 作業台と実行パネルの初めの形と、読み取れる理由（あとから書く記録）

## 目的

作業台（パイプの編集）と実行パネル（「pipe-in: 実行を見る」）には、初めの形を決めた決定の記録が無い。段階1〜3（`docs/roadmap.md`）で大きく変える前に、今の形と、コードと文書から読み取れる理由をここに残し、あとから読む人が「なぜこうなっているか」を追えるようにする。

あとから書く記録なので、書くのは今のコードと文書から読み取れる事実だけにする。理由が読み取れないものは「理由は記録に残っていない」と書き、推測の理由は足さない。部分の記録は重ねて書かず、リンクで指す：作業台の判定のスイッチは [D0005](D0005-judge-switch.md)、ケーブルの動きは [D0007](D0007-cable-physics.md)、README の画面と確認用のページは [D0009](D0009-readme-screens.md)、製品の名前を変えたことは [D0006](D0006-rename-pipe-in.md)。この記録は、文書だけの変更で、拡張・本体のコードの振る舞いは変えない。

## 決めたことと理由

事実はどれも、今のコードと文書から読み取れるものだけ。各項目は「今の形」「読み取れる理由」「理由は記録に残っていない」の順に書く。

### 実行パネル：読むファイル（FR-01）

- 今の形：実行パネルが読むのは、実行のフォルダの `state.json`、`logs/` の中で段のログの名前として読める `*.jsonl`（`parseStageLogName` が読める名前だけ）、成果物（`state.json` の `stages` の `output` から作った一覧にあるものだけ）。読めないファイルは「無い」として扱い、例外を投げない（`vscode/src/infra/fsWorkDirSource.ts`・`vscode/src/domain/artifacts.ts`）。
- 読み取れる理由：work_dir の `state.json`・`logs/*.jsonl`・成果物を読むだけで描く形にした。本体（当時の名前は devpipe）には手を入れない。記録の読み取りと図の組み立ては、`vscode` に依存しない純粋な関数にした（コミット 1e109d6）。
- 読み取れる理由：段の `output` がファイル名でないもの（パスの区切りを含む・`.` で始まる）は成果物の一覧に入れない。開くのも読むのも、成果物の一覧にあるものだけにした（コミット 11bdcc5）。
### 実行パネル：見張りと再描画（FR-02）

- 監視の対象：`state.json`・`*.md`・`logs/*.jsonl`
- まとめる時間：`200ms`
- 今の形：監視は拡張で1つ（`vscode/src/extension.ts` の `retarget`）。対象は work_dir の直下と、1段下のフォルダの、上の3つ。変更・作成・削除のどれでも、200ms まとめてから（`schedule`）図の状態を作り直し（`render`）、ステータスバーと、開いていればパネルの両方に配る。パネルが `ready` を送ると描く。work_dir の設定を変えたとき、フォルダを開き直したときは、監視を張り直し、選んだ実行を忘れる。
- 理由は記録に残っていない：待ち時間を 200ms にした根拠、監視を1つにして候補全体（直下と1段下）を見る形にした理由。

### 実行パネル：見る実行の選び方（FR-03）

- 今の形：候補は、work_dir の直下（開発フロー。`state.json` があるとき）と、`state.json` を持つ直下のフォルダ（パイプ）。フォルダ名がパイプの名前の規則に合わないもの・`logs` は候補にしない。既定は `updated_at` がいちばん新しいもの（同じなら直下）。パネルで選べ、選べるのは候補にある id だけ。パネルを閉じると選びを忘れ、既定の最新に戻る（`vscode/src/domain/runs.ts`・`vscode/src/extension.ts` の `selectedRun`）。
- 読み取れる理由：パネルから来た実行の id は、見つけた候補にあるときだけ受け付ける。候補の外のフォルダは読まない（コミット 11bdcc5。`vscode/src/extension.ts` の `selectRun` のコメントも同じ）。
- 読み取れる経緯：直下と、`state.json` を持つ直下のフォルダを候補にし、既定は最新に更新された実行、2つ以上あればパネルの上のボタンで切り替え、パネルを閉じたら既定に戻る、という形はコミット 11bdcc5 で入った。
- 理由は記録に残っていない：選びをパネルを閉じたときに忘れる形にした理由。

### 実行パネル：節の状態（FR-04）

- 節の状態：`まだ`・`動いている`・`完了`・`失敗`・`省略`
- 今の形：状態は上の5つ（`vscode/src/domain/pipelineView.ts` の `NODE_STATUS_LABELS`）。節は、開発フローは11節、パイプは 依頼メモ → 段 →（確認）→ … → 完了。確認の記録がないまま先の段が動いていれば「省略」、差し戻しのやり直し中は前回の判定を「まだ」に戻す。古い記録（`stages` が無い）は、開発の5段だけを受け付ける（`vscode/src/domain/runRecord.ts`）。
- 理由は記録に残っていない：状態を5つにした理由、「省略」の判断の理由。

### 実行パネル：確認待ち（FR-05）

- 今の形：`state.json` の `pending_review`（段と文書）を、パネルの帯には「〈段〉の確認を待っている：〈文書〉」の形で出し、ステータスバーには「〈段〉の確認待ち」と出す（文書は説明（tooltip）に出す）。帯の優先順は、記録なし → 最終結果 → 動いている段 → 確認待ち → 「次を待っている」（`vscode/src/view/panelHtml.ts` の `renderBanner`・`vscode/src/view/statusBar.ts`）。
- 読み取れる経緯：`pending_review` があれば、「〈段〉の確認を待っている」と文書を、パネルの帯とステータスバーに出す形はコミット 11bdcc5 で入った。
- 理由は記録に残っていない：帯をこの優先順にした理由。

### 作業台：層の分け方（FR-06）

- 今の形：domain（純粋な関数）・app（口 `PipeStore`・`VersionStore` と手順）・view（HTML の文字列とメッセージの形）・infra（口の実装。触れる場所を絞る）・webview（画面の操作。ビルドで1つの `pipeEditor.js` に束ねる）・入口 `vscode/src/extension.ts`（`vscode` を import してよい唯一のファイル）。判断は domain の関数に出し、画面のスクリプトは呼ぶだけにする。層の決まりは `vscode/src/architecture.test.ts` が検査する（`docs/development/design.md` の「拡張の層」）。
- 読み取れる理由：色は `var(--vscode-*)` だけ、外部の読み込みはしない、ログから来た文字は `escapeHtml` を通す、パネルの CSP がインラインの style 属性を捨てるので位置や大きさは描いたあとに入れる、の各決まりは design.md に書いてある。
- 読み取れる理由：`vscode` を import するのは `vscode/src/extension.ts` だけにした（コミット 11bdcc5）。記録の読み取りと図の組み立てを `vscode` に依存しない純粋な関数にした（コミット 1e109d6）。パネルの CSP が style 属性を捨てて崩れていたので、位置と大きさは CSSOM で入れる。確認用ページ（`npm run preview`）も同じ CSP で作る（コミット 01677f2）。
- 理由は記録に残っていない：domain・app・view・infra という切り方そのものを選んだ理由、ほかの切り方との比べ。

### 作業台：書ける場所（FR-08）

- 固定ファイル：`pipe.toml`・`layout.json`・`README.md`
- 指示文：`prompts/*.md`
- 版のファイル名：`<13桁>[-draft].json`
- 今の形：`vscode/src/infra/fsPipes.ts` が書けるのは、パイプの置き場所の中の `pipe-in-<名前>/`（前の版の `devpipe-<名前>/` も）にある、上の固定ファイルと指示文だけ。`vscode/src/infra/fsVersions.ts` が書けるのは、拡張の保存場所の `pipe-versions/pipe-in-<名前>/` にある、上の版のファイル名だけ（前の版のフォルダ名は受け付けない）。外は読まず、書かない。保存先は拡張が開いたパイプから決め、パネルから来た値では決めない。
- 読み取れる理由：保存先は拡張の側で持ち、パネルから来た値では決めない、とコメントにある（`vscode/src/extension.ts` の保存先を決める箇所）。指示文を開くときは読むだけの表示にするのは、書き換えても作業台の保存で上書きされるため（同じファイルの `openPrompt` の箇所のコメント）。拡張の保存場所で前の版のフォルダ名を受け付けないのは、保存場所は前の版から引き継がないため（`vscode/src/infra/fsVersions.ts` の先頭のコメント）。
- 読み取れる経緯：作業台（当時の名前は作図台）はコミット 01677f2 で足された。同じコミットで、プラグインの pipe-builder の書き込みもパイプのフォルダだけに絞られた。コミット 9f1907c で「パイプ作図台」は「パイプ作業台」に改名され（当時のコマンド ID は `devpipe.editPipe` のまま。今は `pipe-in.editPipe` で、前の ID は D0006 で読み替えて登録だけしている）、版は拡張の保存場所にだけ書くことになった。
- 理由は記録に残っていない：書ける固定ファイルをこの3つに絞った理由。

### 作業台：版の残し方（FR-09）

- 残す版の数：`50`
- 今の形：保存のたびに、保存した版を1つ残す。パイプごとに新しい方から、上の数まで。保存せずにパネルを閉じたときは、下書き（`-draft`）として残し、通知の「開き直す」で続きから開ける。版を残せなくても、保存そのものは済ませる。プロジェクトには書かず、拡張の保存場所の `pipe-versions/` にだけ書く（`vscode/src/domain/pipeVersions.ts` の `VERSION_LIMIT`・`vscode/src/app/pipeVersions.ts`・`vscode/src/extension.ts`）。
- 読み取れる理由：下書きを残すのは、VSCode がパネルを閉じるのを止められないため（`vscode/src/extension.ts` のコメント）。保存していない変更はタブ名に ● を付け、閉じたときは下書きを残して開き直せるようにした（コミット 9f1907c）。版をプロジェクトに書かず、拡張の保存場所にだけ書くことは、`vscode/src/infra/fsVersions.ts` の先頭のコメントと design.md にある。そう決めた理由は書かれていない。
- 理由は記録に残っていない：版の上限を 50 にした根拠。
