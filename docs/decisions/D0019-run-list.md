# D0019 実行の一覧と Web アプリの形の実行パネル（並列・別の worktree・前の実行・セッション名・時系列）

## 目的

パイプを並列で流す開発者が、実行パネルで、いまの作業フォルダの並列の実行・同じ git リポジトリの別の worktree の実行・`archive/` の前の実行を、セッション名で見渡して選べるようにする。選んだ実行の図・出力・時系列（ガントチャート）を右に出す。イシュー #15。`docs/roadmap.md` 段階1「見る」。人の希望で、検証のあとに動画とキャプチャを撮った。

## 機能要件と受け入れ基準

本体（`pipe_in/`）は記録に項目を足すだけ、拡張（`vscode/`）は読むだけ。本体のテストは `tests/`、拡張のテストは `vscode/src/` の中（ID の頭で探せる）。

#### 候補と一覧（読み取り）
- D0019-AC-01 場所の直下の `state.json`・`*/state.json`・`archive/*/state.json` が、それぞれ別の run になる。`logs`・`archive`・名前の規則に合わないフォルダ・`state.json` の無いフォルダは run にならない。
- D0019-AC-02 **消した。** 「run が 1 つだけのときは一覧が出ない」は廃止（FR-30）。一覧が常に出ることは AC-43。この ID は使わない。
- D0019-AC-03 1 行に、セッション名・パイプ名・ブランチ・状態・今の段・費用（`$0.000`）・最後に動いた日付・セッション ID の先頭 8 文字が出る。読めない項目は「—」。
- D0019-AC-04 `final` のある run は「終わった」で、結果（PASSED・TEST_FAILED・STOPPED_BY_HUMAN・STAGE_ERROR・BLOCKED）が言葉で付く。知らない結果の文字はそのまま出す。
- D0019-AC-05 `pending_review` のある run は「確認待ち」で、今の段に確認の対象の段が出る。
- D0019-AC-06 段のログに結果の行が無い run（`final` が無く確認待ちでもない）は「動いている」で、今の段にそのログの段が出る。
- D0019-AC-07 行の状態と今の段は、同じ記録から作った図の状態・ステータスバーと食い違わない。
- D0019-AC-08 `archive/` の run は「終わった」で「前の実行」の印が付く。`final` が無い古い記録も「終わった」として出る。
- D0019-AC-09 並びは確認待ち → 動いている（`idle` を含む）→ 終わった。同じ状態のなかは最後に動いた時刻の新しい順で、読めない時刻は最後。run を選んでも並びは変わらない。
- D0019-AC-10 `archive/` の run は新しい方から 10 件まで読み、超えた分は読まずに「古い実行を N 件、省いています」と出る。10 件以下なら出ない。
- D0019-AC-11 `archive/<日時>/` を選ぶと、図・出力・成果物・時系列が今の work_dir 直下の記録と同じ形で見える。

#### 確認待ちの目立たせ方
- D0019-AC-12 確認待ちの行にだけ、目立たせる印（クラス）と「確認待ち」の文字が付き、待ち時間が `data-elapsed`（基準の秒）で出る。`since` が読めない古い記録では待ち時間を出さず、印と文字だけ付く。
- D0019-AC-13 点滅の CSS は `@media (prefers-reduced-motion: no-preference)` の中だけにある。
- D0019-AC-14 動いている行・終わった行には、確認待ちの印も点滅も付かない（動いている行は経過の数え上げだけ付く）。

#### 別の worktree
- D0019-AC-15 ワークスペースの最初のフォルダが主の checkout のとき、`.git/worktrees/*/gitdir` に登録された別の worktree の work_dir の run が、同じ一覧に出る。別の worktree の行には「別の worktree」の印が付く（いまの work_dir の行には付かない）。
- D0019-AC-16 最初のフォルダが linked worktree のとき、`gitdir` をたどって主の checkout とほかの worktree の run も出る。自分自身は重ならない。
- D0019-AC-17 `.git` が無い・`worktrees/` が無い・登録が壊れている、のとき、別の worktree の run は無いものとして扱い、例外を出さない。
- D0019-AC-18 登録されたパスが実在しない・相対パス・`.git` が自分の登録を指し返していない・work_dir の設定が worktree の外を指すものは、場所にしない。
- D0019-AC-19 別の worktree が 8 個を超えるときは、更新が新しい方から 8 個だけ読み、省いた数が文字で出る。
- D0019-AC-20 別の worktree の run を選ぶと、図・出力・成果物・時系列が出る。パネルから来た id が候補に無ければ何も読まず何も起きない（`..` や外のパスを含む id を含む）。
- D0019-AC-21 拡張の `src/` に `child_process` の import が無い。

#### 選びを覚える
- D0019-AC-22 run を選ぶと場所の目印と run の目印が `workspaceState` に残り、開き直すと同じ run が選ばれている。
- D0019-AC-23 覚えた run が候補に無いとき（消えた・移った・worktree が無い・値の形が壊れている）、既定（`updated_at` が最新）になり、例外を出さない。
- D0019-AC-24 設定 `pipe-in.workDir` を変えたとき、覚えた選びは新しい work_dir の候補に当てはまらなければ使われない。
- D0019-AC-25 覚える処理は work_dir・プロジェクト・worktree のどこにも書かない（書き込みは `workspaceState` だけ）。

#### 更新と重さ
- D0019-AC-26 いまの work_dir の run の変化は、今までと同じ 200ms のまとめで描き直される（監視の対象を狭めない）。
- D0019-AC-27 別の worktree・`archive/` の run の変化が、パネルを開いたままで次の更新のときに行へ反映される。パネルが見えていないあいだは読み直さない（時計を差し替えて確かめる）。
- D0019-AC-28 描き直しは、同じ記録のとき同じ HTML になる（時計を引数で受ける）。D0016・D0017 のスクリプトのテストが通る。

#### 安全と古い形
- D0019-AC-29 一覧と詳細に出る外から来た文字（セッション名・セッション ID・パイプ名・段の表示名・受け持ち・ブランチ名・フォルダ名・結果）に `<script>` や `"` を入れても、HTML に生で出ない。`style=`・`on…=`・外部の読み込みが無く、CSP のテストが今のまま通る。
- D0019-AC-30 `state.json` の中身が壊れている・`pipe`・`updated_at`・`total_cost_usd`・`stages` が無い古い形でも、行と詳細が出て、読めない項目は「—」になる。
- D0019-AC-31 拡張のメッセージの種類は増えない（`ready`・`openArtifact`・`selectRun`）。タブ・絞り込みの操作はメッセージを送らない。`parseWebviewMessage` は形の違う値を捨てる。
- D0019-AC-32 work_dir を読む口に書き込みの呼び出しが無い（`tests/test_decision_ui.py`）。層と依存の向きの検査（`architecture.test.ts`・`tests/test_architecture.py`）が通る。
- D0019-AC-33 前の版の `archive/` の名前（`20261017-100000`・重なって `-2`）が付いた run も出る。`stages` が無い記録は、これまでどおり開発の5段で読む。

#### 記録に足す項目（本体）
- D0019-AC-43 一覧は、run が 0・1・2 つ以上のどれでも出る（0 のときは「実行がありません」）。
- D0019-AC-44 `record start --name "X"` で `state.json` の `name` が "X" になる。`--name` を付けないと、`00_input.md` の最初の行から作った名前になる（名前の取り方の規則）。
- D0019-AC-45 `pipe-in --name "X"`（開発フロー・パイプの両方）で `state.json` の `name` が "X"。付けなければ要件メモの最初の行から。`--pause` → `--review` の再開、`--from` の再開のあとも `name` が変わらない。
- D0019-AC-46 名前の取り方：見出しの印（`#`〜`######`）を取る・前の空行を飛ばす・連続する空白を1つにする・60 文字を超えれば 59 文字＋`…`・空のメモや見出しの印だけなら名前を書かない。本体（Python）と拡張（TypeScript）が同じ入力で同じ結果を返す（同じ表をテストの両側に持つ）。
- D0019-AC-47 `record start --session-id ID` で `state.json` の `session_id` が ID になる。付けなければ項目を書かない。空白だけ・改行を含む・長すぎる（100 文字超）値は断る（エラーで、記録は作らない）。
- D0019-AC-48 `record begin <段> --agent A` で `Prompt` 行と、続く `record done` の `runs[]` の要素に `agent` が入る。付けなければ書かない。
- D0019-AC-49 古い記録のまま、本体の既存のテスト（`record`・再開・まとめ・`archive/` への移し）がすべて通る。`name`・`session_id`・`agent` の無い `state.json` で再開・`record` の各コマンドが動く。`record start` が終わった記録を `archive/` へ移すと、`name`・`session_id` も一緒に移る。
- D0019-AC-50 `pipe_in/` の記録の形を足すだけで、既存の項目の意味・名前を変えない（`tests/test_architecture.py`・記録の形のテスト）。`engine/guard.py`・`generator/guard_hook.py`・`.claude/hooks/*` は狭めない。

#### 記録の読み取り（拡張）
- D0019-AC-51 `parseRunRecord` が `name`（文字）・`session_id`（文字）を読む。文字でない・空・長すぎる（`name` は 200 文字、ID は 100 文字を超える）・ID に空白や制御文字を含む値は null。
- D0019-AC-52 セッション名は、`state.json` の `name` → 無ければ `00_input.md` の最初の行（同じ規則）→ 無ければ今までの呼び名（パイプ名／「開発フロー」）の順。`00_input.md` が読めなくても例外を出さない。
- D0019-AC-53 セッション ID は、`session_id` → 無ければ `runs[]` の `seq` が最大の段の `session_id` → 無ければ「—」。パイプの記録は後者から出る。
- D0019-AC-54 `00_input.md` を読むのは、その run のフォルダ（`archive/<日時>/` を含む）の中の1つだけ。先頭の 4KB までを読み、書かない。名前が `state.json` にある run では読まない。

#### 画面の組み立て（拡張）
- D0019-AC-55 パネルの本体が、上のバー・左の一覧・右の詳細の3領域になる。上のバーにアプリ名・作業フォルダが出て、選んだ run が別の worktree のときだけ「別の worktree を表示中：ブランチ名」が出る。
- D0019-AC-56 一覧に、絞り込みの入力（ラベル付き）、状態のタブ（すべて・確認待ち・動いている・終わった。件数つき。`role="tablist"`・選択中は `aria-selected="true"`）、状態の見出しで分けた行が出る。見出しの順は確認待ち → 動いている → 終わった。
- D0019-AC-57 行は3行の中身（FR-33）で、行を押すと `selectRun` が送られる。キーボード（Tab・Enter・Space）でも押せ、選んでいる行は `aria-pressed="true"`。
- D0019-AC-58 絞り込み：セッション名・ID（全部）・ブランチ名のどれかに含まれる行だけが残る（大文字小文字を区別しない）。状態のタブと一緒に効き、残る行の無い見出しは隠れ、どれも残らなければ「該当する実行がありません」が出る。
- D0019-AC-59 状態のタブを押すと、その状態の行だけが見える。「動いている」は `idle` の行も含む。件数は絞り込みに関わらず、記録の run の数。
- D0019-AC-60 詳細の上の部分に、パンくず・見出し（セッション名と状態のバッジ）・「成果物を開く」ボタン・メタ（パイプ・ID 全部・今の段・経過・費用・最後に動いた時刻）が出る。確認待ちのバッジには待ち時間（`data-elapsed`）が付く。
- D0019-AC-61 確認待ちの run では、詳細に黄の知らせが出て、確認を待っている段の名前と文書の場所が読める。最終の結果（終わった run）・いま動いている段の文言は、詳細の見出し・バッジ・メタのどこかに残る（1版目のバナーの文言が失われない）。
- D0019-AC-62 詳細の下のタブ「図と出力」「成果物」「使用量」が `role="tablist"` で並び、選んだものだけが見える。初めは「図と出力」。「成果物を開く」ボタンは「成果物」タブを選ぶ。切り替えでメッセージは送られない。
- D0019-AC-63 「図と出力」は、左に図の枠（図・注意・理由の欄・時間の節。D0010・D0016・D0017 の要素がすべてある）、右に出力（上）と時系列（下）。出力の枠の高さは右の欄の約 3 分の 1。一覧・図の枠・出力・時系列の4つが別々のスクロール領域（`overflow: auto`）になる。
- D0019-AC-64 「成果物」タブに成果物のボタン（今までの `data-artifact`）、「使用量」タブに使用量の表がある。ない成果物のボタンは押せない。
- D0019-AC-65 描き直しをまたいで、絞り込みの文字・状態のタブ・図と出力などのタブ・理由の欄の選び・一覧と各枠のスクロール位置・入力のフォーカスが残る（`panelScript*.test.ts`）。出力の末尾追従は今までどおり。
- D0019-AC-66 動いている行（`started_at` が読めるとき）に経過の `data-elapsed` が付き、1 秒ごとに増える。終わった行は固定の文字。`started_at` が読めなければ経過を出さない。
- D0019-AC-67 狭い幅の CSS：800px 以下で1列（一覧が上）になり、一覧に最大の高さがある。「図と出力」の中も縦に積まれる。このブレークポイントは `@media (max-width: 800px)` に1つだけ書く（他の大きさの規則は設計で決める）。

#### 時系列
- D0019-AC-68 段の実行ごとに1行が `seq` の順に出る。行の名前は「段の表示名 回 · 受け持ち」。回の無い段・`agent` の無い記録では、その部分を省く。
- D0019-AC-69 エージェントの帯が、最後の `Prompt` の `at` から `at` ＋ `duration_sec` まで描かれる。動いている段は「今」まで。動いている帯に印が付く。
- D0019-AC-70 確認の待ちの帯が、段の実行の終わり（いま待っているなら `since`）から次の実行の `Prompt` の `at` まで描かれる。最後の確認は `updated_at`（いま待っているなら「今」）まで。斜線の模様の別の要素で、いま待っている帯に印が付く。確認の無い段・`--yes` の run には出ない。
- D0019-AC-71 失敗した段、または判定が不合格・実行できずの回の帯は、赤のクラスが付く。合格の回には付かない。
- D0019-AC-72 横軸は `started_at` からの時間で、目盛りの文字は `m:ss`（1 時間以上は `h:mm:ss`）。時計を引数で受ける純粋な関数で、同じ入力で同じ出力になる。ずれつき・ずれなしの時刻が混ざっても、同じ瞬間なら同じ位置になる。
- D0019-AC-73 `Prompt` の `at` が無い・壊れている段は、行は出て帯が出ず「時刻の記録なし」が付く。時刻が一つも取れなければ「時刻の記録がありません」が出る。壊れた値・未来の時刻でも例外を投げず、帯が負の幅・欄の外にならない。
- D0019-AC-74 時系列の外から来た文字（段の表示名・受け持ち）は `escapeHtml` を通り、`style=` を使わない（SVG の属性だけ）。段の実行が 200 を超えるときは省略の文字が出る。

#### 古い形・D0010・D0016・D0017 との両立
- D0019-AC-75 D0010・D0016・D0017 の既存の画面の決まりが、新しい並びでも保たれる：理由の欄が開け閉めでき、時間の節と数え上げが動き、成果物のボタンが `openArtifact` を送り、使用量の表がある。それぞれの既存のテスト（`reasonsHtml`・`timesHtml`・`panelScript*`・`usageHtml`）が、置き場所の変更に合わせた直しだけで通る（意味は変えない）。
- D0019-AC-76 D0017-AC-18「バナーに全体の経過」は、「詳細のメタに全体の経過」として満たす。ガイド（`docs/guide/vscode.md`）に新しい並びを書く。

## 決めたことと理由

### 1回目から2版目へ（人の見直し）

1回目は、一覧を図の上に横幅いっぱいに置いた。画面で見た人の判断（「横幅いっぱいに広がるのが気になる。Web アプリのセオリーに沿った、なじみのある UI/UX にしたい」）で、キャンバスのデザイン案（表・カード・見出し・細い列・Web アプリの形）を見比べて、Web アプリの形（案E）に決め、要件定義からやり直した。1回目の読み取りの部分（別の worktree・archive・場所つきの目印・選びを覚える・約5秒の読み直し・設定）はそのまま使い、見た目を作り直した。「エージェント・スキル」の表は #46 に分けた。

### 人が決めたこと

- 別の worktree は、`.git/worktrees/*/gitdir`・`commondir`・`HEAD` をファイルとして読んで見つける（`git worktree list` を子プロセスで動かすと、git が設定で別のプログラムを動かす道が開き、「読むだけ」から外れる）。絶対パス・実在・指し返し・work_dir が中に収まる（symlink も解く）を確かめて受け入れる。数は 8 個まで。
- 別の worktree と `archive/` は、パネルが見えているあいだだけ約5秒ごとに読み直す。いまの work_dir は今の監視のまま。選んだ実行が動いている・待っているあいだも読み直して時系列の帯を伸ばす。
- 設定 `pipe-in.showOtherWorktrees`（既定は出す）を足す。`archive/` は場所ごとに 10 件まで、超えた分は「省いています」と出す。
- 一覧の並びは 確認待ち → 動いている → 終わった。確認待ちの行は黄の枠と「確認待ち」の文字で目立たせ、点滅は枠だけ（文字の濃さは変えない）、`prefers-reduced-motion: no-preference` のときだけ。
- 選んだ実行は `workspaceState` に場所と目印だけ覚える（work_dir には書かない）。候補に無ければ最新の実行に戻る。
- セッション名は始めるときに付ける（`pipe-in --name`・`record start --name`）。付けなければ要件メモの最初の行（先頭の `#` を取り、60 文字まで）。名前の規則は本体と拡張が同じ表（`tests/fixtures/session_names.json`）でテストする。`--review` と `--name` の併用は断る。
- セッション ID は `record start --session-id`（`/pipe-in` のスキルは `${CLAUDE_SESSION_ID}` で今の会話の ID を渡す）。パイプの記録は最後に動いた段の SDK の会話の ID を出す（段ごとに別の会話なので、`/pipe-in` を動かす会話の ID とは別物）。受け持ちは `record begin --agent` で残す（SDK の段には書かない）。
- 時系列の時刻は本体に足さずに今の記録から描く（段の始まりは `Prompt` の `at`、待ちの終わりは次の段の始まり、最後の確認は `updated_at` で近似）。
- 「成果物を開く」は「成果物」のタブへ切り替えるだけ（メッセージを増やさない）。
- 狭い幅：1101px 以上は 3 領域、801〜1100px は 2 列（図と出力を縦に積む）、800px 以下は 1 列で一覧が上（高さ 35vh まで）。
- 図は元の大きさ（320px）で描き、枠の中でスクロールする。時系列は HTML の並びで描き、行の名前と文字は元の大きさのまま帯と目盛りだけが枠の幅に合わせて伸び縮みする（横スクロールなし）。帯は行ごとの SVG（`preserveAspectRatio="none"`）で、`<style>` を増やさない。
- 図の拡大縮小（AC-79）を足した。

### 聞かずに決めたこと

- 日本語入力の変換中は描き直しを待つ（変換が壊れないように）。
- 今より 60 秒を超えて先の時刻は読めない値として扱う。
- 1回目の画面の確認で見つけた不具合（キーボードで行を選んだあとのフォーカスが失われる、点滅で文字が薄くなる）は、テストを足してから直した。

形の互換：`state.json` に `name`・`session_id`、`runs[]` と `Prompt` 行に `agent` を足すだけ（付けなければ書かない）。古い記録は名前を要件メモから、ID と受け持ちは空で読む。`archive/` は `state.json` ごと移るので足した項目も残る。メッセージの種類（`ready`・`openArtifact`・`selectRun`）は変えず、`selectRun` の id が `<場所>|<id>` になった。CSP は変えない。依存は足していない。`guard.py`・`guard_hook.py`・`pipe_in_guard.py` は触っていない。
