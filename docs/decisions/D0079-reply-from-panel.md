# D0079 実行パネルから 承認・修正の依頼・中止 を返せる（#19・#20）

## 目的

端末で流している `pipe-in` が確認の段で人の入力を待っているとき、実行パネルのボタンから 承認・修正の依頼・中止 を返せるようにする。拡張が書くのは「返事のファイル」1つだけで、それを読んで動くのは `pipe-in` 本体だけ（ロードマップの段階3「口を出す」の2つ目）。

「拡張は work_dir を読むだけで書かない」の決まりに、例外を1つ作る機能。拡張は段を流さず、段の判断も持たない。

## 決めたことと理由

- **決まりをどこまで変えるか。** 拡張が work_dir の中に書いてよいものを、実行のフォルダ（work_dir の直下か、直下1段のパイプのフォルダ）の `reply.json` 1つだけ足す。新しく作るときだけで、上書きしない。拡張は段を流さず、返事を読んで動くのは本体だけ。段と識別子の照合も本体がする。ロードマップの段階3で、人が「パネルから答える」を求めたため。
- **対象は、端末で流している実行だけ。** 記録に `driver` が無い実行（ターミナルの `pipe-in` と、作業台の「流す」D0078）が、確認の段で人の入力を待っているあいだだけ答えられる。`--pause` で止めた実行（読む本体が居ない）・`/pipe-in` の記録（会話が質問欄で止まっていて、ファイルを見張れない。画面からの答えはアーティファクトのボタン D0044）・会話の中で流した記録・別の worktree・`archive/`・終わった実行には、ボタンを出さない。issue #20 の「`/pipe-in`（record）も返事を受け取る」は、この理由でしない。
- **返事のファイルの形。** 実行のフォルダ直下の `reply.json`（隠しファイルにしない）。JSON 1つで、鍵は `version`（`1`）・`stage`・`id`・`action`・（修正の依頼のときだけ）`feedback`。余計な鍵・型違い・16,384 バイト超・使えない文字は断る。直してほしい点は「人の言葉」というデータで、動作は `action` の鍵だけで決まる。上限と使えない文字は D0044 の `live_answer.py` に合わせた。
- **動作の言葉は `approve`・`revise`・`quit`。** 本体の `Decision.action` と `--review` と同じ。`pipe-in record review` の `approved` とは別の言葉（`record review` は `approved` のまま）。`approved` と書いた返事は、知らない動作として断る。
- **長さはコードポイントで数える。** 本体（Python）と拡張（JavaScript）で数え方が食い違わないように、拡張も UTF-16 の長さで数えない。検める順は両側とも「文字か → 使えない文字 → 前後の空白を取る → 空か → 長さ」。前後の空白の取り方の違い（`trim()` と `strip()`）は、先の「使えない文字」で断られる文字だけなので、結果は同じになる。
- **本体は読むだけ。** 返事を作る関数は拡張だけが持つ。拡張が作る文字と本体が読む結果は、共通の表（`tests/fixtures/reply_file.json`）で結ぶ。
- **印は `pending_review` と別の項目 `reply_wait`。** `pending_review` に入れると、`--review` や `live` のボタン（D0044）が動いてしまう。印は待っているあいだだけ書き、無いときは鍵ごと書かない。識別子は待ちごとの乱数（10 文字の 16 進）で、同じ秒に始まった2つの待ちでも別になる。
- **待ち方は、標準入力と返事のファイルを 0.5 秒ごとに一緒に待つ。** 先に来た有効な答えで進む。待ち始め・流し始め・再開で、残っていた返事を消す。強制終了で残った印も、流し始め・再開で外す。
- **標準入力は、錠を持たない読み方で、頼まれたときだけ読む。** 設計の初めの案（別のスレッドが `input()` を繰り返す）は、Linux・Python 3.13 で試すと、標準入力も標準出力も端末のとき、プロセスが終わらずに止まった。`sys.stdin.buffer.raw.readline()` なら、すぐに終わる。そこで、スレッドは主のスレッドに頼まれたときだけ1行読む形にした。パネルのボタンを使わないかぎり、標準入力の読み方は今までと同じで、返事で進んだ待ちのあとだけ、読みが1つ残る（そのあと打たれた最初の1行は、次の待ちの外で届けば捨て、待ちの最中に届けばその待ちの答えになる）。
- **返事を受け付けるのは、標準入力が端末のときだけ。** 標準入力がパイプ・ファイルのときは、今までの道そのまま（印を書かず、返事を読まない）。`printf '\n\n' | pipe-in …` のような今の使い方と、EOF の中止を変えないため。`cli.py` が「対話できない環境です」と知らせる区切りと同じ。
- **書きかけを消さない。** 拡張は一時ファイルを作らずに直に書く（書く口の許すものを増やさない）。本体は、解釈できない中身が同じ中身で2回続けて見えるまで、無効と決めず、消さない。
- **見ていた確認にだけ答える。** パネルから来る値は、動作と直してほしい点の文字だけ。場所は拡張が作った実行の一覧から、段と識別子は拡張が読んだ記録から決める。書く直前に記録を読み直し、最後に描いた印（段と識別子）と同じときだけ書く。
- **書く口は `vscode/src/infra/fsReplies.ts` だけ。** `fsPipes.ts`・`fsVersions.ts` と同じ考え方で、場所とファイル名を絞る。排他で新しく作り、リンクを辿らず、一時ファイルを作らない。返事のファイルについて拡張が読むのは、`lstat` で分かる「有るか」と「更新時刻」だけ。
- **段のエージェントに書かせない。** 開発フローもパイプも最後に通る `protect()` で、返事の場所をどの段の書ける範囲からも外した（大文字小文字を区別しない）。開発フローの設計の段が、`domain_dir` が work_dir を含む設定で書けた穴も、ここで塞がる。`guard.py`・`bashwrite.py`・`guard_hook.py`・`.claude/hooks/pipe_in_guard.py` は変えていない（止める範囲は増えるだけ）。待ち始めの掃除と、待ちごとの乱数の識別子が、先回りの書き込みへの守りになる。
- **`reply.json` を予約名にした。** パイプの段の `output` に使えない（本体の `RESERVED_OUTPUTS` と拡張の写し）。`output = "reply.json"` の既存のパイプは、検査で理由つきで止まる。
- **印のある実行を、一覧で「確認待ち」に数える。** 端末で人の入力を待つ実行は、知らせる価値がある。ステータスバーの件数・知らせ（`pipe-in.notifyWhenWaiting`）・「先に開く」にも入る。
- **`--pause` で止めた実行の案内を直した（D0077 の残り）。** `driver` の無い記録の確認待ちに、開発用の答え方（`record review`）が出ていた。`pipe-in --review approve`（パイプの記録なら `--pipe <名前>` 付き）の案内に直した。`pipe-dev`・`pipe-chat` の案内は変えていない。
- **選ばなかった形。** `pending_review` に印を入れる（上の理由）。`record review` のコマンドを拡張が起こす（拡張が起こしてよい子プロセスは「流す」だけ）。`/pipe-in` の記録も対象にする（上の理由）。一時ファイルと rename で書く（書く口の許すものが増える）。印のある実行を一覧で数えない。
- **テストを変えたこと（理由つき）。** 仕様が変わって期待が変わった既存のテストを、テスト先行の段で直した。(1) 帯の出し分けを作り直したので、`driver` の無い確認待ちに開発用の文を期待していたもの：`vscode/src/view/shellHtmlAnswer.test.ts` の `D0064-AC-02`・`D0064-AC-03` は、入力を `/pipe-in` の記録（`driver` あり）にして期待を残した。`vscode/src/view/chatNotice.test.ts` の「端末の記録」のテストは、期待を `pipe-in --review` に直して、この記録の AC-40 にした。(2) パネルと拡張のあいだの知らせが増えたので、種類を固定していたもの：パネルから送る種類を 3 つと固定していた `vscode/src/view/panelScriptTools.test.ts` の `D0050-AC-30`・`panelScriptArtifacts.test.ts` の `D0025-AC-63`・`shellHtmlGroup.test.ts` の `D0063-AC-12` を、`reply` を足した 4 つにした。拡張から送る種類を `render` だけと固定していた `tests/test_decision_ui.py` の `D0010-AC-03` を、`replyRefused` を足した形にした（D0010 の記録の箇条書きにも足した）。(3) 書く口が増えたので、`vscode/src/architecture.test.ts` の `D0065-AC-22` を 3 つにした。(4) 検査の二重化の見本 `tests/fixtures/check_parity/err-output-reserved` に `reply.json` の段を足した（誤りは 4 件）。承認したあと（実装の段）に直したテストは 2 つで、どちらもテストの側の誤り。共通の表の「段の名前が日本語」の行は、段の名前がテストの見出しの文字（要件定義）と同じで、今までどおりの見出しを「返事の文字が出た」と数えていたので、別の名前にした。`vscode/src/domain/runListReply.test.ts` の AC-38 の 1 件は、実行の目印に使えない `_` 入りの名前を使っていて、今の作りでも通らなかったので、目印の形を直した（検査の中身は変えていない）。スレッドを使うテスト 2 件には、読むスレッドが行を渡し終えるのを待つ間合いを足した（混んだ機械でごくまれに落ちうるため）。
- **返事のファイルを確かめるのは、印のある記録だけ。** 拡張が `reply.json` を `lstat` するのは、読んだ記録に形の合う印 `reply_wait` があるときだけにした（前の実行・別の worktree は見ない）。初めの実装は、印の無い記録でも確かめていて、「読むのは一覧にある名前だけ」を守る既存のテスト（`D0025-AC-47`・`D0025-AC-37`）が落ちた。読む範囲を、要るときだけに絞った。
- **監査で直したもの。** 監査は 7 件で、どれも文書・コメントの食い違い（古くなった言い切り）だった。ロードマップの「済み」の範囲を絞り（`/pipe-in` の記録への返事はしない）、`vscode/src/extension.ts` の先頭のコメント・D0010 の記録・`docs/guide/vscode.md`・`vscode/README.md`（英語版も）の「work_dir には書かない」に例外を書き、検める順のコメントに理由の語の違い（直してほしい点が文字でないとき、本体は `bad_type`、拡張は `need_feedback`）を書き、テストのコメントの古い句を消し、ウォークスルーと使い方に「実物の VSCode ではまだ確かめていない」を添えた。助言（公式の文書との照らし合わせ。変えた `.claude/` のスキル 2 つが対象）は 0 件で、審査は流していない（助言が 0 件のため）。
- **人の確認。** 範囲（ロードマップの段階3を順に）・commit と push と下書きの PR・止まらずに進めることは、始めに人に聞いて決めた。要件定義と設計の決めきれない点（返事のファイルの名前と版・間隔・一覧で数えること・標準入力の読み方・端末のときだけ受け付けること・守りの置き場所）は、メインが推しで決めた。人の確認は PR で。
- **受け入れたリスク。**
  - 強制終了した `pipe-in` の印が残り、ボタンが出続ける。一覧でも、次の流し始めの掃除まで「確認待ち」のまま。「送りました」のあと 30 秒の案内と、次の流し始めの掃除で受ける。
  - 本体が返事を断ると、パネルはボタンに戻る。理由は端末にだけ出る。
  - 返事が反映されるまで、待ちの間隔（0.5 秒）のぶん遅れる。
  - Windows では、拡張が返事のファイルをまだ開いていると、本体が消せないことがある。止まらず、次の繰り返しで消し直す。
  - Bash を許した段で、書ける場所が実行のフォルダを含むとき（パイプの `access = "docs"` で `docs_dir` が work_dir を含む、など）は、フォルダごとの写し（`cp -r`・`rsync`）とスクリプトの実行（`python x.py`）で、返事のファイルを書けてしまいうる。パイプのフォルダ・前の記録・`protected_paths` の守りと同じ、今の守りの限界（D0036 の残った課題）。人の確認を固い関所にしたい段には、Bash を許さない。
  - 人の確認は、悪意のあるエージェントに対する固い境界ではなく、進め方の関所である（今までと同じ）。
  - 大文字小文字だけ違う `output`（`Reply.json`）は、予約名の検査では断らない（ほかの予約名と同じ）。段の書き込みは `protect()` が止める。

## 対象外・残った課題

- `--pause` で止めた実行・`/pipe-in` の記録・会話の中で流した記録・別の worktree・`archive/`・終わった実行への返事。
- 標準入力が端末でない実行への返事（ボタンが出ない。VS Code の統合ターミナルと作業台の「流す」は端末なので出る。Windows の mintty で pseudo console を使わないときは出ない）。
- 返事の履歴・取り消し・送ったあとの変更。確認する文書をパネルの中で見せること（今までどおり「確かめる文書を開く」で開く）。
- 時系列の「確認を待った帯」は、印だけの実行では出ない（図の節・経過・一覧の行には出る）。
- 端末の行の編集は、今までどおり端末の標準の動き。待ちの文の出し先だけが、標準出力に変わった。
- 監査で見つかって、直さなかったもの：`.claude/agents/pipe-in-coder.md` の決まりの写し「拡張は work_dir を読むだけ」に、返事のファイルの例外が書かれていない（重さは低。エージェントの定義は、この機能では変えていない。人が見て直す）。
- 実機の確かめ（AC-71〜74）。確かめる点：(1) ボタンで端末の `pipe-in` が進むか（Windows と macOS か Linux）。(2) 返事で進んだあと、実行が終わって端末のプロンプトが普通に戻るか（Windows は、残った読みがあるまま終われるかを自動では確かめていない）。(3) Windows で、拡張が書いた直後のファイルを本体が消せるか。(4) 約 5 秒ごとの描き直しと日本語入力。
