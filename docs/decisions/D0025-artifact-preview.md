# D0025 実行パネルの「成果物」タブを、一覧とプレビューの形にする

## 目的

実行パネルの「成果物」タブは、以前のパネルのボタンを移しただけで、上にボタンが並び下が空いていた（押すとエディタが開く）。これを Web アプリで見慣れた「左に成果物の一覧・右に中身のプレビュー」の形にして、成果物を読むたびにエディタへ移らなくても、パネルの中で内容を確かめられるようにする。拡張は成果物を読むだけで、外から来た文字は必ず `escapeHtml` を通し、外部から何も読み込まない。イシュー #49。`docs/roadmap.md` 段階1「見る」。

## 機能要件と受け入れ基準

拡張（`vscode/`）だけを変える。本体（`pipe_in/`）・記録の形・`pipeline.toml`・`pipe.toml`・`extension.ts`・メッセージの種類・CSP・依存・設定は変えない。テストは `vscode/src/` の中（ID の頭で探せる）と `tests/test_guide.py`。AC に添えた略称は次のファイル（パスは `vscode/src/` から。`TG` だけリポジトリの直下から）。

- FR-08 Markdown を、読むだけの HTML に直して出す（自前の小さな変換 `view/markdownHtml.ts` の `renderMarkdown`）

  - D0025-AC-19 段落：続く行は 1 つの段落、空行で分かれる。`\r\n` も `\n` と同じ。`br` は作らない。空の入力は空の出力。（MD）
  - D0025-AC-20 箇条書き：`-`・`*`・`+`・`数字.` と空白が項目。空白 2 つ以上深い字下げは子（タブは空白 4 つ）で、3 段まで（4 段目以降は 3 段目に並ぶ）。空行をはさんでも同じ種類の項目なら同じ一覧。見出し・囲み・表・引用・`---` は一覧を終わらせる。段落の途中の行が 1 でない番号（`2025. …`）で始まるときは、項目にせず段落の続き（`-`・`*`・`+` と `1.` は段落を終える。CommonMark と同じ）。（MD・MF）

  - D0025-AC-22 表：ヘッダ行・区切り行（`:?-+:?`）・本文行が `table` になる。区切り行が無い `|` の行は段落の文字。ヘッダの字下げは 3 つまで。（MD）

  - D0025-AC-24 表のセル：ヘッダのセルの数に合わせ、足りない分を空のセルにする（表の安全弁の中で。下の「決めたこと」）。`\|` はセルの中の `|`。省略の一文を出したあとの別の表は丸ごと出さない。（MD・MF）

  - D0025-AC-28 区切り線：3 つ以上の同じ `-`・`*`・`_` の行は `hr`。下線の見出しは使わない。（MD）

- FR-10 Markdown でないファイルは、そのままの文字で出す
  - D0025-AC-39 拡張子が `.md` でない成果物（拡張子なしも）は、`pre` の中に `escapeHtml` を通した文字で出す。`pre` の直後に改行を 1 つ足す（HTML の決まりで捨てられる分。先頭の空行が減らない）。（AH・AF）

#### 読む（拡張）
- FR-12 読む大きさに上限を付ける。超えたら先頭だけ読み、「続きはエディタで」と出す
  - D0025-AC-42 成果物の読みは `readHead(file, 262,145)` の 1 回だけ。読んだ文字を UTF-8 にした長さが 262,144 バイトを超えたら、先頭の 262,144 バイトまでにして切れた印を付ける（`stat` の大きさでは決めない）。`readHead` は、1 回の読みが短く返っても（ネットワーク・FUSE）、いっぱいになるかファイルの終わりまで読み続ける。（FSA・RS）
  - D0025-AC-43 成果物の読みで `readFile` を呼ばない。成果物 1 つにつき `lstat` 1 回・`readHead` 1 回。読み取りの口は 6 つのまま。`readHead` の確保は 0 で埋めない（`Buffer.allocUnsafe`、使うのは読んだ分だけ）。（FSA・STX）
  - D0025-AC-44 切れ目が文字の途中でも、末尾に U+FFFD を出さず、UTF-8 で 262,144 バイト以下。ファイルの中ほどの本物の U+FFFD は変えない。（FSA）
  - D0025-AC-45 切れた成果物のプレビューの見出しの下（枠の外）に「先頭 256 KiB までを表示しています。続きはエディタで開いてください。」。上限は `domain/artifacts.ts` の 1 か所の定数（`ARTIFACT_MAX_BYTES`・`ARTIFACT_TOTAL_MAX_BYTES`）から作り、ほかのファイルに数を直書きしない。（FSA・AH・AP・STX）
  - D0025-AC-46 「あるか」は読んだ範囲で決める。（ART・FSA）
- FR-13 読んでよいのは、記録から作った一覧にある名前の、通常のファイルだけ
  - D0025-AC-47 `/`・`\`・`:` を含む名前と `.` で始まる名前は一覧に入らず、読まれない。別の worktree・`archive/<日時>` の実行も、その実行のフォルダの中だけを読む。（FSA）
  - D0025-AC-48 通常のファイルでないもの（フォルダ・symlink（リンク先が中でも外でも）・その他）は読まず、「まだない」と同じ扱い。例外は出ない。`00_input.md` の先頭 4 KiB（実行の一覧の名前づくり）と `state.json` は、今までどおり symlink を辿る。（FSA）
  - D0025-AC-49 更新時刻は、種類の確かめと同じ 1 回の `lstat` の値から読む。`lstat` が失敗したら読まない。（FSA）
  - D0025-AC-50 `fsWorkDirSource.ts` に書き込みも `child_process` も入らない。口の型は変わらない。（FSA）
  - D0025-AC-51 `createFsWorkDirSource` の options に `fs?: ReadOnlyFs` を足す（既定は本物）。呼び出し側（`extension.ts`）は変えない。（FSA）

## 決めたことと理由

### 人が決めたこと（要件定義で聞いた 5 点。どれも推しの案）

- **成果物の中身は、描き直しの HTML に、「ある」成果物すべてのプレビューを入れて渡す。** 見えるのは選んだ 1 つで、選びはパネルの中だけで持つ。メッセージの種類と CSP は増やさない。選びを拡張へ送る新しいメッセージを足す案は、HTML は軽くなるが、メッセージの種類を固定する既存のテスト（D0016・D0017・D0019・D0021）を置き換え、選びの保存先も決め直すことになる。
- **読む上限は、1 つの成果物につき 256 KiB（262,144 バイト）。** イシューの例のとおり。合計の上限は、設計で人に聞き直した（下の設計の問い 3）。
- **symlink の成果物は読まず、「まだない」と同じ扱いにする。** 中身が画面に出るようになるので、外のファイルが見えてしまう道を塞ぐ（安全側に倒す）。範囲は成果物の写しに入る読みだけで、`00_input.md` の先頭 4 KiB（実行の一覧の名前づくり）と `state.json` は今までどおり辿る（絞るのは別のイシュー）。
- **Markdown は、自前の小さな変換で HTML にする。依存は足さない。** `marked` は開発用の間接依存で、生の HTML をそのまま通すので、無害にする部品が別に要る。`view`・`domain` は外のパッケージを import できず、層の決まりも変えることになる。自前なら、許すタグを一覧で絞れて、外から来た文字の扱いをテストで示しやすい。
- **選びはパネルのスクリプトの変数だけで持つ。** 描き直しはまたぐが、パネルが作り直される・VSCode を開き直すと既定に戻る（図と出力のタブの選びと同じ）。`workspaceState` に保存する案は、拡張の書き込み先とメッセージが増える。

### 設計で人が決めたこと（5 点。どれも推しの案）

- **隠れているときも、成果物は今までどおり読む。** `extension.ts` を変えないため。重い変換と送信は、パネルが見えているときだけ（D0024 のまま）。見えていないときに読まない案は、`extension.ts` の文字を固定している検査（`extensionStale.test.ts`・`extensionCounts.test.ts`）を書き換え、ステータスバーの「記録がありません」のために `00_input.md` の有無の確かめも別に要る。読みの重さは下の「確かめたこと」で実測した。
- **表の安全弁：列は 100 まで、1 回の変換のセルは 20,000 まで。超えたら残りの行を省いて固定の一文「（表が大きいので、ここから先は省略しました。続きはエディタで開いてください。）」を出す（1 回の変換で 1 つだけ）。** 「足りない分を空のセルにする」を文字どおりやると、ヘッダが広く本文が短い表で出力が入力の何千倍にもなる。
- **1 回の読みで写しに入れる文字の合計にも上限（4 MiB）を置く。** 要件定義では「合計の上限なし」と承認していたが、パイプの段の数に上限が無く、成果物は「段の数 + 2」個になりうると設計で分かったので、聞き直した。一覧の順に読み、合計が 4 MiB に届いたら残りは読まず「まだない」と同じ見た目にする（最大でも 4 MiB + 256 KiB 未満）。`state.json` の上限と同じ大きさ。
- **symlink の成果物の見え方は「まだない」と同じで、理由は画面に出さない。** 写しに新しい状態を 1 つ足さずに済む。受け入れたリスクに書いた。
- **`.claude/skills/pipe-in/SKILL.md` の確認用ページの列挙の 1 行は、D0024 と同じく監査のあとで直す。** 直すのは名前の列挙だけで、公式の文書と照らす点が無いので、助言（と審査）は流さない。

### 実装で人が決めたこと（2 点。どれも推しの案）

実装の段の読み手の指摘で、承認された設計の決めを変えたもの。人に聞いて、どちらも残した。

- **プレビューの中身の HTML の合計にも上限（`PREVIEW_HTML_MAX_CHARS` ＝ 8 MiB 文字）を置く。** 設計は「HTML は読んだ文字から作るので、読みの上限で HTML の重さも抑えられる」として、HTML 側の上限を置かないと決めていた。ところが空行で区切った `>>>a` の繰り返しは、6 バイトが 83 文字（約 14 倍）になり、読みの合計の上限の中でも HTML が約 58 MB・変換が約 1.4 秒になった。既定の選びを先に作り、あとは一覧の順に作って、入らないものが出たらそこで止める（入らないものを次々に変換して捨てると、拡張ホストの同期処理の時間が減らないため）。入らなかったプレビューは、見出しと「エディタで開く」を残し、枠の中に「表示する量が多いので、このプレビューは省略しました。エディタで開いて読んでください。」だけを出す。読む量の上限と出す HTML の上限は役目が違うので、2 か所に分かれることは受け入れた。
- **プレビューの中身の向きを変える制御文字（U+202A〜202E・U+2066〜2069）も U+FFFD にする。** 設計は「名前だけ U+FFFD にし、中身はファイルの内容そのものなのでそのまま出す」としていた。確認のために読む文書の見かけの順を、外から来た文字で入れ替えられ、エディタと違ってプレビューは見えない文字を目立たせないので、名前と同じにした。長さは変わらない。

### 聞かずに決めたこと

- 成果物の一覧は 4 つの欄（名前・ファイル名・作った段・時刻）。時刻は実行の一覧の行と同じ `MM/DD HH:mm` で、ファイルの更新時刻を `ViewClock.localOffsetMin` で手元の時刻に直す。

### 受け入れたリスク

- **`lstat` と開くあいだの差し替えは塞がない。** 成果物は `lstat` で通常のファイルと確かめてから `readHead` で開き直すので、そのあいだに symlink へ差し替えられると辿る。作業フォルダに書ける別のプロセスが要る競合で、拡張は何も書かず、コミットされた静的な symlink は `lstat` で止まり、見えるのは使う人自身の画面だけ。閉じるには、`readHead` に省ける第 3 引数（`O_NOFOLLOW` で開く。定数の無い Windows は開いたあと `handle.stat().isFile()`）を足し、`open` の開き方を固定している検査（`tests/test_decision_ui.py` の D0019-AC-32）と AC-50 の言い方を直す。
- **UTF-8 として読めないファイル**は、読めないバイト 1 つが U+FFFD（3 バイト）に数えられ、長さが最大 3 倍にふくらむ。Shift_JIS などで保存した約 85 KiB（87,382 バイト）を超えるファイルは、上限より小さくても「切れた」印が付き、案内は「先頭 256 KiB まで」と出るが、実際に出るのはその約 3 分の 1 まで減ることがある。合わせるには口の型（文字を返す）を変える要があるので、ガイドに書いて受け入れた。
- **symlink の成果物は「まだない」と同じ見た目で、理由は出ない。** `00_input.md` が symlink のときは、図の依頼メモ（開発フローでは要件メモ）の節が「まだ」になり、`state.json` もログも無い実行では「記録がありません」にもなる（今までは辿って読めた）。
- **隠れていても読む。** 別の worktree の行があるあいだは、閉じたパネルでも約 5 秒ごとに、選んだ実行の成果物（1 つ 256 KiB まで・合計 4 MiB + 256 KiB 未満）を読む。重い変換と送信は見えているときだけ。
- **合計の上限に届くと、一覧の後ろの成果物（まとめなど）から「まだない」と同じ見た目になる。** 上限いっぱいのものが 17 個以上のときで、まれ。プレビューの HTML の上限に届いたときは、後ろのプレビューが案内だけになる（まれ）。HTML を作る側はパネルで押した行を知らない（選びはパネルの変数だけ）ので、自分で押した行のプレビューが後ろにあたるときも案内だけになる。
- **100 列を超える表は、右の列を（見出しも本文も）黙って捨てる。** 省略の一文は、セルの数か HTML の長さで行を省いたときだけ出る。ガイドと拡張の README に書いた。
- **描き直しは本体を丸ごと入れ替える。** 文字を選んでいる途中の選びと、横にスクロールした表・コードの位置は、描き直しで消える（プレビューの枠の縦横の位置は残る）。
- **パネルが隠れて作り直されると、選びは既定に戻りうる**（`retainContextWhenHidden` を持たない）。
- 更新時刻は「今」のずれで直すので、夏時間をまたぐ古い時刻は 1 時間ずれる。年は出さない。
- `.md` でない成果物の更新は見張りの対象外で、次の `state.json`・ログの変更か、約 5 秒の読み直しで反映される。
- 焦点のあったプレビューが丸ごと消えたとき（その成果物が「まだない」になったとき）は、焦点が `body` に落ちる。

形の互換：記録（`state.json`・段のログ・`99_summary.md`）・終了コード・`pipeline.toml`・`pipe.toml`・置き場所・コマンド・設定の鍵・メッセージの種類・CSP は変えない。足したのは拡張の内側の写しの成果物の項目（`{ text, mtimeMs?, cut? }`。今までの文字だけの形も読む）と、HTML の成果物のタブだけ。意味が変わるのは、symlink の成果物・先頭 256 KiB が空白だけの大きい成果物・合計 4 MiB を超えた後ろの成果物の 3 つ（どれも「まだない」と同じ見た目になる）。依存は足していない（`package.json`・`package-lock.json` は変わらない）。`extension.ts` は 1 文字も変えていない。`guard.py`・`guard_hook.py`・`pipe_in_guard.py` は触っていない。拡張の書き込み先は増えていない。拡張の守りは狭めず、symlink の成果物を読まないことで強めた。
