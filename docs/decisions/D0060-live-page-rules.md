# D0060 進み具合のページで、「N回目」を2回目から出し、更新の時刻を見ている人の時刻帯で出す

## 目的

D0059 で進み具合のページ（`pipe_in/engine/live_page.py`）にデザインの土台を入れたが、同じページに手を入れていた別の作業（閉じた PR #104）にだけあった決まりが入っていなかった。設計の板 S3（`docs/design/canvas/LiveProgress.dc.html`）に合わせて「N回目」を2回目から出し、「HH:MM 更新」を見ている人の時刻帯で出す。札の表示名が 80 文字で切れることもテストで固定する。

## 機能要件と受け入れ基準

### 機能要件

- FR-01：段の「N回目」は、回数が 2〜999 の整数のときだけ出す（1回目は出さない。変な値も出さない）。
- FR-02：頭の「HH:MM 更新」は、写しの `generated_at` を時刻として読み、見ている人のブラウザの時刻帯の時・分で出す（24 時間・2 桁）。読めない・無い値では出さない。
- FR-03：頭の札の表示名は 80 文字で切れる（今の写しの読み方 `checkSnapshot` の切り方のまま。札の側には手を入れない）。
- FR-04：D0059 のほかの決まり（色・書体・アイコン・帯・数・合計・ボタン・動き・大きさ・外部の読み込みの範囲）は変えない。

### 受け入れ基準

- D0060-AC-01：回数が 2 の段は「2回目」、999 の段は「999回目」が出る。（tests/test_live_page_js.py）
- D0060-AC-02：回数が 1・null・0・負・小数・NaN・文字・真偽・1000 以上・配列の段には「回目」の要素が出ない。（tests/test_live_page_js.py）
- D0060-AC-03：`2026-07-01T12:40:05+09:00` は、時刻帯が UTC なら「03:40 更新」、`Asia/Tokyo` なら「12:40 更新」、`America/New_York` なら「23:40 更新」。台の時刻帯の切り替えが効くことも確かめる。（tests/test_live_page_js.py）
- D0060-AC-04：時・分は 2 桁の 24 時間表記。`Z` つき・小数秒つき・マイナスのずれつき・30 分ずれの時刻帯・0 時ちょうども同じ規則で出る。（tests/test_live_page_js.py）
- D0060-AC-05：`generated_at` が無い・null・数・読めない文字・日付として無い値（2月30日など）では「更新」が出ない。（tests/test_live_page_js.py の `test_d0059_ac12_bad_or_missing_generated_at_is_not_shown`。D0059-AC-12 のテストに 2月30日の行を足して受け持たせた）
- D0060-AC-06：札の表示名は 80 文字以内ならそのまま、81 文字以上なら先頭 79 文字と「…」。絵文字の途中では切らない。段の行の表示名は変わらない。（tests/test_live_page_js.py）
- D0060-AC-07：D0059 のほかのテストが変えずに通る（直したのは、時刻をそのまま出すことを期待していた D0059 のテスト2件だけ）。（tests/test_live_page.py・tests/test_live_page_js.py ほか）
- D0060-AC-08（画面）：確認用ページ（`tests/live_page_preview.py` の `all-states`）で、1回目の段に「1回目」が出ず、2回目の段に「2回目」が出て、更新の時刻がブラウザの時刻帯で変わる。

## 決めたことと理由

- **閉じた PR #104 の決まりのうち3つだけを移す**（人が決めた）。#104 と D0059（PR #105）は同じファイルを別の形で広く書いていて、マージで合わせると重なりを外す手間が大きいので、#104 を閉じ、#104 にだけあった3つを main の上に足した。
- **帯に作業中の段を入れない #104 の形は移さない**。デザインの決まり（作業中＝点）と合わないため、D0059 の帯のままにした。
- **時刻は `new Date(ms)` の `getHours`・`getMinutes` を 2 桁にそろえて出す**。#104 と同じ形。`Intl` の時刻の書き方は、時刻帯や環境によって「24:00」が出ることがあるので使わない。
- **札の長さはコードを足さずテストで固定する**。写しを読むときに表示名を 80 文字で切っているので、札もすでに 80 文字に収まる。#104 も同じだった。
- テストでは、node の台の子プロセスにだけ `TZ` を渡す（既定は UTC）。手元の時刻帯でテストの結果が揺れないようにするため。`os.environ` は書き換えない。
- 保護の仕組み（`guard.py` など）には触らず、依存も足さない。写しの形（`live.py`）も変えない。

### 監査で直したこと

- 監査の4件のうち、人が選んだ3件を直した。D0059 の AC-12 に D0060 が置き換えたことを書き（A-01）、この記録の AC-05 にテスト名を書き添え（A-02）、落ちたテストの数の書き方を分けた（A-03）。
- 直さなかったもの：A-04（札の80文字はページが読む側の上限で、写しの表示名は40文字まで。2つの文書の数が違って見える）。
- 助言と審査は流していない（変えたファイルに `.claude/`・`plugin/`・`runner.py`・`guard.py`・`guard_hook.py` が無いため）。
