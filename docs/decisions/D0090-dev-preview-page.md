# D0090 開発用の記録の確認用ページを足し、時系列の確認待ちの言葉の重なりを直す（#139）

## 目的

- D0080 で、開発用の記録（`/pipe-in` の記録）は費用が「取れない」になった。けれども、確認用のページ（`npm run preview`）に、開発用の新しい記録のページが無かった。画面の確認は、手で記録を組んで行った。
- そのとき、時系列の最後の行で、「確認待ち 0:00 ● 待っている」の言葉が、実行の帯の上に重なって読めなかった。

確認用のページ `run-panel-dev-*` を足し、言葉の重なりを直す。

## 決めたことと理由

- **重なりの原因**：確認待ちが、段の終わりと同じ時刻に始まって「今」も同じ時刻のとき、長さ 0 の待ちの帯が右端（100%）に出る。帯の右端が 85% を超えると、言葉は帯の左に置く決まりなので、言葉は左へ伸びて、同じ行の実行の帯の上に乗る。issue の「合計が短い」は直接の原因ではなく、条件は「右端にある細い待ちの左に、言葉より広い実行の帯がある」こと。
- **置き方**：言葉を、帯の下の行に出す（その行だけ、高さを広げる）。ほかの案は選ばなかった：帯の中に出す（帯の中の時間の字と重なる）／言葉を省いて印だけにする（待ちの時間が見えなくなる）／待ちの帯の最小の幅を広げる（0 秒の待ちが太く見えて、時間を偽る）。
- **条件**：下の行に出すのは、待ちの帯の右端が 85% を超え、帯の幅が 5% 未満で、言葉の範囲（帯の左端から、言葉の長さの目安ぶん左まで）に実行の帯がかかるときだけ。ほかの入力の行の HTML は、1字も変えない（テストが固定する）。
- **既存のページにも効かせる**：設計は「既存の確認用ページに、条件に当たる待ちは無い」と見ていたが、テスト先行の段の実測で、7種のページ（実行の一覧・更新なし・成果物・エージェントとスキル・返事など）の、一覧のほかの実行（別の worktree の確認待ちの行。幅 2〜5%・右端）に在ると分かった。同じ重なりの入力なので、定数をいじって外すことはせず、そこにも新しい置き方を効かせた。そのため、既存のテストの固定のハッシュ値3つ（実行の一覧・更新なしの2種）を、新しい値に替えた（7種のうち、固定のハッシュに映るのはこの3種。ほかは、固定している範囲に当たる行が無いか、パネル全体のハッシュのテストが無い）。
- 見本の記録は、`chat` の見本と同じく、`vscode/scripts/` の中のデータから一時フォルダに書く。本体が書く形とずれないように、共通の表の開発用の行と、見本の鍵を突き合わせるテストを足した。
- 画面の確認の手順（`.claude/` の中）の一覧の行は、段の役が書けないので、メインが足した（ページを足したら1行足す、という元からの決まりで、足し忘れはテストが落とす）。
- 新しいテストの正規表現を1か所直した（ページの `<style>` の規則にも当たっていたので、言葉の要素に絞った）。
- 無人の実行で進めた。次の点は推しの案で決めた（人の確認は朝）：下の行に出す置き方／条件の定数（5%・18%・32%）／既存のページにも効かせること／ページは短い記録の1組だけにすること。
