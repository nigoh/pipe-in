# D0062 パイプの判定とやり直し（on_fail）を実行の図に出す

## 目的

パイプを流しているとき、どの段が判定に通ったか・落ちたか、何回やり直したか（上限はいくつか）を、実行パネルの図で見られるようにする。作業台で決めた判定とやり直しの設定が、実行の図でも同じ札で見える（GitHub の issue #12）。

調べると、記録に足りないものがあった。本体は判定のある段の検証のたびに `runs[]` へ `check` の要素を足すが、何回目かは書かず、段の並び（`stages[]`）にも判定の設定（`on_fail`・`max_retries`）は残らなかった。拡張は `check` の要素を読まずに捨てていた。そこで、記録に足りない 2 つを足すだけで書き、拡張が読んで図に出す。

## 機能要件と受け入れ基準

### 機能要件

- FR-01：本体は `state.json` の `stages[]` の、判定のある段に `check`（`on_fail`・`max_retries`）を足す。判定の無い段・開発フローには足さない。`on_fail` は前の段へ戻すなら段の名前、自分をやり直すなら `null`。
- FR-02：本体は `runs[]` の `check` の要素に `attempt`（その段の何回目の検証か。1 から。確認で止めて再開しても続きの番号）を足す。
- FR-03：拡張は `check` の要素を読み、段ごとの検証の結果（合否・回・要約・直す点）として `RunRecord` に持つ。読めない形の要素は捨て、例外にしない。
- FR-04：パイプの図で、判定のある段のあとに「判定」の節を出す。状態は、最新の検証が合格なら完了、不合格なら失敗、まだ・やり直し中なら待ち。
- FR-05：判定の節に、やり直した回数と上限（「2 / 3 回」）を出す。上限まで落ちて終わったときは「上限まで」と分かる言葉を出す。
- FR-06：前の段へ戻す判定は、判定の節から戻り先の段へ戻りの矢印を描く。自分をやり直す判定は矢印を描かず、作業台と同じ札を節に付ける。
- FR-07：判定の節を選ぶと、右の欄に検証ごとの結果（回・合否・要約・直す点）を出す。
- FR-08：古い記録は今までどおり描く（判定の節を出さない／出せる範囲で出す）。

## 決めたことと理由

要件定義の「決めきれない点」は、推しの案で決めた（人の確認で止まる所は親が聞く）。

1. **判定の節は段ごと `check:<段>`**。パイプの判定は段ごとに設定できるため。検証の段が 1 つに寄せる案は、段ごとの上限や戻り先が混ざるので取らない。
2. **置き場所は、その段の直後（確認の節より前）**。確認は判定に通ってから取るので、本体の流れの順に合わせた。
3. **回数は「やり直した回数 / 上限」**。実際に戻した数を出す。「検証 N 回目」だけだと上限と比べにくいため。右の欄の見出しは「検証 N 回目」で、記録の `attempt` と同じ数え方。
4. **枠（グループ）内の段も同じ扱い**。記録は書き、図は他の段と同じに出す。描き分けは別の issue に回す。
5. **残り回数（`retries_left`）は記録に持たせない**。`attempt` と `max_retries` から導けるため。
6. **再開時の番号は、記録の `runs[]` の同じ段の `check` の数から数える**（`BasePipeline` が持つ履歴は、`review` の再開で `state.json` から戻る）。
7. **記録は足すだけ**。`stages[].check`（判定のある段だけ）と `check` の要素の `attempt`。無い古い記録は、判定の節を出さない／並びの番号で読む。古い版の拡張は知らない項目を読まずに捨てる。
8. **本体の `engine` はパイプの定義を知らないまま**。`BasePipeline._stage_checks()`（既定は空）を足し、`LinearPipeline` だけが実装する。依存の向きは変わらない。
9. 札の文字は `checkChipText`（`vscode/src/domain/pipeCheck.ts`）に 1 か所だけ置き、作業台の `checkChip` と実行の図が同じ関数から取る。
10. 戻りの矢印が複数あるときは、通り道を 6px ずつ左へずらす（最小 10）。ラベルは最初の 1 本だけにする。画面の確認で重なりが出たら直す。
11. 節の高さは 2 行ぶん（46）。「上限まで」の言葉は 2 行目の右に置き、高さは変えない。
12. `guard.py`・`guard_hook.py`・`pipe_in_guard.py` は変えない（止める範囲は狭めない）。依存は足さない。`pipeline.toml`・`pipe.toml` は変えない。
13. 画面の確認用ページ `run-panel-check-self-*`・`-back-*`・`-old-*` を足した。見本の記録は `vscode/scripts/checkSamples.ts` が、共通の表を読んで一時フォルダに作る（`tests/fixtures/` には足さない）。

### 既存のテストとの食い違い

本体の `check` の要素に `attempt` が増えるので、`check` の要素の鍵の集まりをそのまま比べている既存のテスト 3 件（`tests/test_check_judge.py` の `test_ac15_*`）は、`attempt` を含めて比べる形に直す必要がある。実装の段はテストを直せないので、直しは親が行う。
