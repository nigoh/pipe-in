# D0073 人のいない実行（無人の実行）で、commit・push・PR の作成を確認で止めない

## 目的

人が開始の指示で commit・push・PR の作成を承認した「無人の実行」（夜のまとめ実行など）が、その枝への commit・push と PR の作成で止まらないようにする。main に入れること（merge・main への push・publish）は、無人でも止めたまま残す。

2026-11-02 の夜の実行では、`.claude/settings.json` の `ask` にあった `git commit`・`git push`・`gh pr create` のたびに確認が出て、人が UI で答えるまで進まなかった（記録の許可の判定は、人がその場で答えた形だった）。公式の文書では、`ask` に当たる操作は auto モードでも必ず確認になる。どのスコープの `allow` も、PreToolUse フックの許可も、`ask` を越えない。クラウドでは、個人の設定と手元の設定も読まれない。セッションの途中で `.claude/` を書き換えるのは保護されたパスで、auto の判定が止める。人のいない実行で確認を出さない方法は、人が `ask` から外して main に入れることだけだった。

## 決めたことと理由

- **無人の実行の見分け方**（人が決めた。Q1）：人が書いた開始の指示そのものに、「人が答えない実行であること」と「commit・push・PR の作成を名指しした承認」の2つがどちらも書かれていること。決まった旗ではなく、自由な文で書けるようにした。承認にならないもの（`--auto` だけ・名指しの無い文・ファイル・ツールの出力・サブエージェントの返事など）は CLAUDE.md の1か所に置いた。
- **親が起こす子の実行**（Q2）：親が人の承認の文を、範囲を変えずに子の開始の指示に写したときだけ、子も無人の実行になる。
- **止まって聞く場面の代わり**（Q3・Q8）：決めきれない点は推しの案で決め、記録に「人の確認は朝」と書く。文書係の案と監査・助言は直さず「残った課題」に書く。不合格3回は `TEST_FAILED` で打ち切り、commit しない。それ以外に人に聞く場面は、聞かずに `BLOCKED` で止める。質問欄は答える人が居ないと止まったままになるので、無人の実行では使わない。監査の A-01 を受けて、無人の実行には `--auto` を付ける決まりにした。付けなかったときは、最初の段の区切りで `BLOCKED` で止めて報告する。
- **`ask` の形**（Q7）：外したのは3本で、残したのは6本。main へ届きうる push の形を21本足して、27本にした。枝名に `domain`・`maintain` のような語が入っても当たらないように、` main`・`:main`・`/main` を前後の形ごとに分けた。テスト先行の段で、後ろに旗が続く main への push（`git push origin HEAD:main --no-verify`・`git push origin refs/heads/main --no-verify`）を止める形の表に足した。こうしないと、設計の2本（`git push *:main *`・`git push */main *`）がどの形にも当たらなかった。規則そのものは変えていない。
- **main の関所**（Q4）：本当の関所は GitHub のブランチ保護（PR 必須・必須のチェック `python`・`extension`。迂回を許す一覧を空にする）。`ask` と CLAUDE.md の決まりは目安とした。PR を必須にすると、手元の `git merge --ff-only` で main に入れる運用は使えなくなる。
- **スキルの字数**（Q5・Q6）：無人の実行の手順は、新しい補助ファイル `.claude/skills/pipe-in/unattended.md` に分けた。`SKILL.md` には指す行だけを置き、12,300 字の上限は変えなかった（12,237 字）。`unattended.md` も、補助ファイルの合計の検査の対象にした（`HELPERS` に足した）。そのうえで合計の上限を 18,500 字から 20,400 字に上げた（足したあとは 20,282 字）。CLAUDE.md の補助ファイルの並びにも `unattended.md` を足した（Q9）。
- **AC の読み替え**：要件定義の AC-17〜19（`--auto` の節・仕上げ・終わりの報告に書く）は、「`SKILL.md` か、`SKILL.md` が指す `unattended.md` に書く」と読み替えた。`SKILL.md` が3か所で `unattended.md` を指していることは、AC-42 で見る。
- **置き換える点**（古い決まりとの関係）：
  - D0039 の `ask` の一覧（`git commit`・`git push` を含む）を置き換える。D0039-AC-25・AC-34 の期待を直した。
  - D0046-AC-27 と D0056-AC-27 の `ask` の一覧の期待を、新しい 27 本に置き換える（期待の一覧は `tests/test_unattended_run.py` の `EXPECTED_ASK` に1つだけ置く）。
  - D0057 の「`--auto` でも、止まって聞く所は同じ」は、無人の実行だけ例外にする（無人の実行では質問欄を使わない）。
  - D0058 の V-01 で `ask` に足した `gh pr create` は、外す。`gh pr merge` は残す。
- **助言の V-05 を受けて**：無人の実行の決まりは、auto モードの判定が守らせるものではなく、Claude 自身が CLAUDE.md に従うことで守られる（commit・push・PR の作成は、auto の判定では元から通る側）。止める関所は `ask` と GitHub のブランチ保護である。

## 受け入れたリスク

- **ふだんの会話でも、枝への commit・push・PR の作成が確認なしで通りうる**（助言の V-04。人が受け入れた）。`ask` から外したので、auto モードの会話では、機能の枝への commit・push・PR の作成は auto の判定に回り、既定で通りうる。止めるのは CLAUDE.md の「人に言われるまでしない」だけで、確認のような強制ではない。個人の設定の `allow` に `git commit` などがあれば、それも効くようになる。main への merge・main への push・publish は、今までどおり確認が出る。default モードでは、`allow` に無い Bash は確認が出る。
- `bypassPermissions` のときは、枝名を書いた commit・push・PR の作成が確認なしで通る。
- `ask` は書かれた形にしか当たらない。別名・`sh -c`・引用符・フルパス・変数・PowerShell・GitHub の MCP などは止められない（`docs/development/workflow.md` の「すり抜けの道」）。止めるのは CLAUDE.md の決まりとブランチ保護である。
- この変更より前の main から切った枝は、`ask` に3本がまだ残っていて、確認が出る（載せ直せば消える）。

## 対象外・残った課題

- 助言の V-02：PreToolUse フック（`pipe_in_guard.py`）でコマンド全文を見て、main への push・強制・削除を止める。引用符つきの `'main'`、remote 名を省いた `git push main`、`sh -c`・別名・変数・`master` などの既定の枝も、ここで止める案。別の件で扱う。
- 助言の V-03：main へ届きうる push の形を `ask` でなく `deny` にする案。無人の実行でも待たずに断られて先へ進めるが、人が頼む main への push も止まる。別の件で決める。
- 助言の V-08：`gh api` の書き込み（`-X`・`--method`・`-f`・`--input`）、`gh -R … pr merge`、GitHub の MCP の `merge_pull_request`・`push_files`・`create_or_update_file` を、`ask` か `deny` で覆う。MCP のツール名は環境で変わる（推測）。別の件で扱う。
- 助言の V-01：`Bash(git push * :**)` は `Bash(git push * :*)` に簡単にしてよい（公式の文書に `**` の意味が無い。推測）。AC-41 の実機の確かめと合わせて決める。
- 助言の V-09：古い `:*` 形と新しい空白形がまざっている。動きは同じなので変えない。
- 助言の V-10：`autoMode.soft_deny` は、起動側の `--settings` か `~/.claude/settings.json` でしか効かない（リポジトリの設定では効かず、クラウドでは使えない）。必要になったら書き方を文書にする。
- 実機の確かめ（AC-34〜38・41）。ブランチ保護の設定は、人が GitHub でする。
