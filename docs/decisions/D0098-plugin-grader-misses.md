# D0098 プラグインの eval の採点の取りこぼしを直す（返事を頼む聞き方・過去の形と「〜ず」・離れた「組む」と選ばせる案の「足す」に当て、同じ 3 本の当たりすぎを絞り、見本のテストと残した記録への当て直しと haiku のラウンドで確かめる）

## 目的

D0097 の監査のあとの比べで、動きは正しいのに、言い回しが採点の正規表現に当たらずに落ちた回が 3 つあった（eval-lists-and-waits の 04-asks・live-stops-without-tools の 04-says-no-tools・build-refuses-judge-only の 02-says-command）。この 3 本を、その返事の形と近い言い換えにも当たるように直し、正しくない返事には今までどおり当たらないことを見本で確かめてから、haiku のラウンドで回した。要件メモは「採点の取りこぼし3つを直して、ラウンドを回して」。結果は [docs/research/plugin-eval-rounds](../research/plugin-eval-rounds/README.md) の「### 採点の取りこぼしを直したあと」にある。

### 要求と前提

- UR-01 プラグインを直す人として、正しく動いた返事（流す前に聞いた・道具が無いと伝えて止まった・`command` と組む案を見せて聞いた）が、採点の言い回しの取りこぼしで落ちないようにしたい。
- UR-02 プラグインを直す人として、採点を広げても、正しくない返事（流した・聞かずに進んだ・道具が有ると言う・自分で `command` を足して作った）は今までどおり落ちてほしい。
- UR-03 プラグインを直す人として、直した採点で haiku のラウンドを回し、取りこぼしが消えたことと、ほかに取りこぼしや動きの崩れが無いかを、調査の文書で読みたい。

- 前提：`claude plugin eval` の regex の採点は JavaScript の正規表現で当たり、pytest は Python の `re` で見る。D0045 と D0097 の範囲（`flags` は `i` だけ・インラインの記号・名前つきグループ・後ろ読み・`\A` `\Z`・`\b` を使わない）で書けば、両方で同じ意味になる。崩れると、pytest が通っても実機で当たらない。
- 前提：`target` を書かない regex の採点は、最後の返事だけを見る（3 本とも `target` を書いていない。D0097 の切り分けもこの読み方。設計で公式の文書と照らす）。崩れて trace の全部を見るなら、当たる・当たらないの見本の作り方が変わる。
- 前提：D0097 で記録（trace）を残した回の結果が、リポジトリの外の作業用フォルダに残っていて、取りこぼした 3 回の記録もある。消えていれば、残った記録への当て直し（FR-09）はできない。
- 前提：取りこぼしは、どれも 12 回に 1 回ほどの返事の形で起きた。haiku の返事は回ごとに揺れるので、1 回のラウンドで同じ形が出るとは限らない。取りこぼしが直ったことは、ラウンドの点ではなく、見本（pytest）と残った記録への当て直しで確かめる。
- 前提：プラグインの文（スキル・エージェント・`stage-rules.md`・フック）は D0097 の最後（版 0.6.2・10 のファイルの合計 44,928 バイト）から変わっていない。ケースの採点を変えても、プラグインの版は上げない（D0045）。
- 前提：言い回しを見る regex は、返事の自由な言い方を全部は拾えない。今回拾うのは、見つかった形と、その近い言い換え・英語の言い方だけで、新しい言い方の取りこぼしはこれからも出うる（そのたびにラウンドで見つけて直す）。

### 状態の問い

状態を持ち、操作や出来事で移り変わるか

答え：いいえ
理由：変えるのはケースの採点の正規表現 3 本・テスト・文書だけで、記録（`state.json`）の移り変わりや新しい状態を足さない。ラウンドを回して直すくり返しは、人（メイン）の作業の手順で、ソフトの状態ではない。

## 決めたことと理由

- **3 本の新しい pattern**（どれも `flags: i`。`\b`・後ろ読み・インラインの記号は使わない）：
  - 04-asks：「（お）返事（を）ください」「ご返答（を）ください」、返事を待つ文（「返事をお待ちします」など）、英語の please reply・please let me know などを足した。当たりすぎも絞った。半角の `?` はすぐ前が `$` でないときだけ数え、`proceed` は `(?:ok|okay|whether|me) to proceed` の形だけ、`confirm` は `confirm(?!ed)` だけにした。
  - 04-says-no-tools：3 つ目の前読みに、過去の形（「無かった」「なかった」、英語の couldn't find・did not find・weren't available など）を足した。ラウンドのあとに、連用の打ち消し（「見つからず」「見当たらず」「使えず」「できず」）も足した。「ず」だけを足すと「迷わず」「必ず」に当たるので、語を名指した。Artifact と Monitor の両方の前読みは残した。
  - 02-says-command：(a) `command` と「組」が同じ返事の中にあれば当てる（前は 40 字の内）。自分で入れて作った形（「組み込んで」「組み込みました」「組みました」「組んで作」）は除く。(b) 選ばせる目印（案・どちら・どれ・選・おすすめ・推し・option・which・prefer・recommend）があり、`command` のあと 20 字の内に言い切りの「足す」「加える」「追加する」があるか、`add ` のあと 20 字の内に `command` があれば当てる。
