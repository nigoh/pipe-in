# D0084 SDK の道の守りを、会話の道と同じ範囲にそろえる（#134）

## 目的

会話の道（`/pipe-in:pipe-run`）は、`.claude/`・`.git/`・`.pipe-in/`・`pipeline.toml` への書き込みを、どの段でも止めていた。SDK の道（`pipe-in`）は、`pipeline.toml` の `protected_paths` に書かないかぎり、止めなかった（既定は空）。そのため、開発フローの実装の段と、パイプの `access = "code"` の段が、この4か所に書けた。`setting_sources = ["project"]` のときは、段が `.claude/settings.json` やフックを書き換えられた。

「どこで流しても同じ守り」にするため、SDK の道も、この4か所を設定なしで守る。守る場所は、1か所の定数にする。

## 機能要件と受け入れ基準

テストは、断りの無いかぎり `tests/test_default_protected.py`。

- FR-01 既定で守る場所の定数 `DEFAULT_PROTECTED_PATHS` を `pipe_in/engine/spec.py` に置く。中身は7つ：`.claude/*`・`*/.claude/*`・`.git/*`・`.git`・`.pipe-in/*`・`pipeline.toml`・前の版の置き場所の下。
- FR-02 SDK の道は、`protected_paths` の有無によらず、この定数と利用者の `protected_paths` を、全部の段の書ける範囲から外す。開発フローとパイプの両方に効く。`Config` に項目は足さない。
- FR-03 会話の道は、同じ定数を使う（`EXTRA_PROTECTED` を消した）。
- FR-04 段に渡す「書ける範囲の説明」に、既定で守る場所も出す（同じものは1回だけ）。
- FR-05 既定で守る場所を外す設定は、作らない。
- FR-06 `pipe-in-gen check` は、`docs_dir`・`writes` が既定で守る場所と重なるパイプに、警告を出す（誤りにはしない）。
- FR-07 `work_dir` が既定で守る場所と重なる設定は、流す前に止める。

## 決めたことと理由

- 守りの部品（`pipe_in/engine/guard.py`・`generator/guard_hook.py`・`.claude/hooks/pipe_in_guard.py`）は変えていない。変えたのは、段の書ける範囲を作る所（`protect()`）が外す場所だけ。今までの `protected_paths` と同じ仕組みに載せたので、すり抜けの道（Bash・`..`・リンク・MultiEdit など）への効き方も同じ。
- 止める範囲を広げるだけで、狭める所は無い。守りの比較の表（`tests/guard_matrix.py`）では、SDK の道の列の 19 行が「許す → 止める」に変わった。ほかの列と行は変えていない。
- 外す設定は作らない（issue で決定済み）。今のひな形・見本・開発フローに、4か所へ書くものが無い。守りを狭める設定は、要ると分かってから、すり抜けの道にならない条件と一緒に決める。
- 前の版の置き場所の下も、既定で守る（今までは、どちらの道でも守られていなかった）。pipe-in 自身は、そこへ書かない（読むだけ）。
- `.git` 自身も守る（メモに無い足し）。worktree では `.git` がファイルになり、`.git/*` だけでは当たらないため。`.github/`・`.gitignore` には当たらない。
- `work_dir` が守る場所と重なる設定は、流す前に止める（メモに無い足し）。重なると、段が自分の成果物を書けず、途中で全部の段が止まるため。`work_dir` の下だけを守りから外す案は、守りに穴ができるので選ばなかった。ひな形・見本・ガイドの例は、どれも `docs/pipeline` で、重なる例は無かった。検査は、設定を読む所でなく、流す入口（`pipe_in/cli.py` と会話の道の始め）に置いた。`record`・`live`・`estimate` のような、流さない入口を巻き込まないため。
- `check` の警告は、誤りにしない（重なっても、重ならない部分は流せる）。先頭がワイルドカードの `writes`（`*.md` など）は、広すぎて警告が多くなるので、見ない。
- 既存のテストの期待を、新しい決まりに合わせた：守りの比較の表の SDK の道の列、`tests/test_reply_guard.py`（説明の文）、`tests/test_chat_hook.py`（本体の道でも止まる）。
- アーキテクチャのテストを2つ直した：`pipe_in/pipe/lint.py` が読んでよいものに `pipe_in.engine.spec`（定数）だけを足した（D0038 の受け入れ基準は「`pipe_in_generator` を読まない」までで、`pipe` → `engine` は決まった依存の向き）。前の名前の検査の許す一覧に `pipe_in/engine/spec.py` を足した（`generator/guard_hook.py` と同じ理由）。
- **動きが変わる場面**（今まで通っていた書き込みが止まる）：
  - 開発フローの実装の段と、パイプの `access = "code"` の段が、`.claude/`・`.pipe-in/`・`pipeline.toml`・前の版の置き場所に書けなくなる。製品コードが `.claude/` の中にある対象では、SDK の道の段でそこを直せなくなる。
  - `docs_dir`・`writes` がこれらと重なる段は、重なった部分が書けなくなる。
  - `work_dir` を守る場所の中にしている設定は、流す前に止まる。
  - 会話の道でも、前の版の置き場所の下が新しく止まる。
- 無人の実行（夜のまとめ実行）で進めた。次の点は推しの案で決めた（人の確認は朝）：前の版の置き場所を入れる／`check` が警告する／`.git` 自身も守る／`work_dir` の重なりは流す前に止める・検査は入口に置く／警告は先頭がワイルドカードの `writes` を見ない／比較の表に前の版の置き場所の行は足さず、守る場所を書いた列は残す／アーキテクチャのテストの2つの直し。
- 受け入れたリスク：`.claude/` の中に製品コードがある対象（このリポジトリのような作り）では、SDK の道の実装の段が、そこを直せない。外す設定が要るかは、別の issue で決める。

## 対象外・残った課題

- 既定で守る場所を外す設定、Skill を SDK の道で止めること、`git config` のようなコマンドを経た `.git/` の書き換え、MCP の道具が書く場所の検査、開発用のフック、プラグインのフック、拡張は、対象外。
- リンクを経た道で今は通る2つの組（プラグインの作る役・開発用の `pipe-in-coder`。D0083）は、この件では変えていない。
- 監査の報告（直していない。人の確認は朝）：
  - A-02 `pipe_in/pipe/chat_record.py` の `chat_specs` の説明と、段に足す文「（記録・.claude/・パイプのフォルダは書けません）」が、前の作りのまま。4か所を外すのは、今は `protect()`。`protect()` の付ける「既定で守る場所」の文と重なる。
  - A-03 `docs/guide/safety.md` の「Bash の `$(…)` は、どの守りでも道具ごと止めます」は、道具ごとでなく、そのコマンドを止める（D0083 からの持ち越し。同じ言い方のテスト名が、この件にもある）。
  - A-04 `safety.md` の「ほかの名前の文字列には何もしません」と、`plugin/hooks/hooks.json` の説明の「それ以外には何もしない」（D0083 からの持ち越し）。
  - D0083 の監査 A-01（開発用の `pipe-in-coder` の例外が本文に無い）は、この件の文書の直しで解けた。
- 助言の報告（公式の文書と照らした。8件。足していない。人の確認は朝）：
  - **V-01（重い）プロジェクトの直下の `.mcp.json` が、既定で守る場所に無い。** 公式の文書では、`setting_sources` に `project` があると読まれ、Claude Code 自身の守るファイルの一覧にも入っている。段が書き換えると、MCP サーバーの定義を足せる（次の段の始めにそのプロセスが起きるかは、助言役の推測で、実機では確かめていない）。足すかは、この件の「止める範囲は issue のとおり」を越えるので、朝に決める。足すなら、定数に1行と、比較の表の行。
  - V-02 `CLAUDE.md`・`CLAUDE.local.md`・入れ子の `CLAUDE.md` も、段への指示を変えうる。ただし、設計の段などが正当に直す使い方とぶつかる。人が決める。

  - V-05 SDK 自身にも `.git`・`.claude` を守る仕組みがあるが、`bypassPermissions` では守らない。そのときは、自前のフックの「止める」だけが守りになる（公式の文書：フックの「止める」は `bypassPermissions` でも効く）。自前の守りは外せない。
  - V-06 `disallowed_tools` に「止める」決まりを足して、二重の守りにできる（任意）。
  - V-07 設定のファイルは、同じ実行の中で読み直される（公式の文書。Claude Code 全般の説明で、SDK での明記は無い）。段の途中で `.claude/settings.json` を書けると、次の段を待たずに効く。1回目の書き込みから止める今の守りの理由になる。
  - V-08 `docs/guide/config.md` の `setting_sources` の説明に、`project` が `.mcp.json` も読むことが書かれていない。
- 審査の採点：overall 0.85、verdict は pass（しきい値 0.7）。審査役の指摘：V-08 の出典の取り違えが1件（`.mcp.json` の根拠は MCP のページ）。プラグインの置き場所は、助言役が文書を取らずに済ませた。公式の文書の一部（hooks・permissions のページ）は、助言役も審査役も読みきれていない。
