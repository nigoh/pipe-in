# D0063 並列の枠を実行の図に出す

## 目的

作業台では並列の枠（stage の `group`）を作れるが、実行パネルのパイプの図は段を一列に並べて描いていた。実行の図でも枠を枠として描き、枠の中の段ごとの状態（待ち・動いている・済み・失敗）を出し、動いている段のログを節を押して選べるようにする（GitHub の issue #13）。

調べると、記録に足りないものがあった。本体は枠の中の段を同時に流すが、`state.json` の `stages[]` に `group` を残していなかった。また、動いている段のログの探し方は「通し番号が最大より後ろ」の 1 つだけを返すため、枠の中で先に済んだ段の番号が大きいと、まだ動いている段のログが落ちた。

## 機能要件と受け入れ基準

### 機能要件

- FR-01：本体は `state.json` の `stages[]` の、`group` を持つ段に `group`（枠の名前の文字）を足す。`group` の無い段・開発フローには足さない。
- FR-02：拡張は `stages[].group` を `StageDef` に読む。文字でない・空の値は null にし、例外にしない。
- FR-03：パイプの図の節の組み立てで、同じ `group` の続いた段を 1 つの枠（枠の名前と、中の段の節の並び）にまとめる。`group` の無い記録・開発フローは今までどおり一列。
- FR-04：図は、枠を作業台と同じ色・形（角丸の線の枠・左上の名前の札）で描き、中の段は並べて置く。枠の前の節と枠、枠と次の節は、矢印 1 本ずつでつなぐ。
- FR-05：枠の中の段の節に、段ごとの状態（まだ・動いている・完了・失敗）を出す。同時に複数の段が「動いている」になれる。
- FR-06：枠の中の段が判定でやり直したときは、その段の節に「N 回目」を出し（段の実行が 2 回以上ある段と同じ）、判定の節は他の段と同じ扱いで枠の中の段のすぐあとに出す。
- FR-07：枠自体にも状態の目印を持たせる（中に動いている段があれば動いている、1 つでも失敗なら失敗、すべて完了なら完了、それ以外はまだ）。
- FR-08：動いている段の判定は、枠の中の複数の段が同時に動く形に直す。段のログごとに「終わっていない」を見て決め、通し番号の大小で落とさない。開発フロー・枠の無いパイプの結果は変えない。
- FR-09：枠の中の段の節を押すと、右の欄の出力がその段のログに切り替わる。押した段のログがまだ無ければ「ログなし」と出す。もう一度押す・別の節を押す・枠の外の節を押すと、いちばん新しいログに戻る。
- FR-10：枠の中の複数の段が動いているとき、既定で出すログは今までと同じ決め方（通し番号がいちばん大きい動いているログ）にし、選んでいる間は選んだログを出し続ける。
- FR-11：古い記録（`group` の無い記録）と、枠の中の段が 1 つだけの枠は、壊れずに描く。後者は枠を描く（作業台と同じ）。

## 決めたことと理由

要件定義の「決めきれない点」は、推しの案で決めた（夜間の無人の実行のため）。

1. **記録の鍵は `stages[].group`**。段の並びとずれる別の配列は取らない。D0062 の `check` と同じ「足すだけ」。`BasePipeline._stage_groups()`（既定は空）を足し、`LinearPipeline` だけが実装する。
2. **枠の中は横に並べ、3 段より多いと折り返す**。作業台に合わせ、同時に流れるのが見える。
3. **ログの選びは節を押す**。選びは画面の中の変数だけで持ち、拡張へ送らず保存しない。タブは取らない。
4. **枠が 1 段だけでも枠として描く**（作業台と同じ）。
5. **枠の状態は名前の札の色で示す**。文字は足さない。
6. **`nodes` は平らなまま、`frames` を別に足す**。節の順・id を変えず、既存のテスト・理由の欄に影響しない。
7. **動いている段は `runningStages`（複数）で持ち、既定のログの段（`runningStage`）は今までの決め方のまま**。時系列・使用量・`pipe-in live` は今のまま。
8. **`group` の読みは、段の名前の規則にしない**。本体の定義は `group` を任意の文字列で受け、作業台の枠名は日本語もありうる。空・空白だけ・65 文字以上・`/` `\` を含む・文字でない値は null、ほかはそのまま読む。
9. **枠の色は `view/frameStyle.ts` の `PAR_COLOR` に 1 か所だけ置き**、作業台と実行パネルが同じ値を読む。
10. **枠があるときだけ本線の x をずらす**（`dx`）。枠が無いときは `dx = 0` で、SVG は 1 文字も変わらない。
11. `guard.py`・`guard_hook.py`・`pipe_in_guard.py` は変えない（止める範囲は狭めない）。依存は足さない。`pipeline.toml`・`pipe.toml` は変えない。

## 対象外・残った課題

- 枠をまたぐ・入れ子の枠、枠の中の段の判定のやり直しの描き分け、アーティファクト（`pipe-in live`）への反映、時系列・使用量の枠ごとのまとめ、枠の中の段のログを同時に並べて見せること、実行パネルから枠を編集すること。
- 強制終了などで終わりの行が無いまま残った枠の中の段のログは、記録に実行が載っていなければ「動いている」と数える。
- 枠の中の節は、上限の棒と金額の表示を出さない（`<title>` には残す）。
