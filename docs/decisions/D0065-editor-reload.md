# D0065 外で書き換わったパイプを、開いたままの作業台が読み直す

## 目的

作業台は開くときに1回読むだけで、Claude Code（`/pipe-in:pipe-build`）や手で `pipe.toml`・`prompts/*.md` が書き換わっても届かなかった。開いたままの作業台が外の書き換えを読み直し、まだ保存していない変更は守る。GitHub の issue #17（段階2の一部）を扱う。

## 機能要件と受け入れ基準

- FR-01 見張りと判断
  - D0065-AC-01 パイプのフォルダの中で、`pipe.toml`・`prompts/` 直下の `.md`・`layout.json` だけを見るべき変更とする。
  - D0065-AC-02 ディスクから読んで作り直したファイルの組が保存済みの形と同じなら何もしない（作業台自身の保存の直後はこれになる。旗や時計は使わない）。
  - D0065-AC-03 違っていて、保存していない変更が無ければ、そのまま読み直す。
  - D0065-AC-04 違っていて、保存していない変更があれば、上書きせず、差分を出して選ばせる。
  - D0065-AC-05 差分は、段の増減・指示文・つなぎ・設定・位置を別の項目にして一覧にする。
  - D0065-AC-06 「自分の変更を残す」を選んだあと、同じ外の形では何も出さない。外の形がさらに変われば選ばせる。
  - D0065-AC-07 短い間の知らせは、デバウンス（300ms）で1回の読み直しにまとめる。
- FR-02 版に残す
  - D0065-AC-08 版の種別に `-external` を足す（並びは 下書き → 外 → 保存。残す数 50 に数える）。
  - D0065-AC-09 取り込む前の保存済みの形を `<id>-external.json` に書く。保存・下書きの版の動きは変えない。
  - D0065-AC-10 前の拡張は `-external` のファイルを形の違うものとして読み飛ばすだけで壊れない。`-external` の無い古い保存場所も読める。
  - D0065-AC-11 外の版も、一覧にあるときだけ読む。
  - D0065-AC-12 取り込む前に、保存済みの形を `-external` に、保存していない変更があれば今の形も `-draft` に残す。版を残せなくても取り込みは止めない。
  - D0065-AC-13 「自分の変更を残す」ではファイルも版も書かない。
  - D0065-AC-14 読めないときは理由だけを知らせ、作業台の形・版を変えない。
- FR-03 メッセージと画面
  - D0065-AC-15 `externalChoice`（load／keep）を `parseEditorMessage` で確かめ、形の違うものは捨てる。
  - D0065-AC-16（画面）保存していない変更が無いときは、トースト付きで自動で読み直し、履歴に「外で書き換わる前」が増える。
  - D0065-AC-17（画面）保存していない変更があるときは、帯に差分と「外の変更を読み込む」「自分の変更を残す」を出し、選んだとおりになる。
  - D0065-AC-18（画面）作業台自身の保存では、帯もトーストも出ない。
  - D0065-AC-19（画面）履歴の「外で書き換わる前」を押すと、その形が読み込まれ、保存を押すまでファイルは書かれない。
- FR-04 守ること
  - D0065-AC-20 差分・理由の外から来た文字は `escapeHtml` を通す。
  - D0065-AC-21 作業台の HTML は、これまでどおり外部を読み込まない。
  - D0065-AC-22 層の向き・`vscode` を import するのは `extension.ts` だけ・書き込み先の絞り込みは変えない。
  - D0065-AC-23（手で）本物の `/pipe-in:pipe-build` で書き換えさせて、AC-16・17 のとおりになる。

## 決めたことと理由

- 判断は純粋な関数に置く（`domain/pipeExternal.ts`・`pipeDiff.ts`）。手順は口を引数で受ける（`app/externalReload.ts`・`debounce.ts`）。見張りの作成は `extension.ts` だけ。
- 作業台自身の保存かどうかは、旗や時計ではなく、ディスクから作ったファイルの組と保存済みの形の比較で決める（同じなら何もしない）。保存との競り合いは、世代を進めて古い読み取りを捨てる。
- 「外の変更を読み込む」を選ぶとき、保存していない変更は下書きの版に自動で残す（人に聞けない夜の実装で、推しの案で決めた。戻せることが主旨で、版は 50 まで自動で整理され、書き込み先は拡張の保存場所だけなので害が小さい）。
- 版の `-external` は、`FILE` の正規表現に足しただけで、書き込み先は増えない。前の拡張は形の違うファイルとして読み飛ばすが、前の拡張に戻して使うと、`-external` が上限の数に入らず消されずに残る（容量だけの害）。
- 見張りは、作業台ごとにパイプのフォルダ（`PIPE_WATCH_GLOB`）に作る。D0034 の配線の検査（`extensionWatch.test.ts`）は `createFileSystemWatcher(` を数えるので、`createPipeWatch` と束ねた別名 `makeWatcher` を通して数えの外に出した（実装が 04 に書いた回避。検査の意図とは食い違うので、「残った課題」に書く）。
- 直した既存のテスト：`tests/test_decision_ui.py`（D0010-AC-05。版のファイル名に `-external`）、`tests/test_skill_tidy_docs.py`（D0039-AC-15。作業台のページが 5 枚）、`docs/decisions/D0010-ui-records.md`（`externalChoice`・版のファイル名）。

## 受け入れたリスク

- 編集の直後（最大 300ms）に外の書き換えが来ると、保存していない変更が「無い」と見られ、自動で読み直して、その編集が消えることがある（設計で許した窓。監査 A-03）。
- 「外の変更を読み込む」の途中で保存が入ると、古い外の形で保存済みの形を上書きすることがある（監査 A-04。低）。

## 対象外・残った課題

- 監査の報告（A-01〜A-09）は直していない。全文は PR の本文の「朝に見ること」にある。大事なのは A-03（保存していない変更を失う窓）・A-05（配線の検査の意図）。
- `.claude/skills/pipe-in/screen-check.md`・`/pipe-help` への追記は、書けないので案のまま（PR の本文）。
- 助言（公式の文書との照らし合わせ）と審査は、`.claude/`・plugin・guard を触らないので流していない。
