# D0016 差し戻しと修正の依頼の理由を、図の節を選んで見られるようにする

## 目的

実行の図を見る開発者が、差し戻し・修正の依頼が「どこへ戻り」「なぜ戻ったか」を、記録（`state.json`）を開かずに、図の節を選んで読めるようにする。イシュー #11。`docs/roadmap.md` 段階1「見る」。

## 機能要件と受け入れ基準

拡張（`vscode/`）だけを変える。本体の記録の形は変えない。テストは `vscode/src/` の中。

- FR-02 図の状態に、差し戻し（不合格の判定 1 件につき 1 つ。開発フローだけ）の一覧を持たせる

  - D0016-AC-04 不合格が 2 回なら古い順に 2 件で、合格は入らない（同上）

## 決めたことと理由

人が決めた 5 点。

- パイプの差し戻しは入れない。パイプの戻り先（`on_fail`）は記録に残らず、本体の変更が要るので、#12（パイプの判定とやり直し）で扱う。パイプでは確認の修正依頼の理由だけ出す。
- 理由は、右の欄の警告の下・出力の上の「理由」の節に出す。図の下（左の列が縦に伸びる）や矢印のツールチップ（長い文が読めず、キーボードで読めない）より、折り返しと長い文を扱いやすい。
- 矢印の描き方は変えず、選んだ節の矢印を強調するだけにする。回数つきの矢印はもう描かれているため。強調は破線をやめて実線にし、色だけでなく線の見た目でも分かるようにする。
- 選びはパネルのスクリプトの中だけで持つ。拡張が持つ新しいメッセージ `selectNode` を足す案より、拡張の状態と検査が増えない。理由の文は全部 HTML に入れて `hidden` で隠し、スクリプトが開け閉めする。
- 不合格のまま終わった最後の判定も一覧に入れて「差し戻されていない」と出す。選べるのは矢印ではなく節だけ。

設計で決めた 2 点。

- 判定の `attempt` が無い古い不合格の `sentBack` は、後ろに判定があるかで決める（記録の順序だけで決まる）。「常に true」にすると、不合格のまま終わった判定を「差し戻した」と誤って出す。
- 実装の節と判定の節の両方を選べる（同じ差し戻しの一覧）。矢印は判定から実装へ引かれているので、どちらの端からでも選べるほうが分かりやすい。

形の互換：記録（`state.json`）・設定・拡張のメッセージは変えない。拡張の内側の型 `Verdict` と `PipelineView` に項目を足すだけで、古い記録では足した項目が空になる。

### D0010 からの変更

[D0010](D0010-ui-records.md) は書き換えない。D0010 が「今の形」として書いていることのうち、次が変わる。

- 実行パネルの図の節に、選べる節ができた（D0010 の「節の状態」には選ぶ操作が無かった）。履歴のある節は `role="button"`・`tabindex="0"` を持つ。図の `<svg>` は、選べる節があるときだけ `role="group"` になる。
- パネルのスクリプトが、押す・Enter・Space の操作と、選んだ節の id を持つようになった（D0010 の「画面のスクリプトは呼ぶだけ」の例外。判断は domain の `reasonNodeIds`・`nodeReasons` に出してある）。拡張へ送るメッセージの種類は変わらない。選んだ節には `aria-pressed` を付け、記録の描き直し（`render`）のあとも選びを残し、フォーカスが選べる節にあったときは同じ節に戻す。
- 変わらないもの：メッセージの種類（`ready`・`openArtifact`・`selectRun`・`render`）、work_dir を読むだけの決まり、読むファイル、監視。

## 対象外・残った課題

- パイプの差し戻し（`check` の不合格と戻り先 `on_fail`）の矢印と理由。#12 で扱う。
- 本体の記録の形（`state.json`・`99_summary.md`・終了コード）の変更。
- 判定が `blocked` のときの理由、red 段の結果の表示。
- 矢印そのものを押して選ぶこと、理由の編集・返事（段階3）。
- 拡張へ新しいメッセージを足すこと、拡張が work_dir へ書くこと。
- 差し戻し前後の成果物の差分の表示、ログの該当位置へのジャンプ。
