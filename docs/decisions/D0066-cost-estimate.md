# D0066 流す前に費用の目安（少なめ〜多め）を出す

## 目的

今は、どのくらいかかるかが流したあとの記録（`usage_summary`）でしか分からない。流す前に、段の数・モデル・ターンの上限・やり直しの上限から費用の幅（少なめ〜多め）を出し、前に同じパイプを流した実績があれば別の欄で見せる。目安であって約束ではないことを、いつも書く。CLI と VSCode の作業台の両方で見られるようにする。GitHub の issue #17 に続く段階4（一般の人へ）の #22 を扱う。

## 決めたことと理由

- 単価は案A：系統ごとの「1ターンの目安」を、本体（`prices.py`）と拡張（`costEstimate.ts`）の2か所に持ち、共通の表との一致をテストで守る（ビルドに手を入れず、更新も3か所だけ）。トークン単価と仮定を持つ案B、JSON を共有してビルドに手を入れる案Cは採らなかった。
- 単価の最初の数字は仮の値（haiku 150・sonnet 500・opus 2500 の 1/10000 ドル／ターン、`as_of` 2026-10）。手元に過去の `state.json` が無く、公式の価格表から出したものでもない。`note` と `docs/guide/usage.md` に「仮の値」と書いた。実績が貯まるか公式の価格表を見たら、`prices.py`・`costEstimate.ts`・共通の表の3か所を一緒に直す。
- 本流の出力は2行：要件の「1行」（FR-06・AC-14）と、どの出力にも FR-09 の文を付ける（AC-15）がぶつかり、目安1行＋FR-09 の文1行にした（監査 A-01）。
- 「多め」のやり直しは、自分の段の `1＋max_retries` 倍だけ。`on_fail` で戻る前の段の再実行は足さない。だから多めは厳密な上限ではない（文書に書いた）。
- 少なめにも `max_budget_usd` の頭打ちを掛ける（少なめが多めを上回る逆転を防ぐ）。
- 実績の読み方は本体と拡張で違う。本体は `usage_summary`／`runs[].metrics.by_model[*].cost_usd` の合計。拡張は、既に読んだ実行の一覧の `total_cost_usd`（`RunRow.costUsd`）から、そのパイプの更新が一番新しい行を選ぶ（要件の FR-07 は `runRecord.ts` の `runs`・`usage` としていたが、実装の段で一覧を使う形にした。監査 A-03）。「今日」の取り方も、本体はローカル日付、拡張は UTC の日付で、古い判定の境で最大1日ずれる（A-06）。
- 目安は `state.json`・`99_summary.md` に書かない（記録の形を変えない）。
- 作業台の表示場所は「ブロック」タブの末尾（段を編集しながら数字の変化を見られる）。作業台のページは足さず（`EDITOR_PAGES` が5つ固定）、既存ページのスタブに `window.__previewEstimate` を足して確かめる。
- 直した既存のテスト・記録（検査を正しく直した。すり抜けではない）：
  - `vscode/src/domain/runListTools.test.ts`（D0050-AC-40）：`RunRow` のキーを固定する検査。題と注釈に「増やすときは、人が決めた設計の変更として直す」とある。設計で承認した `costUsd` を足したので、17個を18個にした。
  - `docs/decisions/D0010-ui-records.md`：作業台の拡張→パネルのメッセージの行に `estimateContext` を足した（`tests/test_decision_ui.py` が型と一致を検査する）。
  - `tests/test_rename.py` の `ALLOWED`：`tests/test_estimate_cli.py` を、前の版の置き場所のパイプでも目安が出ることのテスト（AC-26）として理由つきで1行足した。

## 受け入れたリスク

- 目安は仮の単価で、実際とずれうる。画面・CLI・文書のどこにも「約束ではない」を書いた。
- 「多め」は厳密な上限ではない（`on_fail` の戻り、思考の長さ、キャッシュは入らない）。
- 監査で見つかった軽い食い違い（A-02 の印の文の言い回し、A-04 の `5.0` の扱い、A-06 の「今日」の取り方）は、今回は直していない。

## 対象外・残った課題

- 請求額の約束・単価の自動取得・並列や分岐の実際の流れの推定・利用枠の予測・作業台に「流す」ボタンを足すこと。
- 監査の報告（A-01〜A-06）は直していない（A-01・A-03 はこの記録で決めを書いた）。全文は PR の本文の「朝に見ること」にある。
- 助言（公式の文書との照らし合わせ）と審査は、`.claude/`・plugin・guard を触らないので流していない。
- `CLAUDE.md`・`.claude/skills/pipe-help/SKILL.md`・`.claude/skills/pipe-in/screen-check.md` への追記は、書けないので案のまま（PR の本文）。
