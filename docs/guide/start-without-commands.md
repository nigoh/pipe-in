# コマンドを打たない人向けの案内

[ガイドの目次](README.md) · [README](../../README.md) — 端末に慣れていない人が、VSCode の拡張とブラウザ・会話で、pipe-in の画面を見て、見本を選び、確認に答えるところまでの道です。

保存したパイプは、作業台の「流す」から流せます。ただし、`pipe-in` を入れることと、パイプを作ること、開発フローを流すことには、端末（か Claude Code の会話）が要ります。この文書は、コマンドを使わずにできる範囲と、できない範囲を分けて書きます。

## コマンドを使わずにできること

- **拡張を入れる**：配布用のファイル（`.vsix`）を VSCode の「拡張機能」から入れます。作り方は [VSCode の拡張](vscode.md)。
- **案内をたどる**：VSCode の「ようこそ」（コマンドパレットの「Help: Welcome」）から「pipe-in をはじめる」を開くと、入れる → 見本を選ぶ → 流す → 確認に答える、の 4 つの手順が左に並び、選ぶと右に本文が出ます。案内は自動では開きません。
- **見本を見る**：コマンドパレットの「pipe-in: 実行を見る」でパネルを開き、左の一覧から実行を選ぶと、図・出力・時系列が右に出ます。
- **パイプを組み立てる**：コマンドパレットの「pipe-in: パイプ作業台を開く」で、見本のパイプを開いて見られます。
- **作業台から保存したパイプを流す**：保存したパイプは、作業台の右の欄の節「流す」で、依頼メモを書いてボタンを押すと流せます（設定 `pipe-in.command` で実行ファイルを決めます）。→ [作業台から流す](vscode.md#作業台から流す)
- **確認に答える**：実行が確認待ちになると、拡張が知らせます（設定 `pipe-in.notifyWhenWaiting`）。答え方は、Claude Code の会話から流したときは会話の中、`/pipe-in --artifact` で流したときは Claude のアーティファクトのページのボタン、端末で流したときは端末の入力、作業台の「流す」で流したときは、VSCode が開く端末の入力です。→ [確認の画面](usage.md#確認の画面)

## コマンドが要るところ

開発フロー（`--pipe` を付けない流れ）は作業台から流せません。端末で次の 1 行を貼ります。次の 1 行は開発フローの形で、pipe-in を入れたあと、対象のプロジェクトと要件メモを渡します。

```bash
pipe-in --project ~/src/myapp --text "ユーザー一覧に CSV 出力ボタンを追加したい"
```

- 入れるときにも、端末で `pip install -e .` を流す手順があります。→ [README](../../README.md#入れる)
- Claude Code の会話が使えるなら、端末の代わりに会話で `/pipe-in <要件メモ>` と書いても流せます。→ [使い方](usage.md)
- 段ごとに Claude Agent SDK を呼ぶので、利用料がかかります。対象は git 管理下にして、作業用のブランチで流してください。

つまり、見る・選ぶことと、保存したパイプを流し始めることは画面だけでできます（作業台から流した実行の確認は、VSCode が開く端末に答えを入力します）。開発フローを流し始める 1 行は端末（か Claude Code の会話）で貼る必要があります。貼る 1 行は、上のものを写して、対象の場所と要件メモの文だけ書き換えれば足ります。
