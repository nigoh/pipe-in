# /pipe-in:pipe-judge — 成果物を審査する

依頼: $ARGUMENTS

（空なら、審査する成果物のファイルと、何を作る約束だったか（依頼）を聞いてから始める）

ここに書いたのは進め方だけです。この会話では、審査役 pipe-judge を呼んで、返ってきた点を `pipe-in-gen judge-score` に渡して結果を伝えるだけで、成果物は直さない・パイプへ差し戻さない。
このスキルは人が呼んだときだけ動く。審査役は Claude を呼ぶので利用料がかかる（`--runs` を増やすほど増える）。
返す合否は、人が読む材料です。パイプの合格・不合格を決めるのは、検査（/pipe-in:pipe-eval）です。

## 0. 前提を確かめる

- `pipe-in-gen --help` が動き、一覧に `judge-score` があるかを確かめる。動かない、または `judge-score` が無ければ、pipe-in の入れ直し（取ってきたフォルダで `pip install -e .` をやり直す）を案内して止まる。
  `judge-score` が無い古い `pipe-in-gen` では、審査役を読むだけに絞るフックも古い可能性がある（フックが古いと、審査役の道具は `tools:` だけで絞られる）。黙って文章で計算に切り替えない。
- 成果物のファイル・依頼・ルーブリックの場所を決める。成果物が見つからなければ、聞いて止まる。

## 1. 引数を読む

- 成果物：審査するファイル（またはフォルダ）。
- 依頼：何を作る約束だったか。`--request <ファイル>` か `--text "…"`。なければ聞く。元の資料があれば、その場所も聞く（「事実」の確かめに使う）。
- ルーブリック：`--rubric <ファイル>` で渡す。ファイルは Markdown の表で、列は `項目名 | 見ること | must か` の 3 つ。`must` の行は最後の列に `must` と書き、それ以外の行は採点の項目になる。渡されなければ**既定**のルーブリック（審査役 pipe-judge の「既定のルーブリック」。採点 5 つと must 2 つ）を使う。
  ルーブリックのファイルは読むだけで、書かない。表を読んで `[{name, must}]` の形にし、`judge-score` の `rubric` に渡す（項目名の食い違いを見つけるため）。既定のときは `rubric` を省く。
- `--runs N`：審査役を呼ぶ回数。**1〜5**、既定は 1。範囲の外（0 や 6 など）は流さずに断る。

## 2. `--runs` が 2 以上のとき

審査役を回数ぶん呼ぶので、利用料はおよそ回数倍になる。呼ぶ前に、「審査役を N 回呼びます（1 回のときの約 N 倍の利用料）。進めてよいですか」と見せ、返事を待つ。1 回のときは聞かずに進める。

## 3. 審査役を呼ぶ

エージェント pipe-judge（一覧では `pipe-in:pipe-judge`）を、回ごとに呼ぶ。審査役の既定のモデルは sonnet。成果物を作ったモデルと同じなら、呼ぶときに別のモデルを指定してよい（作ったモデルと別のモデルで審査するほうがよい）。渡すもの：成果物の場所・依頼・元の資料の場所・ルーブリック（項目名・見ること・must か）。
返事は JSON（`reasons` → `scores` → `must`）。形が崩れていたら、1 度だけ言い直させる。それでも崩れていたら、人に見せて止まる。

## 4. 計算させる

総合点・合否・ばらつきは、審査役にも自分にも暗算させない。`pipe-in-gen judge-score` に、標準入力で JSON を渡して計算させる（一時ファイルは作らない）。

```
pipe-in-gen judge-score <<'JSON'
{ "rubric": [ {"name": "…", "must": false} ], "runs": [ <審査役の返事を回の数だけ> ] }
JSON
```

- 総合点は採点項目の点の平均（`null` は数えない）。0.7 以上で `pass`、届かなければ `fail`。
- must の違反が 1 つでもあれば、平均に関わらず `fail`。must が確かめられなかった（`null`）ときも `fail` で、`must_unchecked` に載る。
- `--runs` が 2 以上なら、項目ごとの平均と総合点の平均を出し、ばらつき（`variance`）も付く。
- 受け取れない入力は終了コード 2 で理由が出る。理由を審査役に伝えて 1 度だけ言い直させ、それでもだめなら人に見せて止まる。

## 5. 結果を返す

先頭に一言添える：「この合否は人が読む材料です。パイプの合格・不合格は /pipe-in:pipe-eval の検査で決まります」。
成果物に検査のコマンド（パイプの `[stages.check]` の `command` やテスト）がありそうなら、先に /pipe-in:pipe-eval で確かめることを勧める。
そのあと `judge-score` の JSON をそのまま返す。キーは次のとおり。

- `runs`：回ごとの `reasons`・`scores`・`must`・`overall`・`verdict`
- `scores`：項目ごとの平均
- `must_violations`：違反した must と根拠
- `must_unchecked`：確かめられなかった must
- `overall`：総合点（平均）
- `threshold`：0.7
- `verdict`：`pass` か `fail`
- `variance`：`--runs` が 2 以上のときだけ。`verdict_disagreement`（合否が割れた回の割合）と `overall_range`（総合点の最大と最小の差）

結果はファイルに残さない。`fail` でも、成果物は直さず、パイプへ差し戻さない。直すか、どう進めるかは人が決める。
