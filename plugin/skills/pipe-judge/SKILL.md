# /pipe-in:pipe-judge — 成果物を審査する

依頼: $ARGUMENTS

（空なら、成果物のファイルと依頼を聞いてから始める）

**最初に `--runs` を見る。** `--runs` が 1〜5 の整数でなければ、「`--runs` は 1〜5 です」とだけ伝えて止まる。利用料の確認を出さない・審査役を呼ばない・`judge-score` を流さない（0 章にも進まない）。`--runs` が付いていなければ 1 として進む。

この会話は、審査役を呼び、点を `pipe-in-gen judge-score` に渡して結果を伝えるだけ。成果物は直さない・パイプへ差し戻さない。
人が呼んだときだけ動く。審査役は Claude の利用料がかかる（`--runs` を増やすほど増える）。
合否は人が読む材料。パイプの合格・不合格を決めるのは検査（/pipe-in:pipe-eval）。

## 0. 前提を確かめる

- `pipe-in-gen --help` が動き、一覧に `judge-score` があるかを確かめる。無ければ、入れ直し（取ってきたフォルダで `pip install -e .`）を案内して止まる。古い `pipe-in-gen` では、審査役を読むだけに絞るフックも古い可能性がある（フックが古いと、審査役の道具は `tools:` だけで絞られる）。黙って文章で計算に切り替えない。
- 成果物が見つからなければ、聞いて止まる。

## 1. 引数を読む

- 成果物：審査するファイルかフォルダ。
- 依頼：`--request <ファイル>` か `--text "…"`。なければ聞く。元の資料があれば、その場所も聞く。
- ルーブリック：`--rubric <ファイル>`。Markdown の表で、列は `項目名 | 見ること | must か`（`must` の行は最後の列に `must`、ほかは採点の項目）。渡されなければ既定（審査役の「既定のルーブリック」）を使う。
  ファイルは読むだけで書かない。表を `[{name, must}]` にして `judge-score` の `rubric` に渡す（項目名の食い違いを見つけるため）。既定なら `rubric` を省く。
- `--runs N`：審査役を呼ぶ回数。1〜5、既定は 1。範囲の外（0 や 6 など）は流さずに断る（頭の 1 行のとおり）。

## 2. `--runs` が 2 以上のとき

呼ぶ前に「審査役を N 回呼びます（1 回のときの約 N 倍の利用料）。進めてよいですか」と見せ、返事を待つ。1 回なら聞かずに進める。

## 3. 審査役を呼ぶ

エージェント pipe-judge（一覧では `pipe-in:pipe-judge`）を回ごとに呼ぶ。既定のモデルは sonnet で、成果物を作ったモデルと同じなら別のモデルを指定してよい。渡すもの：成果物の場所・依頼・元の資料の場所・ルーブリック（項目名・見ること・must か）。
返事は JSON（`reasons` → `scores` → `must`）。崩れていたら 1 度だけ言い直させ、それでも崩れていたら人に見せて止まる。

## 4. 計算させる

総合点・合否・ばらつきは、審査役にも自分にも暗算させない。`pipe-in-gen judge-score` に標準入力で JSON を渡す（一時ファイルは作らない）。

```
pipe-in-gen judge-score <<'JSON'
{ "rubric": [ {"name": "…", "must": false} ], "runs": [ <審査役の返事を回の数だけ> ] }
JSON
```

- 総合点は採点項目の平均（`null` は数えない）。0.7 以上で `pass`、届かなければ `fail`。
- must の違反が 1 つでもあれば、平均に関わらず `fail`。確かめられなかった must（`null`）も `fail` で、`must_unchecked` に載る。
- `--runs` が 2 以上なら、回の平均を出し、ばらつき（`variance`）も付く。
- 受け取れない入力は終了コード 2 で理由が出る。審査役に伝えて 1 度だけ言い直させ、だめなら人に見せて止まる。

## 5. 結果を返す

返事は、次の 3 つをこの順に書く。

1. 先頭に一言：「この合否は人が読む材料です。パイプの合格・不合格は /pipe-in:pipe-eval の検査で決まります」。
2. `judge-score` が出した JSON を、```json の囲みにそのまま貼る。要約・表・言い換えに置き換えない。キーを消さない・足さない。
3. 短い添え書き（数行まで）。検査のコマンドがありそうなら、先に /pipe-in:pipe-eval で確かめることを勧める。

```json
<judge-score が出した JSON をそのまま>
```

キーは `runs`・`scores`・`must_violations`・`must_unchecked`・`overall`・`threshold`・`verdict` と、2 回以上なら `variance`（`verdict_disagreement`・`overall_range`）。

結果はファイルに残さない。`fail` でも直さず、差し戻さない。どう進めるかは人が決める。
