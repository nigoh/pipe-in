# pipe-in-spec-qa：仕様とソースの突き合わせ（検討事項・QA）（見本）

仕様書の項目とソースの対応を取り、食い違いと検討事項を洗い出し、QA の観点とテストケース案を書きます。
どの段もコードやテストは書きません（読むだけで、文書を書きます）。
`generator/templates/spec-qa/` を決まった値で埋めた写しに、各段の上限（`max_turns`・`max_budget_usd`）を足した見本です。

## 何をするか

3 つの段で進みます。仕様とソースの対応 → 食い違いと検討事項 → QA の観点とテストケース。
成果物は対象プロジェクトの `docs/pipeline/spec-qa/` に置かれます。差し戻しはありません。

## 向く場面と向かない場面

- 向く：仕様書があり、実装との食い違いや、QA で確かめる点を洗い出したいとき。
- 向かない：仕様書が無いとき。食い違いを自動で直したいとき（読むだけで、コードは直しません）。

## 必要なもの

- `pipe-in` と `pipe-in-gen`（`pip install -e .`）、Claude Agent SDK を使える状態。
- 依頼メモ（必須）に、仕様書の場所と、見てほしい範囲を書きます。
- 対象のプロジェクトのフォルダ（読むだけです）。

## 流し方

依頼メモに、仕様書の場所と、見てほしい範囲を書いて渡します。

```bash
pipe-in --pipe examples/spec-qa/pipes/pipe-in-spec-qa --project <対象のフォルダ> --text "仕様書は docs/spec/order.md。注文の確定まで"
```

`--pipe` にはこのフォルダのパスを渡します（リポジトリの直下で流すときの形）。
自分のプロジェクトで使い続けるときは、`pipe-in-spec-qa/` を対象の `.pipe-in/pipes/` に写せば、`pipe-in --pipe spec-qa` で流せます。
VSCode の拡張の作業台では、「見本から作る」で写せます。

## 段と書ける範囲

| 段 | 成果物 | access | docs_dir | 人の確認 |
| --- | --- | --- | --- | --- |
| `trace` | `01_trace.md` | read | — | なし |
| `gaps` | `02_gaps.md` | read | — | あり |
| `qa` | `03_qa.md` | read | — | あり |

3 つとも `read` で、成果物のほかは書けません。

## 費用の目安

| 段 | max_budget_usd | max_turns |
| --- | --- | --- |
| `trace` | $1.5 | 50 |
| `gaps` | $1.5 | 50 |
| `qa` | $1.5 | 50 |

1 回通しの上限の合計：$4.5

差し戻しはないので、上の額がそのまま全体の上限です。

**実測はまだありません。** ここの金額は、各段の `max_budget_usd` の合計（上限）で、見積りではありません。審査（`judge`）はこのパイプにありません。審査を足すときは、その費用が検証の段の上限の中に入ります。

## 直し方

- 段の並び・書き込める範囲・確認の有無・上限は `pipe.toml`、各段への指示は `prompts/` のファイルです。
- 上限は、実際に流した費用を見て決め直してください。
- 直したら `pipe-in-gen check spec-qa --pipes-dir examples/spec-qa/pipes` で確かめてください。
