# pipe-in-video：動画を作るパイプ（見本）

SNS 向けの短い紹介動画を、人の確認を挟みながら作るパイプです。`聞く → 台本 → 見本 → 書き出し → 確かめる` の5段で、台本と見本は「案を出して人が選ぶ」形で進みます。
`pipes/` や `.pipe-in/` には入っていない見本なので、`pipe-in` には `--pipe` にこのフォルダのパスを渡します（名前だけでは見つかりません）。定義の検査は `pipe-in-gen check video --pipes-dir examples/video/pipes` です。

## 必要なもの

- `pipe-in`（このリポジトリを `pip install -e .` したもの）
- `ffmpeg`・`ffprobe`（書き出しと確かめる段で使う）
- Playwright とブラウザ（場面の HTML からこま（PNG）を撮る）
- ロゴを使うときは、人が `video/assets/logo.svg` に置く（パイプは読むだけで、描かない・描き直さない）。社外のロゴを例にしない

足りないものがあれば、段が止まって入れ方を書きます（`curl`・`wget` は、この見本の段では使えません）。

## 流し方

対象のプロジェクトのフォルダで、確認で止まる形（`--pause`）で始めます。

```bash
pipe-in --pipe examples/video/pipes/pipe-in-video --pause --text "<要件メモ>"
```

パスはこのリポジトリから見た形です。ほかのフォルダで流すときは、このフォルダの場所に置き換えます。

確認の返事は、端末で要件メモ（`--text`・`--input`）と `--pause` を除いた同じ引数に `--review approve`・`--review revise --feedback "…"`・`--review quit` のどれかを付けて流し直します（例：`pipe-in --pipe examples/video/pipes/pipe-in-video --review approve`。`--review` は `--text` と一緒には使えず、次の確認でもまた止まります）。ブラウザから押したいときは、下の「受付」を使います。`--pause` を付けなければ、端末で確認に答えながら続けて流せます。

動画・こま・案のデータは、プロジェクトの `video/` に出ます（`.gitignore` 済みで、追跡しません）。

| 場所 | 中身 |
| --- | --- |
| `video/assets/logo.svg` | 人が置くロゴ（任意） |
| `video/choices.md` | 選んだ記録（`script` と `mock` が書く） |
| `video/script/options.json` | 台本の案のデータ |
| `video/mock/1/`〜`3/` | 見本の案ごとの場面の HTML とこま。出し直しは 4〜6 と続く |
| `video/mock/options.json` | 見本の案のデータ |
| `video/render/` | 撮影と変換のスクリプト |
| `video/out/` | 書き出した MP4。大きさの上限があるときは `limited.mp4` と `size_limit_bytes.txt` |
| `video/verify/frames/` | 確かめる段が取り出したこま |

## 段ごとに人が見るもの

| 段 | 人が見るもの |
| --- | --- |
| `ask` | 番号付きの質問と、各質問の「推し：…」。ロゴの有無と、ロゴの使い方の決まりの文書の場所 |
| `script` | 流れの違う2〜3案の台本の表。字幕が 1.5〜3.5 秒に収まっているか |
| `mock` | 見せ方の違う3案のこまと特徴 |
| `render` | `ffprobe` の結果（1080×1920・30fps・h264・yuv420p など）と MP4 |
| `verify` | 判定（確認は無く、不合格なら `render` へ戻る） |

## 入力例（要件メモ）

pipe-in 自身の紹介動画を作る例です。

```text
pipe-in の紹介動画を作りたい。
意図：pipe-in が、要件メモから要件定義・設計・テスト先行・実装・検証までを段ごとに進め、
区切りで人が確認することを、開発者に短く伝える。
縦長 15 秒、音は無し。最後の一文は「まずは要件メモから。」。
10MB 以内の版も欲しい。
```

台本の形の見本は `examples/video/pipe-in-intro-script.md` です。

## 選ぶ回と選んだ記録（`video/choices.md`）

`script` と `mock` の確認では、案の番号と直す点を返します。

- 「2案目で、最後の字幕を短く」：次の回は2案目だけを直して出す
- 「どれもびみょう」：別の方向で案を出し直す（番号は 4〜6 と続く）
- そのまま承認：選ばれた案で次の段へ進む

選んだ記録は、回の始めに `script`・`mock` が読み、`render`・`verify` は最後の行を見て、選ばれた1案だけを扱います。選ばれた案が無いと、`render` は書き出さず「案が選ばれていません」と書いて止まります。書き方の例：

| 段 | 回 | 出した案（番号：一行の説明） | 選んだ案（番号か「選ばれなかった」） | 直した点 |
| --- | --- | --- | --- | --- |
| script | 1 | 1：段を順に見せる／2：確認の場面を主役にする／3：図を主役にする | 2 | 最後の字幕を短く |
| script | 2 | 2：確認の場面を主役にする（字幕を短く） | 2 | なし |
| mock | 1 | 1：明るい／2：暗い／3：落ち着いた色 | 選ばれなかった | 別の方向で |

## 案のデータの形（`options.json`）

比較のページは、案のデータを読んで描きます。データはオブジェクトで、`options` に案の配列を持ちます。`round` は任意です。

`video/script/options.json`（台本の案）：

```json
{
  "round": 1,
  "options": [
    {
      "number": 1,
      "title": "段を順に見せる",
      "summary": "この案の流れ",
      "scenes": [{"start": 0, "end": 2.5, "show": "見せるもの", "caption": "字幕"}]
    }
  ]
}
```

`video/mock/options.json`（見本の案）：

```json
{
  "round": 1,
  "options": [
    {
      "number": 1,
      "title": "明るい配色",
      "summary": "この案の特徴",
      "frames": ["video/mock/1/frames/scene1.png"]
    }
  ]
}
```

- `number` は 1 以上の整数（出し直しは 4〜6）、`title`・`summary` は文字列
- `scenes` の `start`・`end` は数、`show`・`caption` は文字列
- `frames` は `video/` で始まる相対パス（`..` を含まない）。それ以外は表示せず、エラーの文にします

## 受付（ブラウザから答える）

最初の実行は端末で打ちます（`--pause` 付き）。止まったあとの答えは、手元の小さな受付から押せます。

```bash
python examples/video/review_server.py -- --pipe examples/video/pipes/pipe-in-video
```

ブラウザで `http://127.0.0.1:8765/` を開くと、止まっている段の案が出ます。「この案にする」「これで決定」「どれもびみょう」「中止」を押すと、受付が `pipe-in --review …` を呼びます。使い方の決まり：

- 待ち受けは `127.0.0.1` だけ。合言葉（起動のたびに作る）と `Host` と `POST` を確かめ、`video/` の外のファイルは配りません
- 受付は `docs/pipeline/video/state.json`（パイプの記録）を読むだけで、記録にも `video/` にも書きません。記録の置き場所を変えているときは `--work-dir`（既定は `docs/pipeline`。その下のパイプ名のフォルダを見ます）で指します
- 同時に動かす操作は1つ。実行中は押せません
- 標準ライブラリだけで動きます

## チャット（Claude のデスクトップ・アプリ）から動かすとき

Claude Code をクラウドの作業環境で動かし、Claude のデスクトップやアプリから話しかけているときは、受付の `127.0.0.1` に人のブラウザが届きません。このときの決まり：

- 確認で止まったら、Claude が `video/script/options.json`（または `video/mock/options.json`）を読み、案を並べた**見るだけのページをアーティファクトで出す**。見本のこまの画像は、`video/` の中のものだけをページに埋め込む
- ページに、案の番号・題・特徴（流れ）と、台本なら秒・見せるもの・字幕の表、見本ならこまを出す。ボタンは置かない（アーティファクトから手元の受付には届かないため）
- 人はチャットで「◯案目にする（直す点）」「どれもびみょう」「これで決定」「中止」と答え、Claude がそれを `pipe-in --review …` にして流す（受付を立てていれば受付に送る。どちらでも同じ引数になる）
- 出し直しや作り込みのたびに、同じアーティファクトを新しい案で更新する（台本と見本は別のページにする）
- 明暗のどちらでも読める配色にし、ページは外から何も読み込まない

手元の PC で動かしているときは、これまでどおり受付のページを開きます。

## 書き込みの範囲について

`script`・`mock`・`render` は `writes` で書ける場所を絞ってあります（台本の前に見本を作り込めない、`render` は選んだ記録に触れない、など）。
ただし **この絞り込みは Bash には掛かりません**。`mock`・`render`・`verify` は Bash を使うので、その中の書き込みは指示文の約束で守ります。`curl`・`wget`・`ssh` などは本体の guard が止めます。受け入れたリスクとして、知ったうえで使ってください。
