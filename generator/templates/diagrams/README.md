# pipe-in-{{name}}：ソースから図を作る

ソースを調べ、フロー図・シーケンス図・状態遷移図・クラス図を Mermaid で描き、図とソースが合っているかを確かめます。
図は Markdown の中に書くので、GitHub や VSCode の Markdown のプレビューでそのまま図として見えます。

## 段

| 段 | 成果物 | 書き込める範囲 | 人の確認 | 検証 |
|---|---|---|---|---|
| ソースの調査 | `01_survey.md` | 成果物だけ | あり | なし |
| 図を描く | `02_diagrams.md` と図のファイル | 成果物と `{{diagrams_dir}}/` | あり | なし |
| 図とソースの突き合わせ | `03_verify.md` | 成果物だけ | なし | 図のブロックの有無を機械で確かめ、合わなければ（審査の `must` 違反を含む）「図を描く」へ戻す（2回まで） |

成果物は、対象プロジェクトの `docs/pipeline/{{name}}/` に置かれます。

## 審査

「図とソースの突き合わせ」では、機械の検査（`pipe.toml` の `command`：`{{diagrams_dir}}/` の `*.md` に Mermaid のブロックが1つでもあるか）と、審査役による審査の両方をします。

- `criteria`：点数をつける項目（要素の過不足・矢印と順番）。平均が `threshold`（0.7）に届かなければ不合格。
- `must`：1つでも違反なら即不合格の決まり（図にソースに根拠のない要素・矢印がないこと）。
- 合否は機械の検査でも決まります。審査だけで差し戻すと、直しで決まりが崩れても気づけないためです。
- くわしくは `docs/guide/pipes.md` を見てください。

`python` が無い・`python3` だけの環境では、`pipe.toml` の `command` を `python3 -c …` などに書き換えてください。Windows の PowerShell・Git Bash でも、`pipe-in` はシェル（cmd.exe）を通すので、外側のダブルクォートのまま動きます。

## 流し方

```bash
pipe-in --pipe {{name}} --project <対象のフォルダ> --text "図にしたい範囲や観点（省いてもよい）"
```

## 直し方

- 段の並び・書き込める範囲・確認の有無は `pipe.toml`、各段への指示は `prompts/` のファイルです。
- 直したら `pipe-in-gen check {{name}} --project <対象のフォルダ>` で確かめてください。
