# /pipe-judge — 調べもの型の報告をルーブリックで採点する

対象: $ARGUMENTS（ファイルのパス。空なら、この会話でいちばん新しい助言の報告）

CLAUDE.md の決まり、とくに「公開リポジトリとしての注意」を守る。

審査は、1つの審査役が1つのプロンプトで5項目を一度に採点する（項目ごとに審査役を分けない）。監査（`/pipe-audit`）は食い違いを、助言（`/pipe-advise`）は新しい助言を並べるが、審査は渡された報告に点を付けるだけで、新しい項目を足さない。

- 前置きの `allowed-tools` は、確認なしで審査役を呼べるようにする許しで、道具を絞るものではない。絞るのはフックと審査役の `tools:`。
- Web を許すのは `pipe-in-judge` の WebFetch だけで、行き先はフック（`.claude/hooks/pipe_in_guard.py` の `DOC_HOSTS`・`GITHUB_HOSTS`）が公式の文書の場所に絞る。WebSearch は使えない。
- 動くフックは、会話を始めた場所の写し。この絞りを持つフックが main に入る前は、そのフックがある worktree で開いた会話でだけ流す。前の版のフックの下では WebFetch が止まり、引用は確かめられないまま `unverified` に入る。

1. 対象を決める。
   - 引数がファイルのパスなら、Read でその中身を読む（作業フォルダの中のものだけ）。
   - 空なら、この会話でいちばん新しい助言の報告（`pipe-in-advisor` の「助言の報告」）を使う。
   - どちらも無ければ、「採点する報告が無い」と書いて止まる。
2. `pipe-in-judge` に Agent ツールで1回だけ任せる。指示には次を書く。サブエージェントはこの会話を見ていない。
   - 報告の全文
   - 頼んだテーマ（分かれば。助言の報告ならそのテーマ）
   - その報告を作ったサブエージェントの道具の呼び出しの回数（Agent の結果に出る数。分からなければ書かない。そのとき tool_efficiency は null になる）
   - 作業フォルダ（今の worktree）
3. 返ってきた前置きと JSON（scores・overall・threshold・verdict・reasons・unverified）を、会話にそのまま見せて止まる。
4. 直さない。合否は人が読む材料で、`fail` でも報告を作り直させない・審査役もメインも何も変えない。報告の項目を直すかどうかは、今までどおり `/pipe-advise` の ID で人が選ぶ。
