# 見本の作り方（/pipe-design の補助）

`/pipe-design` の「2. 見本を作る」で読む。見本は1枚の HTML で、Claude のアーティファクトとして公開する。

## つまみを決める

- 画面の見直しを、互いに独立したつまみ（4〜7本）に分ける。例：配置・押したときの手応え・但し書きの出し方・入力の形・部品の選び方・見た目・密度。図なら、形・箱の中身・線・強調・動き・スマホでの組み替え。
- 1本のつまみの選択肢は2〜6つ。今の形を必ずどれかに入れる（比べる基準になる）。
- わざと盛りすぎた選択肢（「全部のせ」）や、良さの条件に外れそうな選択肢も入れてよい。外れる理由が見えると、決めやすい。
- 構成が変わると見え方が変わるもの（図など）は、構成の見本を2〜3つ（小さい・ふつう・大きい）用意して切り替えられるようにする。

## 案の番号

- つまみの頭文字と選んだ番号を並べた文字を、案の番号にする（例：`L1F2N5R2P1S2D2`）。番号から同じ見本を開けるようにし、「番号をコピー」を付ける。
- 人が選んだ案は、この番号で受け渡す。★ の保存先の文書の id にも使う（`favs.md`）。

## ページの形

見かたを3つ持つ。

- **一覧で見る**（最初に開く画面）：おすすめの案（20〜30。名前つき）と、基本の案から「つまみを1本ずつ変えた」縮図を、つまみごとに並べる。縮図を押すと「1案を触る」で開く。「縮図の幅」（広い画面・スマホの幅）・「★ だけ出す」・「★ の番号をコピー」・「見立てのよい順」を置く。
- **1案を触る**：つまみ・おすすめの案・前後の案へ送るボタン・ランダムに1案・番号で開く・画面の幅（広い画面・スマホの幅）。中の部品は本当に押せて、押すと数字や図が変わるようにする（手応えは触らないと比べられない）。
- **良さの条件**：条件と出典・つまみと条件の照らし合わせの表（○ 合う・△ 注意・× 外れる）・見本そのものと食い違う所。

## 縮図

- 案ごとに、本物と同じ部品を、決まった幅（広い画面は 1180px 前後・スマホは 390px）で描き、`transform: scale()` でカードの幅に縮める。縮図の中は `inert` にして、押せないようにする。
- 見えてから描く（IntersectionObserver）。60 枚を超えるなら、見本を分けることを考える。
- 1つのページに同じ部品が何十も並ぶので、id は案ごとにずらす（SVG の marker など）。

## 1案を触るの作り

- 状態（つまみ・選んでいる値）から HTML を作り直す形にする。描き直しで押した所や動きが途切れないよう、差分だけ当てる小さなライブラリ（morphdom など。cdnjs か jsDelivr の版を固定したもの）を使ってよい。読めないときも、全部を描き直して動くようにする。
- 手応えの見本（数え上がり・差分の札・光る・前の値を残す・棒）は、動きを減らす設定（`prefers-reduced-motion`）で止める。月額などの変化は `role="status"` で最後の値だけを読み上げる。

## 明るい画面と暗い画面

- 色はすべて役の名前のトークンにし、`:root` に明るい値、`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` と、`:root[data-theme="dark"]` の両方に暗い値を書く。`body` に背景を付ける。
- 対象にデザインの決まり（pipe-in なら `docs/design/README.md` の色・書体・角）があれば、それを使う。「見た目」のつまみで決まりから外す案を出すときは、そう書く。
- 文字は 4.5:1、枠・線・フォーカスの表示は 3:1 以上にする。

## 公開と確かめ

- アーティファクトの決まり（外枠なし・`<title>` は名前・`description`・`icon`）に従う。書く前に、アーティファクトの作り方の手引き（artifact-design）を読む。
- 公開の前に1回だけ、Playwright で開いて確かめる：全部のおすすめの案を押す・明るい画面と暗い画面・幅 390px で横のはみ出しが 0・ページのエラーが 0。崩れが見つかったら直して、もう1回だけ確かめる。
- 公開したら、URL を人に見せる。持ち主だけが開ける。

## リポジトリに置く

- 対象のリポジトリの `docs/design/<名前>.html` に置く（アーティファクトと同じ、外枠の無い断片のまま）。README に、公開先・案の番号の読み方・★ の保存先・直し方・手元で開く手順（外枠を付けたファイルを作って開く）を書く。
- 直すときは、このファイルを元にして同じ公開先へ出し直す。
