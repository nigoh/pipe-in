# /pipe-advise — 公式の文書と照らして助言する

会話を開かずに流すときは `/pipe-help` の「会話を開かずに流す」を見る。そのときは手順 2 の報告で止まり、3 以降は人が承認したあと会話でする。

テーマ: $ARGUMENTS（例: フック・サブエージェント・Agent SDK のオプション。空なら全部）

CLAUDE.md の決まり、とくに「公開リポジトリとしての注意」を守る。

- Web を許すのは `pipe-in-advisor`（と、助言の報告を採点する審査の `pipe-in-judge` の WebFetch）だけで、行き先はフック（`.claude/hooks/pipe_in_guard.py` の `DOC_HOSTS`・`GITHUB_HOSTS`）が公式の文書の場所に絞る。
- 動くフックは、会話を始めた場所の写し。この絞りを持つフックが main に入る前は、新しいフックが動く会話（そのフックがある worktree で開いた会話）でだけ流す。

1. `pipe-in-advisor` に Agent ツールで任せる。指示には、テーマ（空なら「全部」）と、作業フォルダ（今の worktree）を書く。サブエージェントはこの会話を見ていない。
2. 返ってきた「助言の報告」を、会話に全文見せて止まる。助言が0件なら、そう書いて終える。「確かめられなかったこと」もそのまま見せる。
3. どの ID を直すかを人に聞く。承認した項目だけを、メインが今のブランチで直す。サブエージェントは直さない（どこにも書けない）。
   - 聞くときは質問欄で聞く（CLAUDE.md の「必ず守ること」）。
   - 直す前に、出典の URL の中身と、リポジトリの該当する所を、メインも読んで確かめる。
   - 直すのは、文書・定義・コメントまで。
   - コードの振る舞いを変える項目は直さず、「`/pipe-in` で直す」と書いて残す（テスト先行で直すため）。
   - 承認の無い項目は変えない。
4. 直したら、触った側のテストを流し直す（`python -m pytest -q`。拡張に触れたら `npm --prefix vscode test`）。
5. 直した ID と、直さなかった ID（と理由）を会話に書く。コミットはしない（人に言われるまで）。
